# 日志审计与监控中心设计

**版本**：v1.0  
**日期**：2026-08-02

---

## 1. 目标

平台后台提供全局日志中心，覆盖操作日志、登录日志、接口日志、异常日志和慢接口日志。第一期做应用级日志，不纳入服务器 CPU、内存、磁盘等基础设施指标。

现有 `op_log`、`api_call_log`、`user_login_logs`、`audit_logs` 可复用，但接口报文需要按新要求改为“元数据入库 + 原始报文文件入 MinIO”。

---

## 2. 日志类型

| 类型 | 说明 | 来源 |
|---|---|---|
| 操作日志 | 业务新增、编辑、删除、导入导出、审批等 | AOP/服务层 |
| 登录日志 | 登录成功、失败、退出、token 刷新 | Auth 服务 |
| 接口日志 | HTTP 请求响应、状态码、耗时 | Filter/Interceptor |
| 异常日志 | 业务异常、系统异常、堆栈 | 全局异常处理 |
| 慢接口日志 | 超过阈值的接口 | 接口日志派生 |
| 平台审计日志 | 租户开通、停用、重置密码、配置变更 | 平台后台 |

---

## 3. 接口日志存储

### 3.1 数据库元数据

接口日志表记录：

- 请求 ID
- Trace ID
- 租户 ID、租户名称
- 厂家归属 ID（经销商请求时）
- 用户 ID、用户名
- 请求来源：前台/平台后台
- HTTP 方法
- 请求路径
- Query 参数摘要
- HTTP 状态码
- 业务 code
- 成功/失败
- 耗时毫秒
- 客户端 IP
- User-Agent
- 请求开始/结束时间
- 异常摘要
- 请求报文文件路径
- 响应报文文件路径
- 请求文件大小
- 响应文件大小
- 是否慢接口

### 3.2 原始报文文件

原始请求和响应报文存储到 MinIO：

- 请求文件：`api-logs/{yyyy}/{MM}/{dd}/{requestId}-req.json`
- 响应文件：`api-logs/{yyyy}/{MM}/{dd}/{requestId}-resp.json`

报文文件内容建议 JSON：

```json
{
  "requestId": "uuid",
  "method": "POST",
  "path": "/api/products",
  "headers": {},
  "query": {},
  "body": {}
}
```

下载文件必须经过平台后台鉴权，不能生成公开永久链接。

## 4. 列表筛选

平台后台日志列表支持：

- 日志类型
- 租户
- 厂家归属
- 用户
- 请求路径
- HTTP 方法
- HTTP 状态码
- 业务成功/失败
- 时间范围
- 请求 ID
- Trace ID
- 最小耗时
- 是否慢接口

操作日志还支持按业务类型、业务 ID、操作人、操作动作筛选。

---

## 5. 报文处理规则

### 5.1 记录内容

记录：

- 请求头中与排查有关的字段，如 `Content-Type`、`User-Agent`、`X-Request-Id`。
- Query 参数。
- 请求体。
- 响应体。
- 异常摘要和堆栈。

不记录或只记录元数据：

- 文件上传二进制。
- 文件下载二进制。
- 图片、PDF、Excel 原始二进制。
- 超过阈值的超大文本，保留截断摘要。

建议阈值：

- 普通文本报文超过 1MB 截断或仅存文件。
- 二进制请求不存 body。
- 响应为文件流时只记录文件元数据。

### 5.2 脱敏

必须脱敏：

- `password`
- `token`
- `accessToken`
- `refreshToken`
- `Authorization`
- `secret`
- 手机号
- 身份证

脱敏策略：

- 手机号保留前 3 后 4。
- 身份证保留前 3 后 4。
- 密码和 token 替换为 `******`。
- 递归处理 JSON 嵌套字段和 Header。

---

## 6. 慢接口

第一期可由接口日志派生：

- 普通接口慢阈值默认 1000ms。
- 报表/导入导出可单独配置阈值，例如 5000ms。
- 超过阈值标记 `slow = true`。
- 平台后台可单独筛选慢接口。

阈值先写配置，不做复杂页面。

---

## 7. 保留与清理

| 数据 | 保留周期 |
|---|---|
| 日志元数据 | 1 年 |
| 原始报文文件 | 90 天 |
| 异常日志 | 180 天 |
| 平台审计日志 | 1 年以上，建议永久或按合规要求 |

清理任务：

- 每天按创建时间清理过期元数据。
- 删除元数据前先删除对应 MinIO 文件，或按对象前缀清理。
- 记录清理任务执行日志。

---

## 8. 平台审计重点

平台后台以下操作必须审计：

- 厂家租户创建、停用、启用。
- 经销商租户创建、停用、启用。
- dealer 绑定。
- 租户管理员创建、停用、重置密码。
- 默认角色、菜单、页面字段、筛选配置修改。
- 全局字典修改。
- 缓存刷新。
- 日志文件下载。

审计日志需要记录变更前后值。

---

## 9. 与现有日志表关系

- `op_log`：现有全链路日志，可作为接口日志基础，后续扩展字段并移除大字段入库。
- `api_call_log`：面向外部接口调用，继续保留用于入站/出站 API。
- `user_login_logs`：继续作为登录日志。
- `audit_logs`：用于业务审计。
- 平台后台新增统一日志查询页，后续可逐步收敛展示。
