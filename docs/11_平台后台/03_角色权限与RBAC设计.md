# 角色权限与 RBAC 设计

**版本**：v1.0  
**日期**：2026-08-02

---

## 1. 设计目标

业务前台权限统一采用 RBAC：用户关联角色，角色关联菜单/功能权限和数据权限。平台后台第一期只有固定后台管理员，不做平台后台 RBAC。

需要同时满足：

- 厂家租户和经销商租户功能基本一致。
- 厂家可见功能范围大于等于经销商。
- 租户管理员可在平台授权范围内自建角色。
- 客服可看租户全部数据。
- 销售只能看自己和下级岗位负责的经销商/客户数据。
- 基础数据是否可见由菜单/功能权限决定，业务单据再叠加数据权限。

---

## 2. 角色分类

| 角色编码 | 名称 | 适用租户 | 默认数据权限 |
|---|---|---|---|
| `MANUFACTURER_ADMIN` | 厂家管理员 | 厂家租户 | 租户所有数据 |
| `MANUFACTURER_SERVICE` | 厂家客服 | 厂家租户 | 租户所有数据 |
| `MANUFACTURER_SALES` | 厂家销售 | 厂家租户 | 自己及下级岗位数据 |
| `DEALER_ADMIN` | 经销商管理员 | 经销商租户 | 租户所有数据 |
| `DEALER_SERVICE` | 经销商客服 | 经销商租户 | 租户所有数据 |
| `DEALER_SALES` | 经销商销售 | 经销商租户 | 自己及下级岗位数据 |

默认角色由平台后台维护模板，开通租户时复制到租户内。租户管理员可以自建角色，但只能选择平台已授权给该租户的菜单和功能权限点。

---

## 3. 权限模型

建议基于现有表扩展：

- `resources`：菜单、按钮、API 权限点。
- `roles`：租户内角色。
- `role_resources` 或现有 `strategy_resources`：角色与权限点关系。
- `user_roles`：用户与角色关系。
- `role_data_policies`：角色数据权限配置。
- `users`：用户归属租户。

第一期可以保留现有 `strategies` 作为权限策略模型，但文档层面统一按“角色直接关联资源和数据权限”描述；实现时可逐步重构，避免大范围影响现有功能。

---

## 4. 权限点编码

权限点按“模块:资源:操作”命名：

| 类型 | 示例 | 说明 |
|---|---|---|
| 菜单 | `product:menu` | 产品管理菜单 |
| 页面 | `product:list:view` | 产品列表页 |
| 按钮 | `product:create` | 新建产品 |
| 按钮 | `product:update` | 编辑产品 |
| 按钮 | `product:delete` | 删除产品 |
| API | `api:POST:/api/products` | 后端接口权限 |
| 字段 | `product:field:costPrice` | 字段级权限预留 |
| 导出 | `product:export` | 导出权限 |

后端必须以 API 权限为准，前端隐藏菜单和按钮只作为体验优化。

---

## 5. 数据权限类型

| 编码 | 名称 | 说明 |
|---|---|---|
| `ALL_TENANT` | 租户所有数据 | 可访问当前租户所有数据 |
| `SELF_CREATED` | 自己创建的数据 | 只访问 `created_by = currentUserId` 的数据 |
| `POSITION_TREE` | 自己及下级岗位数据 | 销售岗位适用，按岗位树和负责经销商/客户过滤 |

用户拥有多个角色时，数据权限取并集。例如用户同时是客服和销售，则可看租户全部数据。

---

## 6. 销售岗位数据权限

现有岗位与经销商负责关系保持不变。销售岗位过滤逻辑：

1. 获取当前用户所属岗位。
2. 递归获取当前岗位及所有下级岗位 ID。
3. 查询这些岗位负责的 dealer/customer ID。
4. 对销售订单、销退出库、手术报告、合同、促销、经销商画像等单据按负责的 dealer/customer 过滤。

岗位树规则：

- 一个用户第一期默认属于一个主岗位。
- 岗位上下级使用现有岗位树。
- 岗位和 dealer/customer 的负责关系使用现有关系，不重新设计。
- 上级岗位可以查看自身及所有下级岗位负责的数据。

## 7. 权限校验流程

### 7.1 登录后加载权限

1. 用户登录。
2. 后端查询用户角色。
3. 查询角色对应菜单、按钮、API 权限点。
4. 查询角色数据权限。
5. 返回 token 和权限快照，或由前端通过 `/api/auth/me` 加载。

### 7.2 请求鉴权

1. 解析 token，得到 `tenantId`、`userId`、`userType`。
2. 加载用户角色与权限点。
3. 校验接口所需权限点。
4. 设置 `TenantContext`。
5. 数据查询层按数据权限自动拼接条件。

### 7.3 管理边界

- 平台后台管理员创建租户管理员。
- 租户管理员创建普通用户和角色。
- 租户管理员不能创建平台权限，也不能超出平台给租户授权的菜单范围。
- 每租户只能有一个启用中的租户管理员。

---

## 8. 平台后台权限

第一期平台后台只有固定管理员账号，不做角色管理。

固定管理员可操作：

- 厂家租户、经销商租户管理。
- 租户绑定 dealer。
- 租户管理员创建、停用、重置密码。
- 默认角色模板、菜单模板、页面字段模板、筛选模板。
- 全局字典。
- 全平台日志中心。
- 缓存刷新和基础运维。

所有平台后台操作都记录操作日志。
