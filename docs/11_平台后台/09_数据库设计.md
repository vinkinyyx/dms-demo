# 数据库设计

**版本**：v1.0  
**日期**：2026-08-02

---

## 1. 设计原则

- 共享数据库、共享 Schema，业务表通过 `tenant_id` 隔离。
- 经销商租户必须归属一个厂家租户。
- `dealers` 是业务客户主数据，不作为租户表。
- 平台表不参与租户过滤。
- 所有新增表包含审计字段。
- 现有 V1–V49 表尽量增量扩展，避免破坏性重建。

---

## 2. `tenants` 扩展

现有 `tenants` 表需要补充：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tenant_type` | VARCHAR(16) NOT NULL DEFAULT 'DEALER' | `MANUFACTURER` / `DEALER` |
| `owner_manufacturer_id` | UUID | 经销商租户归属厂家；厂家租户为空 |
| `deployment_mode` | VARCHAR(16) NOT NULL DEFAULT 'SHARED' | `SHARED` / `DEDICATED` |
| `disabled_at` | TIMESTAMPTZ | 停用时间 |
| `disabled_by` | BIGINT | 停用人 |
| `disable_reason` | VARCHAR(500) | 停用原因 |
| `enabled_at` | TIMESTAMPTZ | 最近启用时间 |

索引：

- `idx_tenants_type_status(tenant_type, status)`
- `idx_tenants_owner(owner_manufacturer_id, status)`

现有固定租户 `11111111-1111-1111-1111-111111111111` 应迁移为厂家租户。

## 3. 租户经销商绑定表 `tenant_dealer_bindings`

```sql
CREATE TABLE tenant_dealer_bindings (
    id BIGSERIAL PRIMARY KEY,
    dealer_tenant_id UUID NOT NULL REFERENCES tenants(id),
    manufacturer_tenant_id UUID NOT NULL REFERENCES tenants(id),
    dealer_id BIGINT NOT NULL,
    status VARCHAR(16) NOT NULL DEFAULT 'active',
    bound_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    bound_by BIGINT,
    unbound_at TIMESTAMPTZ,
    remark VARCHAR(500),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    version INT NOT NULL DEFAULT 0,
    deleted_at TIMESTAMPTZ
);
```

约束和索引：

- 一个经销商租户只能有一个未删除绑定：唯一索引 `ux_tdb_dealer_tenant`。
- 同一厂家下一个 dealer 只能有一个启用绑定：部分唯一索引。
- `idx_tdb_manufacturer(manufacturer_tenant_id, status)`。
- `idx_tdb_dealer(manufacturer_tenant_id, dealer_id)`。

`dealer_id` 不加外键，因为 `dealers.id` 属于业务租户表且跨租户引用主要用于关系绑定；应用层必须校验 dealer 属于厂家租户。

## 4. 用户表调整

`users` 继续复用。需要关注：

- `tenant_id` 必填。
- 平台后台管理员可归属一个固定平台租户，或使用 `user_type='PLATFORM_ADMIN'` 且独立登录。
- 租户管理员通过角色识别，不新增管理员表。
- 每租户只能有一个启用中的租户管理员，建议用部分唯一索引或应用事务保证。

建议字段：

- `user_type` 扩展支持：`MANUFACTURER_USER`、`DEALER_USER`、`PLATFORM_ADMIN`。
- 如继续使用旧值 `vendor/dealer`，需要兼容并逐步迁移。
- 增加 `last_password_reset_at`，如现有字段不足。

## 8. 产品对码表 `product_mappings`

```sql
CREATE TABLE product_mappings (
    id BIGSERIAL PRIMARY KEY,
    manufacturer_tenant_id UUID NOT NULL,
    dealer_tenant_id UUID NOT NULL,
    manufacturer_product_id BIGINT NOT NULL,
    dealer_product_id BIGINT NOT NULL,
    manufacturer_product_code VARCHAR(64) NOT NULL,
    dealer_product_code VARCHAR(64) NOT NULL,
    package_unit VARCHAR(32),
    conversion_rate NUMERIC(18,6) DEFAULT 1,
    status VARCHAR(16) NOT NULL DEFAULT 'active',
    import_batch_no VARCHAR(64),
    remark VARCHAR(500),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by BIGINT,
    updated_by BIGINT,
    version INT NOT NULL DEFAULT 0,
    deleted_at TIMESTAMPTZ
);
```

唯一约束：

- 一个厂家产品在一个经销商租户下只能对应一个经销商产品。
- 一个经销商产品在一个厂家租户下只能对应一个厂家产品。

建议唯一索引：

- `ux_pm_manufacturer_product(manufacturer_tenant_id, dealer_tenant_id, manufacturer_product_id) WHERE deleted_at IS NULL`
- `ux_pm_dealer_product(manufacturer_tenant_id, dealer_tenant_id, dealer_product_id) WHERE deleted_at IS NULL`

导入批次表：

```sql
CREATE TABLE product_mapping_import_batches (
    id BIGSERIAL PRIMARY KEY,
    manufacturer_tenant_id UUID NOT NULL,
    file_name VARCHAR(255),
    object_key TEXT,
    error_object_key TEXT,
    total_count INT DEFAULT 0,
    success_count INT DEFAULT 0,
    fail_count INT DEFAULT 0,
    status VARCHAR(16) NOT NULL,
    created_by BIGINT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at TIMESTAMPTZ
);
```

## 9. 日志表

### 9.1 操作日志

现有 `op_log` 和 `operation_log` 可复用。建议统一以 `op_log` 为主，补充：

- `tenant_type`
- `owner_manufacturer_id`
- `auth_source`
- `request_id`
- `trace_id`

### 9.2 接口日志

现有 `op_log` 已包含请求和响应字段，但报文长期放数据库会膨胀。建议新增：

```sql
CREATE TABLE api_http_logs (
    id BIGSERIAL PRIMARY KEY,
    request_id VARCHAR(64),
    trace_id VARCHAR(64),
    tenant_id UUID,
    tenant_type VARCHAR(16),
    owner_manufacturer_id UUID,
    user_id BIGINT,
    username VARCHAR(64),
    auth_source VARCHAR(16),
    http_method VARCHAR(8),
    path VARCHAR(255),
    query_string TEXT,
    status_code INT,
    biz_code INT,
    success BOOLEAN,
    slow BOOLEAN,
    spent_ms BIGINT,
    client_ip VARCHAR(64),
    user_agent VARCHAR(512),
    error_message TEXT,
    request_object_key TEXT,
    response_object_key TEXT,
    request_size BIGINT,
    response_size BIGINT,
    started_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at TIMESTAMPTZ
);
```

索引：

- `idx_api_http_logs_started(started_at DESC)`
- `idx_api_http_logs_tenant(tenant_id, started_at DESC)`
- `idx_api_http_logs_owner(owner_manufacturer_id, started_at DESC)`
- `idx_api_http_logs_request(request_id)`
- `idx_api_http_logs_slow(slow, started_at DESC)`

现有 `op_log` 可逐步迁移或并行一段时间。

### 9.3 平台审计日志

CREATE TABLE platform_audit_logs (

## 10. 数据清理任务

需要新增定时任务：

- 清理过期接口日志元数据。
- 清理 MinIO 原始报文文件。
- 清理过期导入临时文件。

建议任务配置：

- 每天凌晨执行。
- 每次删除限量，避免锁表。
- 记录清理结果日志。
