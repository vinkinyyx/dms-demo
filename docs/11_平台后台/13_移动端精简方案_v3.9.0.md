# 移动端精简方案（v3.9.0 销售场景）

**版本**：v3.9.0  
**日期**：2026-08-04  
**适用范围**：`frontend-vue` 的 `/mobile` 路径下全部页面。

---

## 1. 背景

原有移动端页面是从 PC 端业务复制而来，包含了销售、采购、收货、发货、库存、消息等全量功能。但实际现场调研显示，**移动端销售人员的真实使用场景只有三类**：

1. 下销售订单（PC 端 80% 时间用来在客户现场下销售订单）。
2. 填手术报台（PC 端无法在手术室外完成，必须用手机）。
3. 看自己的业绩和订单（"我这个月做了多少"、"我下过哪些单"）。

收货、发货、库存查询、消息等能力对销售几乎无用，导致移动端入口臃肿、加载慢、误操作率高。

## 2. 目标

- 移动端 **只服务销售人员**。
- **底部 TabBar 由 5 个精简为 4 个**：首页 / 订单 / 报台 / 我的。
- 销售只下 **销售订单**，不在手机上处理采购。
- 报台支持 **创建 + 列表 + 详情**，让销售能回顾自己报过的台。
- 首页聚焦 **个人业绩 KPI**（今日订单、本月销售、本月报台）。
- 报表页聚焦 **个人销售业绩**（本月销售、月度趋势、TOP 经销商）。

## 3. 调整后结构

```
/mobile/login           登录
/mobile/home            首页（个人业绩 + 快捷入口）
/mobile/orders          订单列表（仅销售订单）
/mobile/orders/:id      订单详情
/mobile/orders/create   下销售订单
/mobile/surgery-reports 报台列表（销售本人）
/mobile/surgery-reports/:id  报台详情
/mobile/surgery-reports/create  新建报台
/mobile/dashboard       我的业绩（本月销售 + 趋势 + TOP）
/mobile/profile         我的（账户、退出）
```

底部 TabBar：

| 顺序 | 名称 | 路径 | 图标 | 备注 |
|------|------|------|------|------|
| 1 | 首页 | `/mobile/home` | `home-o` | 个人 KPI + 快捷入口 |
| 2 | 订单 | `/mobile/orders` | `orders-o` | 销售订单列表 |
| 3 | 报台 | `/mobile/surgery-reports` | `edit-o` | 报台列表 |
| 4 | 我的 | `/mobile/profile` | `user-o` | 账户与设置 |

## 4. 页面调整清单

### 4.1 `MLayout.vue`（重写）

- 移除"收货"和"发货"Tab。
- 5 项 Tab 改为 4 项：`首页 / 订单 / 报台 / 我的`。
- 保留外层布局与样式不变。

### 4.2 `MHome.vue`（重写）

**KPI（来自 `/api/dashboard/kpi?period=today` 与 `?period=month`）**：

- 今日订单数
- 今日销售订单金额
- 本月销售订单数
- 本月销售订单金额
- 本月报台数

**快捷入口（4 项）**：

- 下销售订单
- 填手术报台
- 我的订单
- 我的业绩

**最近订单**（保留，便于快速回看）：

- 来自 `GET /api/orders?page=1&size=5`，仅显示本人能看的（后端按 tenant + 销售归属自动过滤）。

### 4.3 `MOrders.vue`（简化）

- 移除"采购订单" Tab，仅保留"销售订单"。
- 移除原页内"新建"快捷弹窗（强制走 `/mobile/orders/create`）。
- 保留订单列表（分页）、订单详情弹窗。
- 详情接口：`GET /api/orders/{id}`。

### 4.4 `MOrderCreate.vue`（重写，Vant 风格）

原版为 PC 端 Element Plus 组件的占位空壳，不可用。重写为 Vant 版本，与 PC 端 `OrderCreate.vue` 业务一致，但 UI 适配移动端：

- 选择经销商（`GET /api/lookups/dealers`，按销售范围过滤由后端在创建时校验）。
- 选择仓库（`GET /api/lookups/warehouses`）。
- 选择产品（`GET /api/lookups/products?dealerId=X`），自动按经销商授权过滤并显示可用库存。
- 行内编辑数量/单价/税率。
- 底部显示金额合计。
- 提交：`POST /api/orders`，body 与 PC 端一致：
  ```json
  {
    "dealerId": 1,
    "warehouseId": 1,
    "orderType": "NORMAL",
    "orderDate": "2026-08-04",
    "remark": "...",
    "lines": [
      { "seq": 1, "productId": 100, "qty": 5, "unitPrice": 120.0, "taxRate": 0.13 }
    ]
  }
  ```

### 4.5 `MSurgeryReportCreate.vue`（重写）

原版字段与后端不匹配（提交 `hospitalName/productName` 等后端不认识的字段，必传 `dealerId/terminalId/warehouseId/lines` 缺失）。重写为 Vant 版本：

- 经销商选择（下拉，按销售范围由后端校验）。
- 医院选择（`GET /api/lookups/hospitals`，提交时由后端校验是否在该经销商授权范围内）。
- 仓库选择。
- 手术日期（Vant `van-date-picker`）。
- 患者姓名、主刀医生、备注。
- 产品明细行（至少 1 行）：
  - 产品选择（`GET /api/lookups/products?dealerId=X`）。
  - 批号 / 序列号（按产品是否序列号管理自动决定显示哪个）。
  - 数量。
- 提交：`POST /api/surgery-reports`，body：
  ```json
  {
    "dealerId": 1,
    "terminalId": 10,
    "warehouseId": 1,
    "surgeryDate": "2026-08-04",
    "patientInfo": "张三",
    "doctorName": "李医生",
    "remark": "...",
    "lines": [
      { "productId": 100, "batchNo": "B20260101", "qty": 1 }
    ]
  }
  ```

### 4.6 `MSurgeryReports.vue`（新增，报台列表）

- 路径：`/mobile/surgery-reports`。
- 来源：`GET /api/surgery-reports?page=1&size=20`，后端按 sales 角色自动过滤其负责的经销商，无需前端传 salesUserId。
- 列表项：报台单号 / 医院 / 经销商 / 手术日期 / 状态。
- 点击进入详情（`/mobile/surgery-reports/:id`）。

### 4.7 `MSurgeryReportDetail.vue`（新增，报台详情）

- 路径：`/mobile/surgery-reports/:id`。
- 来源：`GET /api/surgery-reports/{id}`。
- 内容：单号、经销商、医院、仓库、手术日期、患者、主刀医生、状态、备注、产品明细（产品名/批号/序列号/数量/单价）。

### 4.8 `MReport.vue` → `MDashboard.vue`（聚焦个人业绩）

- 移除"采购统计"和"库存预警" Tab（销售不需要）。
- 仅保留"销售业绩" Tab：
  - 本月销售金额、本月销售订单数（来自 `getKpi({ period: 'month' })`）。
  - 近 12 个月销售趋势（来自 `getSalesTrend()`）。
  - 本月 TOP 经销商（来自 `getTopDealers({ period: 'month' })`）。

### 4.9 `MProfile.vue`（新增，"我的"页）

- 路径：`/mobile/profile`。
- 内容：当前用户（用户名/姓名/角色/所属经销商）、修改密码入口（保留原 PC 流程入口跳转）、退出登录。

### 4.10 移除的页面

以下页面在本次精简中**删除文件并移除路由**（因销售在手机上用不到，且简化菜单后无法触达）：

- `MMessages.vue`（消息中心 PC 端未实现，且销售场景无强需求）。
- `MInventory.vue`（库存查询）。
- `MReceipt.vue`（收货）。
- `MShipment.vue`（发货）。
- `MOrderTrace.vue`（订单追溯并入订单详情）。

如未来需要恢复，可从 git 历史还原。

## 5. 路由调整

`frontend-vue/src/router/index.js` 的 `/mobile` 段调整后：

```js
{
  path: '/mobile',
  component: () => import('@/views/mobile/MLayout.vue'),
  redirect: '/mobile/home',
  meta: { mobile: true },
  children: [
    { path: 'home',                 name: 'MHome',         component: () => import('@/views/mobile/MHome.vue') },
    { path: 'orders',               name: 'MOrders',       component: () => import('@/views/mobile/MOrders.vue') },
    { path: 'orders/:id',           name: 'MOrderDetail',  component: () => import('@/views/mobile/MOrderDetail.vue') },
    { path: 'orders/create',        name: 'MOrderCreate',  component: () => import('@/views/mobile/MOrderCreate.vue') },
    { path: 'surgery-reports',                name: 'MSurgeryReports',       component: () => import('@/views/mobile/MSurgeryReports.vue') },
    { path: 'surgery-reports/:id',            name: 'MSurgeryReportDetail',  component: () => import('@/views/mobile/MSurgeryReportDetail.vue') },
    { path: 'surgery-reports/create',         name: 'MSurgeryReportCreate',  component: () => import('@/views/mobile/MSurgeryReportCreate.vue') },

    { path: 'profile',              name: 'MProfile',      component: () => import('@/views/mobile/MProfile.vue') }
  ]
}
```

## 6. 后端影响

- 全部使用既有 API，不新增后端接口。
- 报台创建字段对齐 `SurgeryReportController.create` 的实际入参（修复了原前端字段缺失导致提交失败的问题）。
- 报台列表 `GET /api/surgery-reports` 已支持按 sales 角色自动过滤，零改动。
