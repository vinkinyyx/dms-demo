## 3. 核心需求确认

### 3.1 三层架构

系统采用三层模型：

```text
平台运营方 → 厂家租户 → 经销商租户
```

- 平台运营方使用独立平台后台。
- 厂家租户和经销商租户共用业务前台。
- 一个厂家可有多个经销商租户。
- 经销商租户必须归属一个厂家租户。

### 3.2 dealer 定位

- `dealers` 表始终是业务主数据，不是租户表。
- 厂家先在自己的前台维护 dealer。
- 平台后台创建经销商租户时，从所属厂家的 dealer 列表中选择一个未绑定的 dealer。
- 一个经销商租户只能绑定一个 dealer。
- 同一厂家下一个 dealer 只能绑定一个启用中的经销商租户。
- 绑定后不支持解绑或换绑；绑定错误只能停用错误租户并新建正确租户。

### 3.3 租户和管理员

- 租户编码全局唯一。
- 每个租户只能有一个启用中的租户管理员。
- 平台后台管理员创建厂家/经销商租户管理员。
- 租户管理员创建普通用户、自建角色、分配权限、重置普通用户密码。
- 平台后台第一期只有一个固定后台管理员，不做平台后台 RBAC。
- 平台后台独立登录页、独立 token、独立 API 前缀 `/api/admin/**`。

### 3.4 数据隔离

- 所有业务表必须带 `tenant_id`。
- 经销商租户只能看自己的数据。
- 厂家租户只能看自己的业务数据。
- 厂家不能查看经销商租户的订单、库存、客户、报表等业务数据。
- 厂家可查看归属自己的经销商租户只读列表，用于产品对码。
- 平台后台不操作业务数据。

### 3.5 权限

业务前台统一 RBAC。

默认角色：

- 厂家管理员：租户所有数据。
- 厂家客服：租户所有数据。
- 厂家销售：自己及下级岗位数据。
- 经销商管理员：租户所有数据。
- 经销商客服：租户所有数据。
- 经销商销售：自己及下级岗位数据。

数据权限类型：

- `ALL_TENANT`
- `SELF_CREATED`
- `POSITION_TREE`

多角色权限取并集。

现有岗位与经销商负责关系保持不变，不重新设计岗位模型。

### 3.6 全局配置

平台后台统一维护：

- 全局字典。
- 平台菜单。
- 页面字段显隐、只读、必填、导出。
- 筛选项显隐、顺序、默认值。

第一期不做：

- 租户级私有字典。
- 租户级页面布局自定义。
- 用户个性化布局。
- 配置审批发布流。

配置层级：全局默认 + 厂家/经销商租户类型差异。

### 3.7 产品对码

- 对码入口在厂家租户前台，不在平台后台。
- 厂家产品与经销商产品必须一对一。
- 第一期只维护关系，服务后续报表汇总。
- 支持 Excel 模板下载、上传、预览、错误报告、确认导入。
- 对码表：`product_mappings`。

### 3.8 日志

- 操作日志、登录日志、接口日志、异常日志、慢接口日志在平台后台统一查看。
- 接口日志采用“数据库元数据 + MinIO 原始报文文件”。
- 日志元数据保留 1 年，原始报文保留 90 天。
- 密码、token、Authorization、secret、手机号、身份证必须脱敏。
- V50 新增 `api_http_logs`，但尚未实现写入 Filter 和 MinIO 存储。

## 4. 建议开发顺序

### 阶段 1：后端基础能力

1. 平台后台认证模块。
   - 新建 `adminauth` 模块。
   - 登录接口：`POST /api/admin/auth/login`
   - 当前用户：`GET /api/admin/auth/me`
   - 退出：`POST /api/admin/auth/logout`
   - 独立 token，不与业务 token 混用。

2. 租户开通模块。
   - 厂家租户 CRUD、启用、停用。
   - 经销商租户创建、绑定 dealer、启用、停用。
   - 租户管理员创建、停用、重置密码。
   - 开通过程在一个事务中完成。
   - 写入 `platform_audit_logs`。

3. 多租户隔离加固。
   - 扩展 `TenantContext`：`tenantType`、`ownerManufacturerId`、`authSource`。
   - 业务 token 解析租户。
   - 平台后台 token 不设置业务租户。
   - 检查所有业务查询是否强制 `tenant_id`。
   - 增加跨租户访问安全日志。

### 阶段 2：平台配置与 RBAC

4. 默认角色模板和资源权限。
   - 管理 `role_templates`。
   - 租户开通时复制默认角色到租户内 `roles`。
   - 补齐角色和资源关联。

5. 菜单、页面字段、筛选项配置接口。
   - 平台后台维护接口。
   - 前台读取接口。
   - 接入 Redis 缓存和刷新。

6. 全局字典管理。
   - 平台后台 CRUD。
   - 前台只读。
   - 废弃租户级字典入口。

### 阶段 3：产品对码

7. 产品对码实体、Repository、Service、Controller。
8. 厂家前台只读经销商租户列表：`GET /api/my-dealer-tenants`。
9. 手工新增、编辑、启用、停用。
10. Excel 导入、预览、错误报告、确认导入。

### 阶段 4：日志中心

11. 接口日志 Filter。
   - 写 `api_http_logs` 元数据。
   - 请求/响应报文写 MinIO。
   - 敏感字段脱敏。
   - 慢接口标记。

12. 平台后台日志查询和报文下载接口。
13. 平台审计日志写入。
14. 日志清理任务。

### 阶段 5：前端

15. 新建 `admin-vue`。
   - Vue 3 + Vite + Element Plus。
   - 独立登录页。
   - 租户管理。
   - 租户管理员管理。
   - 默认角色和权限模板。
   - 菜单/页面字段/筛选配置。
   - 全局字典。
   - 日志中心。

16. 改造 `frontend-vue`。
   - 移除 `/admin` 旧后台页面和菜单入口。
   - 保留租户内用户、角色、权限分配。
   - 接入新菜单和 UI 配置。
   - 厂家租户增加产品对码页面。

### 阶段 6：测试与种子数据

17. 编写多租户隔离测试。
18. 编写租户开通测试。
19. 编写产品对码导入测试。

## 7. 注意事项

- 不要把平台后台继续做进 `frontend-vue/src/views/Admin.vue`；该旧页面应迁移后移除。
- 不要让前端传 `tenantId` 决定数据范围，租户必须从 token 解析。
- 不要让厂家通过普通业务接口查看经销商租户真实业务数据。
- 平台后台接口必须以 `/api/admin/**` 开头。
- 原始报文不要直接长期存数据库，使用 MinIO 文件。
- 二进制上传下载不要记录完整 body。
- 所有平台写操作都要写审计日志。
- 绑定错误不能解绑，只能停用错误租户并新建正确租户。
- 旧文档中“超级管理员/租户级字典/固定单厂家”的历史描述已标注为不再优先，应以 `docs/11_平台后台/` 为准。
