# 架构与多租户隔离设计

**版本**：v1.0  
**日期**：2026-08-02

---

## 1. 目标

采用“平台运营方 → 厂家租户 → 经销商租户”的三层 SaaS 架构。默认共享数据库、共享 Schema，通过 `tenant_id`、厂家归属字段、RBAC 和数据权限完成隔离。

核心原则：

1. 业务前台一套代码服务厂家租户和经销商租户。
2. 平台后台独立应用、独立部署、独立登录态。
3. 厂家不能访问其他厂家及其经销商数据。
4. 经销商只能访问自己租户内的数据。
5. 平台后台只做平台管理，不操作业务单据。
6. 预留独立部署能力，但第一期只实现共享部署。

---

## 2. 逻辑分层

| 层级 | 说明 | 数据边界 |
|---|---|---|
| 平台运营方 | 系统提供方，使用平台后台 | 管理所有厂家、经销商、配置、日志 |
| 厂家租户 | 使用系统的厂家 | 只能访问本厂家数据及归属本厂家的关系数据 |
| 经销商租户 | 某厂家下属经销商 | 只能访问本经销商租户业务数据 |

厂家租户下的 `dealers` 是厂家的客户主数据；经销商租户通过绑定关系关联其中一条 dealer 记录。该绑定不是数据授权，不代表厂家能查看经销商租户业务数据。

---

## 3. 部署与应用划分

### 3.1 应用划分

| 应用 | 建议目录 | 入口 | 说明 |
|---|---|---|---|
| 业务前台 | `frontend-vue` | `/login` | 厂家和经销商业务用户使用 |
| 平台后台 | `admin-vue` | `/admin/`（未登录自动进入登录态） | 平台后台管理员使用；API 走 `/api/admin/auth/login` |
| 后端 API | `backend` | `/api/**`、`/api/admin/**` | 同时提供前台和平台后台接口 |

平台后台与业务前台必须使用不同登录接口和 token：

- 业务前台：`/api/auth/**`
- 平台后台：`/api/admin/auth/**`

### 3.2 共享部署

第一期默认共享部署：

- 多厂家、多租户共用同一套前后端和数据库。
- 平台表、全局配置表不按租户隔离。
- 业务表通过 `tenant_id` 隔离。
- MinIO、Redis 按 key/object prefix 隔离。

### 3.3 独立部署

后续独立部署时复用同一套代码，但独立配置：

- 独立数据库。
- 独立 Redis。
- 独立 MinIO bucket 或独立对象存储。
- 独立域名和部署环境。
- 通过部署配置标记部署模式。

数据模型预留 `deployment_mode`，第一期不实现独立部署控制台。

## 4. 租户上下文

后端通过 `TenantContext` 保存当前请求上下文：

- `tenantId`
- `userId`
- `username`
- `tenantType`
- `ownerManufacturerId`
- `userType`
- `authSource`（前台 / 平台后台）

上下文来源：

- 业务前台：从业务 token 解析。
- 平台后台：从后台 token 解析，不设置业务租户上下文。
- 不允许前端直接传 `tenantId` 决定数据范围。

请求结束后必须清理 ThreadLocal，避免线程复用污染。

## 5. 数据隔离规则

### 5.1 表分类

| 表类型 | 示例 | 隔离规则 |
|---|---|---|
| 平台表 | 平台管理员、平台配置模板、全局字典 | 不参与租户过滤 |
| 租户主体表 | `tenants` | 按角色和权限访问 |
| 厂家归属关系表 | `tenant_dealer_bindings`、`product_mappings` | 必须带所属厂家条件 |
| 租户业务表 | `products`、`dealers`、订单、库存 | 必须按 `tenant_id` 隔离 |
| 日志表 | 操作日志、接口日志 | 平台可全局查；业务用户按租户查 |

### 5.2 业务表要求

所有业务表必须包含：

- `tenant_id UUID NOT NULL`
- `created_at`
- `updated_at`
- `version`
- `deleted_at`（如需软删除）

经销商专属关系表还必须包含：

- `owner_manufacturer_id` 或可通过绑定关系稳定推导。

### 5.3 查询和写入

- 查询：自动追加 `tenant_id = currentTenantId`。
- 新增：自动写入当前 `tenant_id`，忽略前端传入值。
- 更新：`WHERE id = ? AND tenant_id = ?`。
- 删除：同更新，必须带租户条件。
- 跨租户访问：抛出权限异常并记录安全日志。

### 5.4 厂家访问经销商关系数据

厂家可访问：

- 归属自己的经销商租户只读列表。
- 自己与经销商之间的产品对码。

厂家不可访问：

- 经销商租户内的订单、库存、客户、采购、销售、手术报告、报表等业务数据。
- 其他厂家及其经销商的数据。

## 6. 缓存隔离

Redis key 必须带明确前缀：

- 业务前台 token：`dms:auth:{tenantId}:{userId}:{tokenId}`
- 平台后台 token：`dms:admin:auth:{userId}:{tokenId}`
- 租户状态：`dms:tenant:status:{tenantId}`
- 全局字典：`dms:cfg:dict:*`
- 页面配置：`dms:cfg:page:*`
- 产品对码：`dms:mapping:{manufacturerTenantId}:*`

租户停用时需要清理或吊销该租户 token 版本。

---

## 7. MinIO 存储隔离

报文文件、导入文件和导出文件按环境和租户分层：

```text
dms-{env}/
  api-logs/{yyyy}/{MM}/{dd}/{requestId}-req.json
  dms-{env}/
  api-logs/{yyyy}/{MM}/{dd}/{requestId}-resp.json
  product-mapping-imports/{manufacturerTenantId}/{batchId}/input.xlsx
  product-mapping-imports/{manufacturerTenantId}/{batchId}/errors.xlsx
```

第一期接口报文路径建议：

- bucket：`dms` 或按环境拆 bucket。
- 请求报文：`api-logs/{yyyy}/{MM}/{dd}/{requestId}-req.json`
- 响应报文：`api-logs/{yyyy}/{MM}/{dd}/{requestId}-resp.json`

下载报文文件必须经过平台后台权限校验，不允许公开直链。

## 8. 安全要求

1. 平台后台和业务前台 token 不能互换。
2. 停用租户后，该租户已有 token 立即失效。
3. 租户编码全局唯一。
4. 用户名为“租户内唯一”；平台后台管理员全局唯一。
5. 平台后台管理员不通过业务接口访问业务数据。
6. 所有平台写操作、租户开通、停用、重置密码必须记录审计日志。
7. 所有跨租户访问尝试记录安全日志。
8. 日志中的密码、token、Authorization、secret、手机号、身份证必须脱敏。

---

## 9. 第一期不做

- 不做模拟登录。
- 不做厂家查看经销商真实业务数据。
- 不做独立部署控制台。
- 不做租户级自定义页面布局。
- 不做租户级字典。
- 不做有效期自动到期。
- 不做计费、套餐计量和资源配额扣费。
