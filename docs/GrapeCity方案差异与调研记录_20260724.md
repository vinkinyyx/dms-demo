# GrapeCity 方案差异与调研记录

> 调研日期：2026-07-24  
> 对比基线：项目 `docs/` 全量需求、设计、测试和部署文档；`GrapeCity医疗行业经销商管理解决方案 - 202503.pdf`（34 页）  
> 当前项目版本：v3.6.2（测试环境已完成 bugfix 集成、前端镜像重建、nginx upstream 修复和 RPA 验证）

## 1. 项目当前范围与进度

### 已覆盖的业务能力

- **主数据与授权**：产品、产品分类、产品价格、供应商、经销商、医院/终端、销售组织、岗位、合同和授权；授权按经销商、产品分类、终端和业务类型控制。
- **交易与库存闭环**：采购/销售订单、审核、分批收发货、执行明细、库存调整/移库/借货/盘点/退换货；批号、序列号、生产日期、有效期、来源单据的追溯。
- **医疗行业能力**：手术植入报台、医院销售、发票扫描件、销售出库多批次、移动扫码、产品流向追踪。
- **经营与治理**：仪表盘、业务报表、操作日志、RBAC 与数据权限、租户/菜单/数据字典管理。
- **集成与交付**：ERP/WMS/HR/UDI/CA 等标准接口契约与 Mock；Vue 3 前端、Spring Boot 后端、PostgreSQL、Docker Compose。

### 最新已完成项（v3.6.0 - v3.6.2）

1. 全站选择器、筛选、名称化、导入导出、全屏编辑抽屉和操作日志整改。
2. 订单审核、授权字段联动、销售出库多批次、手术报台、订单追溯报表、销售岗位维护。
3. 登录会话时长、移动端收敛、测试环境部署及 nginx upstream 修复。

### 当前需注意的范围边界

- 现有外部系统对接以 **Mock/桩接口** 为基线，尚不能视为真实 ERP、MDM 或物流 EDI 已上线。
- v3.6.0 已将移动端收敛为核心路由；PDF 所述的完整移动库存和销量上报链路不能直接认定为当前已交付。
- 当前资料确认了临期、库存和审批预警；尚未形成独立的合规风险预警中心。

## 2. PDF 独有需求（建议纳入候选需求池）

下表仅列出在项目文档中未找到同等能力，或仅有相邻能力而没有明确实现/验收定义的条目。

| 优先级建议 | PDF 独有需求 | 与当前项目的差异 | 建议的验收边界 |
| --- | --- | --- | --- |
| P0/P1（取决于渠道模式） | **真实 ERP、MDM、经销商和物流平台 EDI 集成** | 当前仅定义 Mock 和接口契约；PDF 要求订单、发货、主数据等双向/自动数据交换，并包含物流平台。 | 明确每个接口的对象、方向、主键、重试/幂等、对账、告警和生产联调清单。 |
| P1 | **返利池及订单级叠加返利分摊** | 项目已有返利/促销概念和报表，但没有明确“返利池余额、可用性校验、订单明细分摊、叠加使用、价格构成可见”的交易引擎。 | 返利规则、池余额、占用/释放、订单行分摊、冲销、审计和经销商可见的价格明细可闭环。 |
| P1 | **产品组套/套包关系与组套设备订单** | 当前未发现产品组合主数据或组套订单。 | 可维护父子 SKU、固定/可选件、数量关系、拆套出库/库存占用和订单价格规则。 |
| P1 | **特殊价格订单与维修订单** | 现有订单类型含普通、促销、样品、试用、换货、寄售；无独立的特殊价审批单和维修订单流程。 | 特殊价申请/审批/有效期/追溯；维修品来源、维修状态、返还或报废及库存影响。 |
| P1 | **质量投诉/质量报告管理** | 当前具备异常收货、退换货和操作日志，但 PDF 单列“质量报告管理/产品投诉”。 | 投诉建单、批号/序列号关联、责任方、调查/CAPA、附件、时限、关闭和报表。 |
| P1 | **多层包装码的扫码追溯** | 当前可按批号/序列号追溯和扫码核对；PDF 展示运输包装-纸箱-彩盒-产品的父子码关系及跨平台流转。 | 包装层级建模、聚合/解聚、扫码入出库、跨层数量校验和终端流向回溯。 |
| P2 | **销售区域/客户归属的月度版本快照** | 当前有销售组织与岗位，但未发现区域版本定期冻结、历史还原和按期归属报表。 | 每月自动快照；人员/医院/区域历史归属可按业务发生期查询，不被后续调整覆盖。 |
| P2 | **客户/医院与产品线关系主数据** | 当前有医院、产品分类和授权，但未明确独立维护“客户/医院 × 产品线”关系。 | 维护有效期、审批/同步、下单与报台校验，并支持按产品线统计。 |
| P2 | **经销商指标主数据与系统使用报表** | 当前有 KPI/经营报表；未发现经销商指标主数据和登录、活跃、操作等系统使用分析报表。 | 指标定义、取数周期、达标计算及使用频率/活跃度/功能使用报表。 |
| P2 | **订单金额/数量限额与常购订单模板** | 现有授权和审批控制，但未发现订单限额及“常购订单”复用模板。 | 限额按经销商/产品/周期配置，超限拦截或升级审批；模板可复制、失效和审计。 |
| P2 | **GSP 订单资料与订单聚合查询** | 已有订单详情、附件、发货及操作日志；PDF 要求把订单、发货、附件、GSP 产品资料集中在一页。 | 定义 GSP 字段/附件清单，提供全链路聚合视图和权限控制。 |
| P3/需决策 | **短信首登密码自助获取** | 项目决策 D-33 已明确不做邮件与短信，改站内消息+企微/飞书；PDF 方案与当前决策冲突。 | 如恢复，需确定短信供应商、手机号实名/绑定、限流、审计与费用归属。 |

## 4. PDF 方案架构摘录

- **业务模式**：厂商直销医院、一级至多级经销商分销、平台/物流协同，以及销售和寄售模式。
- **应用层**：PC Web + 移动端；订单、收货、库存、协议、发票、报表和仪表盘；工作流、日志、报表服务、文件服务。
- **集成层**：SAP/ERP、CRM、OA/BPM、外部服务和 Web API/Web Service。
- **数据与安全**：集中数据库、接口管理和权限管理。PDF 的网络示例采用 Azure、应用网关/WAF、TLS、应用服务器与 SQL 数据库分层部署；这是参考架构，不应直接替代本项目 Docker/Aliyun 的既有部署决策。
