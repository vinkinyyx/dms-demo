## 第一阶段：API自动化快速回归（约38秒）

### 1.1 执行命令

```bash
cd automation_test

# 全量运行（五层套件 + 原有模块，约38秒）
python -m pytest tests/ -v --tb=short

# 仅运行五层套件（快速回归核心，约30秒）
python -m pytest tests/test_l1_entry.py tests/test_l2_list.py tests/test_l3_detail.py tests/test_l4_interaction.py tests/test_l5_link.py -v

# 按层级单独运行
python -m pytest tests/test_l1_entry.py -v   # L1 入口层：API是否存在
python -m pytest tests/test_l2_list.py -v    # L2 列表层：字段/分页/筛选
python -m pytest tests/test_l3_detail.py -v  # L3 详情层：三要素+明细
python -m pytest tests/test_l4_interaction.py -v  # L4 交互层：CRUD+校验
python -m pytest tests/test_l5_link.py -v    # L5 链路层：端到端一致性
```

### 1.2 五层验证模型说明

> L1过了≠功能可用，但L5过了才真的能用。五层逐层深入，每一层都有明确的通过标准。

| 层级 | 名称 | 验证目标 | 通过标准 | 用例数 |
|------|------|---------|---------|--------|
| **L1** | 入口层 | API接口存在且可达 | HTTP 200 + code 0 | 69 |
| **L2** | 列表层 | 列表有数据、字段完整、分页有效 | 字段数达标 + size生效 + 有total | ~80 |
| **L3** | 详情层 | 详情三要素完整（基本信息+业务明细+操作记录） | 详情存在 + 明细结构合理 | ~70 |
| **L4** | 交互层 | CRUD操作正常、字段校验有效 | 创建成功 + 必填项报错正确 | ~15 |
| **L5** | 链路层 | 跨模块数据一致、业务闭环通顺 | 关联数据匹配 + 链路无断裂 | ~12 |

### 1.3 验证标准

- ✅ **passed**：正常通过
- ⚠️ **skipped**：可接受（数据不足、条件不满足）
- ⚠️ **xfailed**：需记录但不阻断（已知Bug/未实现功能，有明确reason）
- ⚠️ **xpassed**：惊喜项（标记为预期失败但实际通过，说明问题可能已修复，需人工确认后移除xfail）
- ❌ **任何 failed** = 回归不通过，必须排查

### 1.7 常见问题排查

| 现象 | 可能原因 | 处理方式 |
|------|---------|---------|
| 全部用例连接超时 | 测试环境挂了 | 检查服务器是否启动 |
| 登录用例全部失败 | 账号密码改了 | 更新 config.py 中 ACCOUNTS |
| 某模块全部404 | 该模块接口路径变了 | 更新 config.py 中 ApiPaths |
| 分页测试全部失败 | 分页参数名变了 | 检查 test_l2_list.py 中 SIZE_PARAM |
| 新出现failed用例 | 后端改了字段或逻辑 | 对比最近提交，更新测试断言 |
| 偶发性失败 | 接口响应慢/网络抖动 | 重跑一次确认，多次失败才是Bug |
| xpassed数量增加 | 已知问题被修复了 | 找到对应测试，移除xfail标记 |
