# 合同模块改造设计文档

> 版本：V1.0（与 DMS v3.11.0 同步）  日期：2026-08-09
> 依据：《合同管理系统_需求规格说明书_V3.0》，采用**方案 A：实体合并 + 方案 B：务实 MVP** 落地，合同模块作为 DMS 内部子系统。

## 0. 与 DMS v3.11.0 同步说明

- 实体模型：废弃 `contract_applications`、`contract_diff`、`contract_signatures`；以 `contracts` 为唯一主实体，`status` 贯穿草稿/审批中/已生效/已驳回/已终止/已到期。
- 菜单：合并为「合同管理」组（`合同工作台 /contracts` + `合同模板 /contracts/templates`）。
- 审批：复用 v3.10.0 审批中心，`BUSINESS_TYPE=CONTRACT`，由 `ContractApprovalCallback` 驱动合同状态流转。
- 二期/暂不做：浏览器内 Word 原文编辑 + 段落级 diff、电子签章、外部办结同步、`numbering_rules` 仅字段预留。
- 老测试数据不迁移，直接清空重建。

## 1. 背景与目标

现有「合同授权」菜单组下有「合同申请」与「合同」两个割裂页面：申请页是字段极少的通用 CRUD，合同页是只读列表，后端为 contract_applications + contracts 双表。与需求文档的四段式（法务模板配置 → 用户申请 → 审批 → 办结同步）差距较大。

本次改造目标：

1. 合并两个合同页面为统一的「合同工作台」，一条合同记录贯穿全生命周期。
2. 新增「合同模板」菜单，供法务上传 Word、自动识别字段、配置审批显隐、绑定分类、发布版本。
3. 复用 DMS 现有租户、权限、审批中心、文件存储，不做嵌入式/独立登录。
4. 外部系统办结同步本期不做，预留扩展点。

## 2. 菜单与权限

菜单组「合同管理」：

| 菜单 | 路由 | 权限码 | 说明 |
| --- | --- | --- | --- |
| 合同工作台 | /contracts | contract:view | 统一入口，列表+新建+详情 |
| 合同模板 | /contracts/templates | contract_template:manage | 法务配置端 |

下线原「合同申请」(contract-apps) 与「合同」(contracts) 菜单项；「授权管理」保持不变。

权限点：

- contract:view 查看合同
- contract:manage 新建/编辑/提交合同
- contract_template:manage 模板配置与发布

## 3. 核心决策

- **实体合并（方案 A）**：废弃 contract_applications 独立实体，以 contracts 为唯一主实体，用 status 贯穿草稿、审批中、生效、终止/到期。老测试数据不迁移，直接清空重建。
- **变更/续签/终止**：基于原合同生成新合同版本，通过 ref_contract_id + application_type 关联，走审批后生效。
- **字段回填 Word 成稿**：纳入 MVP。用户提交后用 POI 将字段值回填模板 Word 生成成稿文件供下载/预览。
- **字段来源**：以上传 Word 自动识别为主，法务可在识别结果上手动新增、编辑、删除字段。
- **审批**：复用现有 approval 模块，BUSINESS_TYPE=CONTRACT，回调改为驱动 contracts 状态流转。

## 4. 状态机

合同 status：

- draft 草稿（可编辑、可提交、可删除）
- pending 审批中（锁定，等待审批中心结果）
- effective 已生效（审批通过）
- rejected 已驳回（可修改后重新提交）
- terminated 已终止
- expired 已到期（定时任务按 valid_to 置位）

操作：

- 草稿 → 提交 → pending
- pending → 审批通过 → effective
- pending → 驳回 → rejected
- rejected → 修改后再次提交 → pending
- effective → 发起终止审批 → pending（终止流程）
- effective → 到期 → expired

`json

- 审批回调 ContractApprovalCallback 改为驱动 contracts。

## 6. 后端设计

包路径 com.dms.contract，按 controller / service / entity / repository / dto 组织。

### 6.1 模板相关接口

- GET /api/contract-templates 列表（分页、按分类/状态筛选）
- POST /api/contract-templates 新建草稿（含上传 Word 后调用解析）
- GET /api/contract-templates/{id} 详情
- PUT /api/contract-templates/{id} 更新草稿（编辑字段定义）
- POST /api/contract-templates/{id}/publish 发布
- POST /api/contract-templates/{id}/new-version 基于某版本创建新版本草稿
- POST /api/contract-templates/parse-docx 上传 Word 解析字段（multipart file，返回识别出的 fields 数组）

Word 解析（TemplateDocxParser）：用 Apache POI 遍历 XWPFDocument 的内容控件（XWPFSDT / SDT），识别文本、下拉、日期、复选框、数字；同时扫描段落与表格中的 \ 占位符。未识别正文作为固定原文。返回字段定义列表。

### 6.2 合同相关接口

- GET /api/contracts 列表（按 status 页签、经销商、分类、编号、有效期筛选）
- GET /api/contracts/actions/export 导出当前筛选结果为 xlsx（16 列，v3.11.1）
- POST /api/contracts 新建草稿
- GET /api/contracts/{id} 详情（含模板字段定义、form_data、附件、审批轮次）
- PUT /api/contracts/{id} 更新草稿/驳回态
- DELETE /api/contracts/{id} 删除草稿
- POST /api/contracts/{id}/submit 提交审批（生成成稿 Word，启动审批流）
- POST /api/contracts/{id}/withdraw 撤回
- GET /api/contracts/{id}/preview-docx 预览/下载成稿
- POST /api/contracts/{id}/attachments 上传附件
- DELETE /api/contracts/{id}/attachments/{attId}
- GET /api/contracts/match-template?category=xxx 按分类匹配当前已发布模板（新建合同页用）

成稿生成（ContractDocxGenerator）：基于模板 original_file_id，将 \ 占位符与内容控件替换为 form_data 值，输出新 Word 存入 files，写回 source_file_id。

### 6.3 审批回调

ContractApprovalCallback（BUSINESS_TYPE=CONTRACT，businessId=contractId）：

- onApproved：status=effective，effective_at=now，写 revision。
- onReturned/onRejected：status=rejected，记录意见到 revision。
- onWithdrawn：status=draft。
- onTerminated：按结果置 terminated 或 draft。

### 6.4 到期定时任务

每日扫描 valid_to < current_date 且 status=effective 的合同，置 expired。

前端为自定义页面，不再使用通用 ModuleView/CrudView 合同配置。技术栈沿用 Vue3 + Element Plus。

新增文件：

- src/views/contract/ContractWorkspace.vue 合同工作台（列表+状态页签）
- src/views/contract/ContractEdit.vue 新建/编辑（分区表单 + 动态字段 + 附件）
- src/views/contract/ContractDetail.vue 合同详情（信息+附件+审批时间线+轮次）
- src/views/contract/ContractTemplateList.vue 模板列表

路由：

- /contracts
- /contracts/new

### 7.1 合同工作台

- 顶部状态页签：全部/草稿/审批中/已生效/已驳回/已终止/已到期。
- 筛选：合同编号、合同名称、经销商、分类、有效期范围。
- 列：合同编号、合同名称、分类、经销商、金额、有效期、状态、当前节点、更新时间。
- 行操作按状态：草稿→编辑/提交/删除；审批中→撤回/查看；生效→查看/发起变更/续签/终止；驳回→编辑/查看。
- 右上「新建合同」。

### 7.2 新建/编辑

分区：

1. 基础信息：合同名称、分类（选后自动匹配模板）、申请类型、经销商、甲乙方、有效期、金额、付款/结算、负责人。
2. 模板动态字段：根据匹配模板的 fields 按 group 动态渲染；填表时表单模型写入 form_data。
3. 附件与合同正文：上传 Word/PDF 等。

操作：保存草稿、提交（提交前校验必填）、预览成稿。提交后锁定。

双区布局（左表单 / 右预览）：MVP 右区展示「成稿 Word 预览/下载」与基本信息摘要，不做原文原地编辑。

### 7.3 合同详情

- 基础信息、动态字段、附件、审批时间线（contract_revisions + 审批中心节点）。
- 提供下载成稿、上传签章附件（仅备注，无电子签章流程）等。

### 7.4 合同模板配置

- 列表：编号、名称、绑定分类、版本、状态、更新时间；操作：编辑草稿、新建版本、发布、停用。
- 配置页：
  1. 上传 .docx → 调 parse-docx → 展示识别字段。
  2. 字段表格可编辑标签/类型/必填/审批可见/分组/排序，可手动新增/删除字段。
  3. 绑定业务分类。
  4. 保存草稿 / 发布。

### 7.5 审批详情对接

复用审批中心。合同审批渲染组件按固定三块：业务信息、审批可见动态字段、字段级变更对比（两轮 snapshot diff）。通过/驳回/转办由审批中心提供。

## 8. 文件与存储

复用现有 /api/files 上传下载（files 表 + 本地存储），合同正文、附件、模板 Word 均通过该接口。bizType 使用 contract-template / contract-final / contract-annex。

## 9. 二期 / 暂不做清单

以下需求来自需求文档 V3.0，本次 MVP 不实现，在此登记：

1. 浏览器内直接编辑 Word 固定原文 + 段落级自动留痕 diff（原始文本+修改后文本+位置，上下文 2-3 行对照）。
2. 预览区富文本原地编辑、表格增删行列、合计行实时计算。
3. 长文本字段自动序号实时重整（一/二/三、1.1、A/B/C 等规则）；numbering_rules 字段已预留。
4. Word 内容控件完整类型识别（图片、整页附件、嵌套重复表格等复杂控件），MVP 仅覆盖 text/number/date/select/checkbox 与占位符。
5. 办结后向第三方系统定时同步（可配置间隔、字段映射、REST 推送、Basic/OAuth2/API Key 鉴权、同步日志、指数退避重试、告警）。
6. 电子签章（CA 证书、短信签署、contract_signatures 流程）。
7. 嵌入式集成（iframe/WebComponent/Vue 组件对外嵌入、宿主 Token 鉴权、CSS 隔离、回调通知）——本期合同直接作为 DMS 内部模块。
8. 价格/商务政策（返利、政策周期等）的结构化关联表：MVP 通过模板 form_data 字段承载（key 如 price_policy_id / rebate_rate / policy_period），后续如需结构化查询再建独立关联表。
9. 宿主项目数据自动回填（从外部项目系统获取项目名称/编号/预算科目）；MVP 由用户在表单手动填写。

## 10. 实施步骤

1. 数据库：新建 V77 迁移，DROP 旧合同表（contract_applications / contract_diff / contract_signatures），重建 contracts / contract_templates / contract_attachments / contract_revisions。
2. 后端：模板实体与 Word 解析、合同实体与接口、审批回调改造、成稿生成、到期任务。

4. 联调：草稿→提交→审批通过生效→成稿下载 全流程；驳回重提；变更/续签/终止。
5. 清理：移除前端 modules.js/menu.js 中旧合同配置，删除后端废弃类。
