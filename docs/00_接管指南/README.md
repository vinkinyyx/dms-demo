# DMS 开发接管指南

本目录用于帮助开发人员在系统已经上线或准备上线后，快速接管 DMS，具备本地开发、测试环境运维、生产问题排查和常规需求变更能力。

## 1. 阅读顺序

建议按以下顺序阅读，不要直接从超大的历史 README 或代码开始：

1. `系统全景图.md`：先建立整体认知。
2. `开发环境启动手册.md`：当天跑通本地环境。
3. `运维部署手册.md`：掌握测试/生产环境如何运行。
4. `需求变更手册.md`：知道常见改动的标准路径。
5. `排障手册.md`：遇到问题时按路径定位。
6. `七天接管计划.md`：按天完成接管训练。
7. `接管验收清单.md`：用任务结果判断是否真正接管。

## 2. 项目概览

DMS 是一个前后端分离的经销/销售管理系统，当前仓库包含：

- `backend/`：Spring Boot 3.2.5 后端，Java 17，约 95 个 Controller，Flyway 迁移已到 V71。
- `frontend-vue/`：业务前端，Vue 3 + Vite + Element Plus + Vant，包含 PC 工作台和移动端页面。
- `admin-vue/`：平台后台，Vue 3 + Vite + Element Plus，部署路径为 `/admin/`。
- `docs/`：产品、需求、数据库、API、部署、测试、报表等历史文档。
- `scripts/`、`tools/`：脚本和辅助工具，使用前需要确认是否仍适用当前版本。

后端主要技术栈：

- Spring Boot 3.2.5 / Java 17
- Spring Security + JWT
- Spring Data JPA + PostgreSQL
- Flyway 数据库迁移
- Redis / Redisson
- MinIO 文件存储
- Springdoc OpenAPI / Swagger

前端主要技术栈：

- Vue 3 + Vue Router + Pinia
- Vite 5
- Element Plus
- Vant（业务前端移动端）
- ECharts（报表/图表）
- Axios

## 3. 接管目标

完成本指南后，开发人员应能独立做到：

- 在本地启动后端、业务前端、平台后台。
- 看懂主要业务模块和系统部署拓扑。
- 在测试环境查看日志、重启服务、定位接口错误。
- 完成字段、页面、接口、权限、报表、状态流等常见需求变更。
- 执行数据库备份、版本回滚和基本故障恢复。
- 继续安全地使用 AI 辅助开发，而不是让 AI 随意改架构。

## 4. 当前已知交接风险

接管前必须优先确认以下事项：

- 仓库中未找到 `docker-compose.yml` 或等价 Compose 文件；`backend/README.md` 提到过 `docker compose up -d`，需要从部署环境或历史备份中补齐该文件。
- `backend/README.md` 存在中文编码异常，应优先参考本目录和源码配置，并在后续修正该文件编码。
- `application.yml` 中存在默认 JWT 密钥和默认数据库/MinIO 密码，生产环境必须通过环境变量覆盖。
- `docs/` 下历史文档很多，部分内容可能滞后于代码；涉及最终实现时以源码、数据库迁移、接口行为和测试环境为准。
- `scripts/`、`tools/` 下存在临时检查脚本和部署辅助文件，不能直接视为生产自动化流程。

## 5. 文档维护规则

- 新增或修改部署步骤时，同步更新 `运维部署手册.md`。
- 新增一类需求改法时，同步补充 `需求变更手册.md`。
- 处理一次真实故障后，把定位路径沉淀到 `排障手册.md`。
- 代码结构变化后，更新 `系统全景图.md`。
- 不要把生产密码、Token、私钥写入文档，统一写入环境变量或密钥管理系统。
