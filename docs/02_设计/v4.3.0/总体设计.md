# DMS v4.3.0 总体设计

> 状态：设计评审稿（评审通过后才进入编码/部署）
> 范围：R1 多出库单销退、R2 客户多联系人/多地址、R3 整单一口价/0 金额、R4 扩展促销、R5 客户代金券、R6 产品全局折扣、R7 客户全局折扣、R8 折扣加价方向、R9 客户自助注册与自助下单。
> 计价规则配套：《订单折扣与促销规则说明书.md》。

## 1. 目标与边界

### 1.1 本期目标
- 一张销退单可关联同一经销商多张销售出库单，按来源行锁定可退量并分别回写。
- 客户主数据支持多联系人、多收货地址；订单选择地址并快照。
- 计价支持：合同价/客户价/全局价、产品全局折扣、促销（满减/满赠/满 N 件打折）、行手动折扣（可加可减，%/金额）、客户全局折扣、整单手动折扣（可加可减，%/金额）、整单一口价、整单/行 0 金额、代金券。
- 产品全局折扣、客户全局折扣各提供独立 PC 维护页面（按时间段、历史留痕）。
- 客户代金券：厂家统一发放、有效期、范围、一单一张、抵扣不摊入单价。
- 客户自助注册（PC + H5）→ 审核 → 自动建账号与客户主数据；客户角色只能操作自己的数据。
- H5 支持客户自助下单全流程（地址、折扣、券、一口价、促销文案）。

### 1.2 不做什么
- E 清单中除满减/满赠/满 N 件打折外的促销（满额折、阶梯增量、套餐、秒杀、首单价等）本期不做。
- 代金券不接真实支付、不找零、一单仅一张。
- 自动折扣（产品/客户/促销）不支持加价；加价只用于手动行/整单折扣。
- 采购、库存盘点等非销售模块数量精度不在本期范围。
- 生产环境部署需另行明确授权。

### 1.3 版本与发布
- 版本升至 v4.3.0（MINOR），同步 CHANGELOG 与文档。
- MINOR 全量冒烟 + 受影响模块 5 维深度测试；F1–F5 核心流全量回归。

## 2. 数据模型（Flyway 从 V100 起）

### 2.1 R2 客户联系人 `dealer_contacts`
- id, tenant_id, dealer_id, contact_name, phone, email, position, is_default, status, remark, 审计字段。
- 迁移：从 `dealers.contact_name/phone/email` 回填一条默认联系人；dealers 旧字段保留为兼容快照，后续以子表为准。

### 2.2 R2 收货地址 `dealer_addresses` 增强
- 增加 address_name、is_default、tags(jsonb)；保留 contact_name/phone/province/city/district/address/postal_code。
- 订单继续用 `orders.ship_address_id` + `ship_snapshot`，下单时写地址快照。

### 2.3 R1 多出库单销退（关系化）
- `rma_order_refs`：id, rma_id, sales_out_id, sales_out_code, dealer_id, created_at（同一 rma 的 dealer 必须一致）。
- `rma_order_lines`：id, rma_id, ref_id, sales_out_line_id, product_id, qty(int), unit_price_incl_tax, tax_rate, sub_total, reason, batch_no, seq, 审计字段。
- `rma_orders` 增加 sales_out_count、total_qty、price_snapshot(jsonb)。
- 旧 `rma_orders.lines`(jsonb) 保留只读回显；新数据以关系表为准。
- 可退量按 `sales_out_line_id` 维度锁定（已退+在途+本次），跨出库单不可挪用。

### 2.4 R6 产品全局折扣 `product_global_discounts`
- id, tenant_id, product_id, discount_rate(0~1，只减), valid_from/valid_to, status, remark, 审计字段。
- 同产品时间段不允许重叠（保存拦截并说明原因）；历史保留不覆盖。

### 2.5 R7 客户全局折扣 `dealer_global_discounts`
- 结构同上，维度为 dealer_id；同客户时间段不允许重叠；只减。

### 2.6 合同价 `contract_prices`（本期新增维护）
- id, tenant_id, contract_id, dealer_id, product_id, price_incl_tax, price_excl_tax, tax_rate, valid_from/valid_to, status, 审计字段。
- 取价优先级：合同价（生效合同+有效期） > 客户基础价(DEALER) > 全局价(GLOBAL)。
- 合同详情新增“价格清单”Tab，支持批量维护与导入导出。

### 2.7 R5 代金券
- `customer_vouchers`：id, tenant_id, code, name, dealer_id, face_value, min_spend, scope_type(ALL/PRODUCT/CATEGORY), scope_refs(jsonb), valid_from/valid_to, status(ISSUED/USED/EXPIRED/DISABLED/VOID), batch_no, remark, 审计字段。
- `customer_voucher_usages`：id, voucher_id, order_id, order_code, used_amount, used_at, status(USED/REFUNDED/REVERSED)。
- 厂家统一发放（可按客户/等级批量生成券码）；抵扣只记订单层，不写行单价。

### 2.8 订单与行扩展
- `orders`：pricing_mode(NORMAL/FIXED_PRICE/ZERO_ORDER/VOUCHER)、voucher_id、voucher_amount、promo_messages(jsonb)、price_snapshot(jsonb)；复用已有 header_discount_*、final_amount。
- `order_lines`：qty 改 INTEGER；新增 base_price_incl_tax、price_source(CONTRACT/DEALER/GLOBAL)、product_discount_rate/product_discount_amount、promo_type/promo_id/promo_hit_id、unit_price_incl_tax(EA 单价 2 位)、ea_discount_amount、line_zero(bool)。
- 关键：代金券不落到行；一口价/整单减差额通过行分摊体现（headerDiscountAmount + EA 单价）。

### 2.9 数量整型与 BOM
- 销售订单行、销退行、销售出库行及相关收发货明细 qty 改 INTEGER；应用层校验正整数。
- `product_bundle_lines.quantity` 改 INTEGER 并校验正整数；母件整数×子件整数用量=整数出库。
- 迁移前生成小数数据检查报告；测试环境可 ROUND，生产需人工确认。

### 2.10 R9 客户注册与账号
- 复用 `users`：user_type=CUSTOMER，绑定 dealer_id，status=PENDING/ACTIVE/REJECTED。
- `customer_registrations`：id, tenant_id, register_name, phone, 密码/验证码, company_name, usc_no, legal_person, contact_*, addresses(jsonb), attachments(jsonb), status, reject_reason, reviewer_id, reviewed_at, created_user_id, created_dealer_id, 审计字段。
- 审核通过：事务内建 dealer + dealer_addresses/dealer_contacts + 建 CUSTOMER 用户并绑定。
- 注册页公开：PC `/register/customer`，H5 `/m/register`（未来挂小程序链接）。

## 3. 后端设计

### 3.1 计价引擎（com.dms.v4 演进）
阶段顺序：
1. 取基础价（合同>客户>全局），记 price_source。
2. 产品全局折扣（行级，只减）。
3. 促销（满减/满赠/满 N 打折；同 SKU 同时段唯一；打折类命中行锁死行手动折扣；促销 SKU 不可手动 0）。
4. 行手动折扣（%/金额，可加可减；减不得使行<0）。
5. 得出行金额 lineAmount。
6. 客户全局折扣（整单级只减，按各行 lineAmount 占比摊回行）。
7. 整单手动折扣（%/金额，可加可减，按行金额占比；减不得使任一行<0）。
8. 互斥模式：FIXED_PRICE 一口价（原价、差额摊行）、ZERO_ORDER 整单 0、VOUCHER 代金券（原价+订单层抵扣）。
9. 分摊到 EA：unitPriceInclTax 2 位，尾差落最大行最后一 EA。
10. 含税/不含税/税额重算；逐行、整单非负校验。

分摊铁律：
- 所有整单层加减（客户折扣、整单折扣、一口价差额）统一按“各行折后总价 lineAmount”比例分摊。
- 手动 0 金额行 lineAmount=0，权重 0，低开与高开都不参与分摊。
- 赠品行（isGift）金额恒 0，不参与任何分摊。
- 任一非负校验失败即拦截，错误信息必须含行号/SKU/具体原因。
- 前端预览走 `POST /api/v4/calc/preview`；提交时后端重算落库，不信任前端金额。

### 3.2 促销
- 新增 promo_type：QTY_DISCOUNT(满 N 件打折/固定单价)、QTY_REDUCE(满 N 件减金额)、GIFT(满赠，已有)。
- rule_detail：scope(SKU/CATEGORY)、targetProductId/targetCategoryId、thresholdQty、discountType(PERCENT/FIXED_PRICE/REDUCE_AMOUNT)、discountValue、cycle(ONCE/EVERY_N)、giftProductId/giftQty。
- 同 SKU 同时段唯一：保存/审批时展开 SKU 集合检查时间窗交集，冲突则拦截并列清单。
- QTY_DISCOUNT 命中行禁用行手动折扣（UI+后端）。
- 门槛按同 SKU 合并数量判断；同 SKU 被拆多行提交时拦截，要求合并为一行并说明原因。
- 命中写 order_promotion_hits 并生成文案。
- 退货跌破门槛：赠品按 0 退，已享优惠从退款扣减（RMA 计价处理）。

### 3.3 折扣与合同价维护
- 产品全局折扣 `/api/product-global-discounts`（PC CRUD + 导入导出 + 权限码）。
- 客户全局折扣 `/api/dealer-global-discounts`。
- 合同价 `/api/contracts/{id}/prices`。

### 3.4 代金券
- 发放 `POST /api/customer-vouchers/batch-issue`。
- 可用券查询 `GET /api/customer-vouchers/available`。
- 下单校验：有效期、范围、门槛、一单一张、面值≤原价合计；核销写 usage。
- 整单未出库作废返还券（usage REVERSED）；部分退货/已出库不退券。

### 3.5 销退（R1）
- `POST /api/rma/orders` 支持 salesOutIds + 逐行 qty。
- 校验：出库单 dealer 一致；逐行 qty ≤ 来源行剩余可退；统一状态机。
- 审批通过按来源行分别回写可退/库存；退价按 EA 快照（折扣/一口价用摊后 EA；券单用原价 EA）。

### 3.6 权限（R9）
- CUSTOMER 角色数据范围强制 dealer_id=当前用户 dealer_id（后端查询/AOP 拦截，不靠前端），越权 403。
- 销售可下单范围=自己负责+下级负责客户（基于 sales_owner_user_id/岗位层级）。
- 客户菜单：销售订单、销退申请、合同、我的报表、我的授权、手术报台、资料/地址。
- 注册审核由厂家管理员在审核队列处理。

## 4. 前端设计

### 4.1 PC
- 订单计价区重构：行折扣（%/金额、正负方向）、整单折扣、一口价、整单 0、代金券、促销文案顶部卡片、行促销标签；互斥联动；提交错误精确到行。
- 客户主数据：联系人/地址子表（默认项）。
- 新增页：产品全局折扣、客户全局折扣、代金券发放管理、客户注册审核。
- 合同详情价格清单 Tab。
- 销退单创建：多选出库单（同客户）、按来源行分组、可退量实时校验。
- 统一 CrudView、按钮 permissionCode + v-has、危险操作二次确认。

### 4.2 Admin
- 促销、代金券、产品/客户全局折扣、注册审核的管理端入口（评审确认维护入口归属 PC 还是 admin）。

### 4.3 H5
- 客户注册页 `/m/register`（资料+附件上传）。
- 客户自助下单：选地址、选品、自动折扣、行/整单折扣、一口价、券选择、促销文案、金额明细实时刷新。
- 我的订单/详情、销退申请、手术报台、合同/报表/授权查看。
