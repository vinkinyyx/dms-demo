# DMS 开发规格：页面、字段、规则与接口 v3.7

## 1. 使用约定

本文件是 `01_整合需求文档`、`02_用户故事` 和 `03_功能设计` 的可实施补充。开发人员必须按本文件定义字段、默认值、校验、权限、状态和副作用；未定义的字段不得自行假定业务含义。所有金额使用 `decimal(18,2)`，数量使用 `decimal(18,4)`，日期用本地业务日期，时间用 UTC 保存并在界面按租户时区显示。除状态字典外，业务枚举必须由后端返回，前端不得硬编码中文值。

通用审计字段适用于所有业务主表：`id`、`tenant_id`、`doc_no`（适用时）、`status`、`created_by`、`created_at`、`updated_by`、`updated_at`、`version`、`is_deleted`。更新请求必须携带 `version`；版本不一致返回 `409 CONFLICT` 和最新数据摘要，禁止静默覆盖他人修改。

## 3. 主数据页面规格

### 3.1 产品编辑页

页面采用全屏 Drawer，页签顺序固定为“基本资料、追溯与包装、组套、价格引用、操作日志”。保存草稿不执行外部同步；提交启用后才允许被订单与库存选择。

| 字段 | 类型/格式 | 必填 | 默认/校验 | 行为 |
| --- | --- | --- | --- | --- |
| 产品编码 `productCode` | 大写字母/数字/`-_`，最长 64 | 是 | 租户内唯一；编辑时不可改，除非具备 `product:change-code` | 失焦调用唯一性校验。 |
| 产品名称 `productName` | 文本，最长 200 | 是 | 去首尾空格；不可只含符号 | 列表、选择器均显示编码+名称。 |
| 实体/BU/产品线/分类 | PickerInput | 是 | 下级必须属于上级；分类状态必须启用 | 变更产品线前提示已有价格、授权和库存的影响。 |
| 管控粒度 | 枚举：NONE/LOT/SERIAL/PACKAGE | 是 | 默认继承分类；SERIAL/PACKAGE 时库存明细强制记录序列号 | 已发生库存时仅允许升级粒度，降级需审批迁移。 |
| 单位与换算 | 主单位、包装单位、换算率 | 是 | 换算率大于 0，最多 4 位小数 | 数量录入统一换算到主单位后记账。 |
| 生产商/产地 | PickerInput/文本 | 否 | 产地从字典选；生产商停用不可新选 | 用于库存追溯筛选。 |
| 有效期天数/预警月数 | 整数 | 条件必填 | 有效期产品必须大于 0；预警月数 0-36 | 收货据此计算临期。 |
| GSP 资料要求 | 多选字典 | 否 | 资料类型由质量角色配置 | 订单聚合页显示缺失项。 |
| 启用状态/启用日期 | 开关/日期 | 是 | 停用日期不得早于启用日期 | 停用后不出现在新建选择器。 |

包装页采用树表。父码类型只能高于子码类型；一个子码只能有一个有效父码；聚合数量等于活跃子码数量或其换算量。组套页不允许产品直接或间接引用自身；提交时用深度优先搜索检测循环并返回完整循环路径。

### 3.2 医院产品线关系页

列表默认显示有效记录，筛选项包含医院、产品线、责任岗位、状态、生效日期范围和是否即将到期。新建弹窗字段为医院、产品线、责任岗位、业务状态、生效日期、失效日期、备注、附件。保存时检查同医院+产品线+状态为有效的时间区间是否重叠；重叠返回 `HOSPITAL_PRODUCT_LINE_PERIOD_OVERLAP` 并列出冲突记录。

编辑有效记录时，若该期间已经有订单或报台，禁止缩短到已发生业务日期之前；应引导用户新建后续版本。失效操作要求填写原因，系统创建 `DISABLED` 状态而非删除，并向关联的待提交订单发出重新校验事件。

### 3.3 区域快照页

页面顶部显示月份、版本、状态、来源、记录数、生成任务和操作按钮；明细采用“区域—岗位—用户—医院—产品线”可展开树。自动生成任务在月末 23:30 执行，使用租户时区；同月已有 `PUBLISHED` 版本时不覆盖，只记录跳过结果。

补建操作要求输入月份、引用的组织版本和原因。系统先生成 `DRAFT`，展示与当前组织的新增/移除/转移数量差异，确认发布后锁定。作废只能作用于未被报表锁定的错误草稿；已发布版本如需修订，创建递增版本并使报表默认使用最新已发布版本，同时允许审计报表指定旧版本。

## 4. 政策中心页面与记账规则

### 4.1 价格规则

价格列表字段包括价格类型、产品、对象类型/对象、币种、含税标志、基础价、折扣、最低成交价、优先级、生效区间和状态。保存规则时检查：同一租户、价格类型、产品、对象、币种、含税标志、优先级下的生效区间不得重叠；重叠时返回冲突规则编号。价格试算的执行顺序如下：

1. 验证产品、经销商、医院和订单日期均有效且有授权。
2. 过滤适用的特殊价；无可用特殊价时过滤合同价、经销商价和全局价。
3. 按规则优先级、对象精确度和最近创建时间排序，取第一条。
4. 按规则计算折扣前价、折扣额、返利候选和税额；金额按币种精度舍入。
5. 生成不可变 `pricing_snapshot`，提交订单时重新试算并对比前端快照版本。

若重新试算金额变化，接口返回 `PRICE_CHANGED`，响应内包含旧值、新值和命中规则差异；前端必须让用户确认，不得自动按新价提交。

### 4.2 返利池与流水

返利池详情的“调整”按钮仅创建调整申请，不直接改余额。调整表单字段为池、方向（增加/减少）、金额、税务处理、原因分类、详细原因、依据附件和影响期间。调整审批通过后服务端在一个事务内插入流水并更新汇总余额。

订单提交时的记账顺序：锁定匹配返利池记录 → 检查 `available >= requestedRebate` → 插入 `OCCUPY` 流水 → `available -= amount`、`occupied += amount` → 写订单返利分摊快照 → 提交订单状态。任一步失败则事务回滚。订单被拒绝/撤销时插入 `RELEASE`；订单关闭且满足结算条件时插入 `SETTLE`，同时 `occupied -= amount`。冲红单以原订单关联键写入反向流水，不允许用户手工输入负数绕开原单。

返利调整和订单占用必须使用唯一 `idempotency_key`。重复请求返回原流水结果；发现相同键但金额或业务单据不同则返回 `IDEMPOTENCY_PAYLOAD_MISMATCH` 并告警。

### 4.3 特殊价申请页

页面字段分组如下：

| 分组 | 字段 | 校验 |
| --- | --- | --- |
| 适用对象 | 经销商、医院、产品、产品线、订单类型 | 经销商/医院/产品必须处于有效授权范围。 |
| 额度 | 最大数量、已用数量（只读）、单位、最大金额（可选） | 最大数量大于 0；批准后不可增大，只可新建补充申请。 |
| 价格 | 标准价（只读）、申请单价、最低成交价（只读）、差额金额、折扣率 | 申请单价大于 0；低于最低成交价自动标记高风险。 |
| 有效期 | 开始日期、结束日期 | 结束不得早于开始；最长时长由产品线参数控制。 |
| 依据 | 原因分类、原因说明、招标/报价文件、审批附件 | 原因说明至少 10 个字符；高风险必须上传附件。 |

审批通过后写入 `approved_quantity`、`consumed_quantity=0`、`reserved_amount`、`approval_snapshot`。下单占用额度时以数据库原子条件更新 `consumed_quantity + orderQty <= approved_quantity`；更新行数为 0 时返回 `SPECIAL_PRICE_QUOTA_EXCEEDED`。

## 5. 订单与履约页面规格

### 5.1 订单列表与筛选

订单列表字段必须包含单号、类型、经销商、医院/收货地址、订单日期、状态、审批状态、ERP 单号、发货进度、含税金额、返利金额、创建人和更新时间。默认按更新时间倒序，每页 20 条；支持 10/20/50/100 条切换。筛选条件必须由后端执行，包含关键字、单号、类型、多状态、经销商、医院、产品、日期、金额区间、是否特殊价、是否有未处理异常和 ERP 同步状态。

批量操作只允许导出、批量提交草稿和批量撤回未审批订单。批量提交逐条校验并返回每个单号的成功/失败结果；存在任一失败时不回滚已经成功提交的其他订单，但页面必须给出失败原因下载文件。

### 5.2 订单编辑 Drawer

基本信息字段：订单类型、经销商、订单日期、期望到货日期、收货地址、联系人、联系电话、医院/下级经销商、币种、备注和附件。订单类型切换后若明细与新类型不兼容，系统提示用户清空或取消切换。地址选择器支持“已有地址、新增地址”，新增地址字段为省、市、区、详细地址、联系人、电话、默认地址；电话按地区规则校验。

明细表字段：行号、产品、组套标识、批号要求、数量、单位、基础单价、折扣、特殊价、返利、最终单价、税率、含税金额、可用库存提示、交付备注。产品变更后清空所有价格相关字段并重新试算；数量、产品、医院、经销商、日期变化都会触发防抖试算。订单行删除时若已使用返利/特殊价，仅草稿状态允许删除；提交后通过撤销整单或冲红处理。

提交按钮依次执行本地必填校验、服务端授权校验、价格重算、额度/返利锁定、订单状态变更和 outbox 写入。接口必须返回统一的 `requestId`。提交成功后 Drawer 切换为只读详情并定位到时间线；失败时保留用户输入和逐字段错误。

### 5.3 订单状态权限矩阵

| 当前状态 | 允许动作 | 执行角色 | 必填信息/副作用 |
| --- | --- | --- | --- |
| DRAFT | 编辑、删除、提交、保存草稿 | 创建人或经销商管理员 | 删除仅逻辑删除；提交锁定价格和返利。 |
| SUBMITTED/PENDING_APPROVAL | 撤回、审批通过、拒绝、退回 | 创建人撤回；非发起人审批 | 审批意见必填；通过创建 ERP 待发送事件。 |
| APPROVED | ERP 确认、取消审批 | 集成服务/授权商务 | 确认写 ERP 单号；取消释放未使用额度和返利。 |
| ERP_CONFIRMED | 创建/接收发货、关闭异常 | 集成服务/仓库 | 发货数量不得超过订单可履约数量。 |
| PARTIALLY_FULFILLED | 继续发货、收货、关闭 | 仓库/商务 | 每次履约写执行明细。 |
| FULFILLED | 收货确认、售后、发票归档 | 收货方/售后 | 全部收货后可进入关闭前校验。 |
| CLOSED | 查看、导出、发起冲红/维修 | 有权限业务角色 | 不允许修改原订单。 |

### 5.4 组套与维修具体规则

组套订单的父项不直接占用普通库存，服务端按子项库存分别检查和占用；发货明细同时保存 `kit_parent_line_id` 与原子件行。若允许替代件，替代件必须属于同一替代组、有效并经过业务规则验证；替代时保存替代原因和审批信息。

维修单创建时若输入序列号，系统查询其最近销售、维修、质量冻结和库存状态。序列号处于已报废、已返还或被其他打开维修单占用时禁止创建。维修收件确认后生成 `REPAIR_IN` 流水，返还生成 `REPAIR_OUT`，报废生成 `SCRAP_OUT`；三类流水均不可编辑。

## 6. 库存、包装码和追溯规格

### 6.1 收货与出库执行明细

执行明细字段为来源单、来源行、产品、仓库、批号、序列号、包装码、生产日期、有效期、应执行数量、本次数量、累计数量、状态、执行人、执行时间、异常代码、异常说明和附件。页面默认展示应执行与累计，禁止用户直接修改累计值。

收货提交前按以下顺序验证：待收货单有效 → 操作仓库有权限 → 本次数量大于 0 → 累计不超过应收 → 产品/批号/序列号匹配 → 有效期符合产品规则 → 包装码可用且归属匹配 → 库存状态转换合法。任一失败返回含行号、字段和建议操作的错误集合；接口不接受部分成功，前端可让用户修正后整体重试。

出库提交时额外校验可用库存、质量冻结、特殊价/订单授权和序列号未被占用。可分多批次发货；同一订单行可关联多条出库执行行，但所有执行量之和不能超过审批数量。

### 6.2 库存状态与动作矩阵

| 来源状态 | 动作 | 目标状态 | 前置条件 |
| --- | --- | --- | --- |
| IN_TRANSIT | 收货确认 | AVAILABLE/QUARANTINE | 收货数量和质量校验通过。 |
| AVAILABLE | 订单占用 | RESERVED | 存在有效订单，数量充足。 |
| RESERVED | 出库确认 | OUTBOUND | 订单/授权有效，批号和序列号一致。 |
| AVAILABLE | 移库 | AVAILABLE | 源/目标仓库均有权限，生成成对流水。 |
| AVAILABLE | 借出 | LOANED_OUT | 存在借货单和授权。 |
| AVAILABLE | 质量冻结 | QUARANTINE | 质量人员提出，库存管理员确认。 |
| QUARANTINE | 放行 | AVAILABLE | 质量复核通过，填写放行依据。 |
| 任意可计量状态 | 报废 | SCRAPPED | 需审批、原因和附件，数量不得为负。 |

库存余额表仅由库存流水异步/事务更新，禁止通过后台 CRUD 编辑余额。调整单通过后产生 `ADJUST_IN` 或 `ADJUST_OUT`；数量、原因、附件、审批意见和前后余额必须同时写日志。

### 6.3 包装码扫描返回协议

`POST /api/v1/package-codes/scan` 请求体包含 `code`、`operation`（RECEIVE/SHIP/QUERY/AGGREGATE/DISAGGREGATE）、`warehouseId`、`businessDocId`、`scannedAt`。成功响应包含产品、包装层级、父码、有效子码数量、库存状态、当前归属、可执行动作和校验消息。无效码返回 `PACKAGE_CODE_NOT_FOUND`；已出库码返回 `PACKAGE_CODE_NOT_AVAILABLE`；父子归属冲突返回 `PACKAGE_HIERARCHY_CONFLICT`，响应中包含冲突的父码/子码但不得泄露无权组织的详细信息。

扫码聚合界面先扫描父码，再连续扫描子码；每扫一项显示绿色成功行或红色失败行。点击“确认聚合”前仅保存在前端会话，服务端确认时对完整集合再做一次原子校验。网络中断时本地仅保存待重试扫描草稿，并明显标记“未入账”，重新联网后必须用户确认再提交。

## 7. 销售、发票、质量页面规格

### 7.1 销售出库与手术报台

销售出库表单字段为销售类型、经销商、医院/下级经销商、产品线、仓库、销售日期、植入单号、科室、医生、手术日期、手术类型、患者资料（受字段权限保护）、备注和附件。销售类型为 `HOSPITAL_SALE` 时医院、产品线、仓库和销售日期必填；为 `DISTRIBUTION` 时下级经销商、授权和上级关系必填。

患者姓名、性别、年龄属于敏感字段。默认仅医疗业务角色可见；报表仅保留脱敏值或聚合统计。导出前需二次确认用途并写审计日志，未获得 `patient-data:export` 权限时导出结果不包含敏感字段。

### 7.2 发票处理

发票录入字段包括发票类型、号码、开票日期、金额、税额、币种、购销双方、关联订单/销售单、扫描件/PDF、状态和备注。号码在“发票类型+销方税号+号码”范围内唯一；重复导入返回已有记录链接。批量导入先进行文件结构、必填、金额和关联单据校验，生成预览任务；用户确认后才写入正式数据。

冲红操作字段为原发票、红冲原因、红字日期、红字金额、红字文件和后续处理说明。红冲金额不得超过原票剩余可红冲金额；完成后原票展示已冲红累计和关联红票。任何发票扫描件的替换使用新附件版本，不删除旧版本。

### 7.3 质量投诉与 CAPA

投诉创建页字段分为：发生信息（发生日期、来源、医院/经销商）、产品信息（产品、批号、序列号、包装码）、事件信息（等级、问题分类、描述、影响数量）、处置资料（临时措施、附件、责任部门、截止日期）。严重等级为 `CRITICAL` 或 `MAJOR` 时，产品、批号/序列号、责任部门、截止日期和至少一个附件必填。

调查页每条记录包含调查人、日期、结论、根因分类、证据附件。CAPA 行包含措施类型、责任人、计划完成日期、实际完成日期、验证方式、验证结论和状态。关闭接口先检查所有 CAPA 为完成、必填调查存在、复核人非发起人且质量冻结建议已处理；任一不满足则返回阻断项列表。

## 8. 报表、预警与接口监控

报表请求统一接受 `dimension`、`measures`、`filters`、`timeRange`、`orgScopeMode`。`orgScopeMode=CURRENT` 使用当前组织关系；`SNAPSHOT` 必须传或推导快照月份。报表后端拒绝无日期范围且无聚合限制的大范围明细导出，返回 `REPORT_RANGE_REQUIRED`，以避免生产查询压垮数据库。

预警由规则任务产生，字段包括规则、业务对象、严重级别、触发值、阈值、责任角色、状态、首次触发时间、最后通知时间和处理说明。相同规则+对象的未关闭预警合并更新，不重复刷屏；达到提醒间隔才再次通知。预警确认不等于关闭，关闭必须记录处理结果和证据。

接口监控详情显示方向、外部系统、对象、业务主键、幂等键、状态、请求摘要、响应摘要、重试次数、下次重试时间和关联单据。重放前先校验消息不是成功状态、当前用户有重放权限、关联业务单仍有效；重放创建新的尝试记录而不覆盖原始失败记录。

## 9. 错误码、通知与审计最低要求

| 错误码 | HTTP | 前端提示 | 处理方式 |
| --- | --- | --- | --- |
| `AUTHORIZATION_EXPIRED` | 422 | 授权已失效，无法提交。 | 提供查看授权或联系管理员入口。 |
| `INSUFFICIENT_STOCK` | 422 | 指定仓库/批次库存不足。 | 显示可用量、占用量和替代建议。 |
| `PRICE_CHANGED` | 409 | 价格政策已变化，请确认新金额。 | 展示差异，用户确认后重新提交。 |
| `REBATE_BALANCE_INSUFFICIENT` | 422 | 可用返利不足。 | 刷新返利池并允许移除返利后继续。 |
| `SPECIAL_PRICE_QUOTA_EXCEEDED` | 422 | 特殊价额度已用完或已过期。 | 显示剩余额度和到期日。 |
| `INVENTORY_STATE_INVALID` | 422 | 当前库存状态不允许此操作。 | 展示当前状态和允许动作。 |
| `SELF_APPROVAL_FORBIDDEN` | 403 | 发起人不能审批自己的申请。 | 要求切换至合规审批人。 |
| `CONCURRENT_MODIFICATION` | 409 | 数据已被其他用户更新。 | 显示最新版本并允许重新加载。 |
| `INTEGRATION_RETRY_PENDING` | 409 | 外部系统处理中，请稍后刷新。 | 提供消息详情链接。 |

所有成功/失败写操作必须生成请求 ID 并在响应头与操作日志中返回。站内消息模板至少包括订单待审批、授权到期、临期库存、返利不足、特殊价到期、质量 CAPA 超期、接口失败和盘点迟报；通知接收人按照“直接责任人—上级角色—平台管理员”的升级规则计算，企微/飞书发送失败不影响业务事务，但需产生接口告警。

## 10. 开发交付物清单

一个功能模块合并前必须包含：数据库迁移脚本及回滚说明、实体/DTO/校验器、权限点、状态机单元测试、服务事务测试、API 契约及错误码、PC/H5 页面、字段级表单测试、端到端关键路径、操作日志验证、监控指标与部署配置。涉及真实外部系统的模块还必须提交字段映射表、样例报文、幂等策略、失败重放手册和双方对账用例。
