# DMS UI 视觉与页面交互规格 v3.7

## 1. 适用范围与原则

本规范覆盖 PC 管理端与 H5 作业端的颜色、排版、空间、组件状态和关键页面行为。其目标是让高密度医疗经销业务保持清晰、稳定、可追溯：界面应先帮助用户判断“我在哪个组织、正在处理什么单据、该单据处于什么状态、下一步能做什么”，再呈现次要信息。所有页面必须复用 token 和组件，不得在页面内定义新的蓝色、圆角、阴影或状态含义。

本规范为当前项目的实施基线，不把未采集的 `xhs-q.htdkgroup.com` 实际样式当作事实。完成现场采集后，只能通过设计评审更新 token 或组件规则，不能直接复制页面造成权限、可用性或医疗数据展示问题。

## 2. Design Tokens

### 2.1 颜色

| Token | 色值 | 用途 | 禁止用途 |
| --- | --- | --- | --- |
| `--color-primary` | `#1677FF` | 主按钮、可点击主链接、当前菜单、焦点环 | 不用于大面积正文或危险操作。 |
| `--color-primary-hover` | `#4096FF` | 主按钮悬停、链接悬停 | 不替代禁用色。 |
| `--color-success` | `#16A34A` | 已完成、有效、通过、库存可用 | 不表示“可编辑”。 |
| `--color-warning` | `#D97706` | 临期、待处理、注意、部分完成 | 不表示审批拒绝。 |
| `--color-danger` | `#DC2626` | 错误、拒绝、逾期、不可逆风险 | 不用于普通删除链接。 |
| `--color-info` | `#475569` | 辅助状态、说明 | 不用于禁用控件。 |
| `--color-text` | `#1F2937` | 一级正文、标题 | 不可低于 14px 的正文。 |
| `--color-text-secondary` | `#64748B` | 辅助文本、时间、说明 | 不能承担唯一状态信息。 |
| `--color-border` | `#E2E8F0` | 分隔线、输入框默认边框 | 不作为卡片阴影。 |
| `--color-bg` | `#F8FAFC` | 工作区背景 | 不替代表格斑马背景。 |
| `--color-surface` | `#FFFFFF` | 卡片、抽屉、表格表面 | 不用于禁用状态。 |

状态徽标始终包含文字：草稿为灰色“草稿”；待审批为橙色“待审批”；已通过/已完成为绿色；部分履约为蓝色；已拒绝/已取消/已逾期为红色；已关闭为深灰色。每个徽标应有浅色背景、深色文字和 1px 边框，不能只用实心彩色方块。

### 2.2 字体、间距和层级

默认字体为 `"Microsoft YaHei", "PingFang SC", Arial, sans-serif`。PC 基础字号 14px，行高 22px；表格密集模式可用 13px/20px，但表单标签和错误文本不得小于 12px。页面标题 20px/28px、600；区块标题 16px/24px、600；抽屉标题 18px/26px、600；辅助说明 12px/18px。

间距只使用 4、8、12、16、20、24、32、40、48px。页面内容区内边距 24px，卡片内边距 16px，表单组之间 24px，字段行间距 16px。圆角：按钮和输入框 6px，卡片和 Drawer 内嵌区域 8px，标签 4px；不使用胶囊形状承载大段文本。阴影只用于浮层：Drawer `0 12px 32px rgba(15,23,42,.18)`，Modal `0 16px 48px rgba(15,23,42,.22)`；普通卡片使用边框而非阴影。

### 2.3 响应式断点

PC 为 `>=1200px`，窄桌面为 `992-1199px`，平板为 `768-991px`，手机为 `<768px`。PC 主内容最大宽度不设固定上限；复杂表格允许横向滚动但必须固定单号、状态和操作列。H5 内容左右内边距 16px，触控元素最小 44×44px，底部固定操作栏必须预留 `env(safe-area-inset-bottom)`。

## 3. 全局框架与导航

PC 顶栏高度 56px，左侧菜单展开宽度 224px、收起宽度 64px，页签栏高度 40px。顶栏左侧显示产品标识与租户/实体切换；右侧依次为全局搜索、消息中心、帮助、用户菜单。租户/实体切换后必须弹出确认提示并清空本地筛选缓存，避免在错误实体下继续处理单据。

菜单分组采用“工作台、渠道与主数据、订单与履约、库存与追溯、销售与质量、报表与治理、系统管理”。一级分组可以展开/收起；当前路由使用主色背景浅化和左侧 3px 指示条，不应只依赖文字加粗。无权限菜单不渲染；有菜单但无数据时显示业务空态，不显示 403 错误页。

面包屑展示不超过 4 级，最后一级为当前页面且不可点击。详情页标题左侧有返回列表，标题右侧显示单号/状态和上下文动作；从报表或待办进入详情后，返回动作必须回到来源页面并保留筛选条件。

## 4. 通用交互状态

### 4.1 加载、空态与错误

首次加载列表显示 5-10 行骨架屏，不使用整页旋转图标；筛选和分页仅在表格区域显示加载层，保留筛选条件。无数据按原因区分：首次无数据提供“新建/导入”入口；筛选无结果提供“清空筛选”；无权限不透露总数，仅提示联系管理员。

网络错误显示错误标题、简短原因、请求 ID、重试按钮和返回操作；接口超时不自动重复提交写操作。保存、提交、扫码等写操作期间按钮置为 loading 并禁用同一动作，接口返回后恢复；若用户关闭页面，必须提示请求仍在处理并提供单号/请求 ID 查询入口。

### 4.2 表单校验与脏数据

字段在失焦后校验，提交时校验所有可见和隐藏必填字段。错误文本位于字段下方，红色边框与错误图标同时出现；页签内有错误时页签标题显示红点和错误数量。表单发生修改即设置 dirty 状态，关闭 Drawer、切换页签、刷新页面均触发离开确认。

日期范围控件默认限制结束日期不早于开始日期；金额和数量输入右对齐、千分位展示、编辑时保留原始小数，禁止使用浮点 JavaScript 直接计算。选择器加载失败显示可重试状态，不能退化为自由文本以绕过主数据校验。

## 5. 组件详细规格

### 5.1 按钮、链接和危险操作

每个页面最多一个主按钮，通常为“新建订单”“新建产品”等创建动作。主按钮高度 32px，表格行内按钮为文字按钮或 28px 次按钮；按钮文案使用动词+对象，禁止只写“确定”。危险操作（删除、作废、冲红、报废、质量冻结、接口重放）为红色文字或危险按钮，点击后需确认框展示对象名称、不可逆影响和必填原因输入。

满足以下条件的操作必须二次确认：会减少库存、释放/核销返利、撤销已提交单据、改变审批状态、删除附件版本、重放外部消息、导出敏感患者资料。确认框的确认按钮应使用业务动词，如“确认冲红”，而非“确定”。

### 5.2 筛选与表格

筛选区默认展示 4-6 个最高频条件，点击“高级筛选”展开其余条件；已生效条件以可关闭 chip 展示并在标题旁显示数量。日期筛选提供今天、本周、本月、上月、本季度、自定义；进入报表时默认本月，进入审计时默认最近 7 天。

表头固定在滚动容器顶部，数据行高度标准为 44px、密集为 36px。单号和关联编码使用可点击链接，跳转前在新页签或当前页签遵循用户偏好；状态列固定显示完整文案；金额列右对齐，数量列右对齐，日期使用 `YYYY-MM-DD`，日期时间使用 `YYYY-MM-DD HH:mm`。表格行内操作收敛在“更多”菜单，常用动作最多显示两个。

### 5.3 Drawer、Modal、页签与时间线

复杂 Drawer 宽度为视口 80%，最小 960px，窄桌面下为 100%；底部操作栏固定，左侧显示保存状态和最后保存时间，右侧依次放“取消/保存草稿/提交”。Drawer 内部页签切换不丢失已输入数据，提交成功后将编辑页签转为详情模式。

Modal 仅用于确认、少量字段或预览，最大宽度 720px。时间线按倒序显示，节点包含动作、操作者、角色、时间、意见、附件与关联链接；系统事件与人工事件视觉区分，但均不可编辑。

## 6. 关键页面线框与交互

### 6.1 工作台

首屏从上至下为欢迎区/实体上下文、四张 KPI 卡、待办与预警、经营趋势、库存与接口异常。KPI 默认：本月订单金额、待审批数、可用库存预警数、返利余额预警数；点击卡片跳转到预置筛选列表。待办每项显示业务类型、单号、发起人、等待时长和处理按钮；超过 SLA 的项使用橙/红色时间标签但不得遮盖主要单号。

趋势图支持切换订单、销量、库存、返利和质量事件，时间粒度根据范围自动选择日/周/月。图表数据与数值表必须可互相切换，图表无数据时仍展示筛选上下文。接口失败区只对具备权限用户显示，点击跳转到已筛选的集成监控。

### 6.2 订单编辑与聚合详情

编辑页顶部固定展示订单类型、草稿状态和离开提醒；正文先呈现基本信息，随后是价格提示条、订单明细、附件、备注。价格提示条在每次试算后显示“已按合同价/特殊价计算”，若规则将过期或返利余额不足，则显示可点击风险提示。明细表支持新增、复制、删除、批量导入；任何价格字段仅只读展示，修改数量后自动重新计算。

详情页顶部展示单号、状态、金额、ERP 单号和主要动作。页签为概要、明细、履约、价格与返利、附件/GSP、发票、售后/维修、操作日志。概要页右侧为时间线；履约页以进度条表示已发/已收数量，点击执行行打开批号、序列号和扫码明细。

### 6.3 库存与扫码页

库存查询页顶部显示组织、仓库和库存状态范围；主表可切换“汇总/明细”。明细模式必须可展开批号、序列号、包装层级和来源单据；临期或冻结状态有醒目标记并提供查看预警/投诉的链接。调整、移库、借货均从独立业务单入口创建，不在列表直接修改数量。

H5 扫码页顶部显示当前动作和目标仓库，中部为相机预览，底部显示最近扫描记录。扫描成功卡片展示产品、层级、数量、批号、状态和下一步“继续扫描/查看详情/确认收货”；失败卡片展示错误原因和手工输入入口。未提交的扫描集合显示数量和“未入账”黄标，退出时提示保存草稿或放弃。

### 6.4 质量投诉与 CAPA 页

质量列表采用风险优先排序：严重等级、是否超期、状态、更新时间。详情顶部红/橙风险条展示等级、剩余 SLA 和冻结状态；页签固定为事件、调查、CAPA、受影响流向、附件、日志。CAPA 表格支持新建、指派、完成和验证，但关闭投诉时必须展示未完成项检查结果，不能通过隐藏字段绕过。

### 6.5 接口监控与审计页

接口监控列表以状态、外部系统、对象、业务单号、尝试次数和最后更新时间为主列；失败消息可展开请求/响应摘要和错误轨迹。点击重放先弹出只读影响范围，再输入重放原因；提交成功仅表示已入队，最终结果由状态轮询或消息中心通知。

审计页不提供编辑和删除，筛选包含时间、操作者、对象、动作、结果、请求 ID。变更详情采用左右对比，敏感字段以掩码展示；导出审计日志时自动加时间范围、导出人和用途水印。

## 7. H5 专项规范

H5 底部导航最多 4 项：工作台、扫码作业、待办、我的；业务详情使用全屏页面而不是嵌套 Drawer。表单采用单列布局，选择器使用底部 Sheet，日期使用系统友好日期选择器；所有提交按钮固定在底部安全区上方。

弱网时允许保存订单/扫码/报台草稿到本地加密存储，但不得本地生成正式单号、库存余额或审批结果。恢复网络后按创建顺序显示待同步队列，用户可以逐条查看、删除草稿或重新同步；同步成功后获取服务器单号并清除本地敏感数据。

## 8. UI 验收清单

1. 每个新页面在 1440px、1024px、768px 和 375px 宽度下无重叠、无不可点击控件，关键操作可见。
2. 所有字段均使用中文标签、帮助说明和一致的必填/错误样式；关联字段不显示裸 ID。
3. 所有状态有文字、颜色和图标/形状中的至少两种表达；键盘 Tab 顺序和焦点样式正确。
4. 列表、表单、Drawer、确认框、空态、加载、错误、权限不足和网络失败均有一致的设计状态。
5. 高风险动作、敏感数据查看/导出、未保存离开、扫码未入账和接口重放均触发预期确认和审计记录。
