# DMS 整合用户故事与验收标准 v3.7

## 开发规格引用

本文件的验收场景须使用《04_开发规格_页面字段接口_v3.7.md》中定义的字段、权限、错误码、库存/返利记账及状态机作为断言依据。

## 使用说明

每一条故事均包含角色、目标、前置条件及可自动化验证的验收标准。优先级中 P0 为生产上线阻断项，P1 为核心行业闭环，P2 为管理完善项，P3 为可后续排期项。故事实现时必须同时交付页面、后端规则、数据权限、操作日志和测试用例。

## EPIC A：主数据、组织与授权

### US-A01 产品与包装层级维护（P1）

作为厂商渠道管理员，我希望维护产品层级、包装层级和追溯规则，以便交易和扫码过程使用统一、可验证的产品资料。

前置条件：管理员具有所属 BU/产品线的主数据维护权限；产品分类、单位、序列号规则已配置。

验收标准：

1. 新增 SKU 时必须填写编码、名称、产品线、分类、单位、批号/序列号管理方式、启用状态；编码在租户内不可重复。
2. 可为 SKU 配置运输包装、纸箱、彩盒、单品等包装层级，并定义父子数量关系；所有层级数量必须为正整数。
3. 可维护生产商/产地、生产日期/有效期要求、临期预警月数、GSP 资料要求和是否允许组套；修改后的规则只作用于新业务，历史单据保留当时快照。
4. 停用已被业务单据引用的产品时，系统提示引用数量并禁止直接删除；允许设置停用日期。
5. 创建、修改、导入、停用和导出产品资料均产生操作日志。

### US-A02 医院与产品线关系（P2）

作为销售人员，我希望维护医院可经营的产品线及责任岗位，以便下单、报台和销量上报自动校验。

验收标准：

1. 关系记录必须包含医院、产品线、生效/失效日期、允许销售状态和责任岗位；同一医院、产品线、重叠有效期不得重复。
2. 销售订单、销售出库和手术报台选择医院后，只展示生效且本人有权限的产品线和产品。
3. 对未建立或已过期关系的提交动作，系统明确提示医院、产品线和失效原因，且不创建库存或销量流水。
4. 关系的新增、变更、停用和导入必须可按医院、产品线、时间检索并导出。

### US-A03 区域月度快照（P2）

作为销售运营人员，我希望每月冻结区域、岗位、人员和医院归属，以便历史业绩不会因人员调整而改变。

验收标准：

1. 系统在每月最后一天按配置时区自动创建快照，并记录来源版本、生成时间、记录数和执行结果。
2. 管理员可对遗漏月份补建快照，但必须填写原因，且补建前后差异可比对。
3. 报表可切换“当前归属”和“按发生期快照归属”；选用后者时必须以业务日期所在月份快照计算。
4. 快照生成后不得直接编辑；若需修正，须创建修订版本并保留原版本。

### US-A04 多级经销商授权（P1）

作为渠道管理员，我希望给经销商配置到产品线、医院/区域和交易类型的授权，以便多层渠道交易受到前置控制。

验收标准：

1. 授权至少包含经销商、上级经销商（如有）、产品线/分类、医院/区域、交易类型、生效期和状态。
2. 订单、分销、销售到医院、移库、借货和退换货在保存草稿时提示风险，在提交时执行强校验。
3. 一级经销商查看下级数据时，只能看到自身授权链路及获授权字段；下级的用户、价格和敏感附件默认不可见。
4. 到期前按配置提醒，失效后禁止新建交易，已完成单据仍可查询。

## EPIC B：价格、返利与订单

### US-B01 价格与折扣计算（P0）

作为经销商下单员，我希望系统在订单行展示可追溯的价格计算结果，以便确认成交价准确且符合政策。

验收标准：

1. 选定产品、经销商、医院和订单日期后，系统按特殊价、合同价、经销商价、全局价的优先级取价。
2. 每个订单行展示基础价、折扣、返利分摊、税额、最终单价和规则名称；无匹配价格时禁止提交。
3. 服务端重新计算所有金额，不信任前端传入金额；四舍五入规则按币种配置且在订单快照中保存。
4. 价格规则变更不回写已提交订单；复制订单时重新取价并提示差异。

### US-B02 返利池预占与核销（P1）

作为商务人员，我希望订单使用返利时自动预占余额并在交易结束后核销，以便避免超额使用和人工对账。

验收标准：

1. 返利池按经销商、BU、产品线、规则和期间维护余额，页面可查看期初、增加、占用、核销、释放和可用量。
2. 提交订单时系统以事务方式校验可用余额并预占；并发提交不会使可用余额为负。
3. 拒绝、撤销、过期或未生效的订单释放预占；完成且符合政策的订单转为核销；冲红按反向金额处理。
4. 管理员手工调整必须提交双人审批，调整前后余额、依据附件和审批意见均可审计。

### US-B03 特殊价订单审批（P1）

作为销售人员，我希望为特定客户申请特殊价格，以便处理招标、战略客户或临时市场机会。

验收标准：

1. 申请必须填写产品、数量、医院、标准价、申请价、差额原因、有效期和附件；申请价低于最低成交价时标记高风险。
2. 系统按差额比例、订单金额和产品线选择审批流；审批人可通过、拒绝或退回并必须填写意见。
3. 通过后生成不可手改的特殊价额度，额度只适用于指定对象、日期和累计数量；订单超量时无法使用。
4. 特殊价到期、撤销和使用完毕后自动失效，详情能追溯到申请、审批和使用订单。

### US-B04 组套设备订单（P1）

作为经销商下单员，我希望选择设备组套并让系统自动带出必配件，以便订单、库存和发货保持一致。

验收标准：

1. 选择组套父品后自动带出固定子件及数量，可选子件只能在允许集合内选择。
2. 删除固定子件、修改固定数量、添加不兼容子件时系统阻止并说明规则。
3. 审批、ERP 下发和发货记录都保留父子行关系；拆套操作须记录来源组套和操作人。
4. 缺少任一必配件或子件库存不足时，系统按配置阻断、提示可替代件或进入缺货审批。

### US-B05 维修订单闭环（P1）

作为售后人员，我希望建立维修订单并跟踪设备从返厂到返还或报废的状态，以便维修品不会混入可销售库存。

验收标准：

1. 维修单关联原销售单或设备序列号，录入故障描述、收件信息、服务级别、附件和预计完成时间。
2. 维修品入库后自动进入维修库存，不能被普通销售订单占用；状态至少包含待收件、在修、待返还、已返还、报废。
3. 替换出库、费用、返利调整或报废均须产生关联业务单据和审计记录。
4. 用户可按序列号看到完整维修历史、维修结果和附件。

### US-B06 订单聚合与常购模板（P2）

作为经销商管理员，我希望在一个页面查看订单全链路并复用常购清单，以便减少重复操作。

验收标准：

1. 订单详情页以页签展示主信息、产品行、审批、ERP、发货、收货、GSP、发票、售后和日志。
2. 常购模板保存产品、数量、地址和备注，但不保存过期价格、返利或授权；由模板创建订单必须重新校验。
3. 批量导入提供模板下载、预校验、错误行导出和异步任务进度；只有全部合法行才允许整批提交。
4. 订单状态变化、外部单号、发货进度和异常均在时间轴呈现。

## EPIC C：库存、扫码和质量

### US-C01 分次收货与库存状态（P0）

作为仓库操作员，我希望按实收数量和批次逐次确认收货，以便库存状态与实物同步。

验收标准：

1. 待收货单来自有效上游出库或 ERP 发货；无待收数量、已取消或无权限仓库时不能收货。
2. 分次收货后系统保存每次执行明细，包括批号、序列号、数量、日期、操作者、异常原因和附件。
3. 确认前库存为在途，确认后进入指定状态；取消或异常退回后按业务规则回退上游状态。
4. 收货数量超过待收量、序列号重复、有效期不合规或批次不匹配必须阻断。

### US-C02 多层包装扫码（P1）

作为仓库操作员，我希望扫描外箱或单品码完成收发货，以便减少逐件录入且保留包装关系。

验收标准：

1. 扫描任一层级码后显示产品、包装层级、父子码、状态、所在组织和可执行动作。
2. 扫描父码入/出库时按未拆分子码汇总数量；扫描子码时校验父码未出库、未报废且归属正确。
3. 聚合、解聚、部分拆箱和异常码处理均记录操作原因、前后关系和操作者。
4. 网络或相机权限失败时移动端给出明确恢复步骤，不能把未校验扫码结果当作成功收货。

### US-C03 产品流向追溯（P1）

作为质量人员，我希望按产品、批号、序列号或包装码查询全链路流向，以便处理召回和质量事件。

验收标准：

1. 时间轴按时间展示发货、收货、移库、借货、分销、销售、退货、维修和报废节点。
2. 每个节点显示来源/去向组织、仓库、数量、单据号、状态和操作时间，并可跳转详情。
3. 对质量事件关联批号，系统可列出受影响库存、在途、医院和销售记录，支持权限控制下的导出。
4. 导出字段包含追溯键、单据、数量、日期、组织和监管所需基本资料，且写入导出日志。

### US-C04 质量投诉与 CAPA（P1）

作为质量人员，我希望闭环处理质量投诉和纠正预防措施，以便管理风险与监管证据。

验收标准：

1. 投诉单必须关联产品和发生对象，可选关联批号/序列号、订单或销售单；支持照片、报告和通信附件。
2. 可配置严重等级、响应时限、责任部门和处理流程；超时自动预警给责任人及管理者。
3. 调查、根因、CAPA、复核和关闭均为独立记录，关闭前必须完成必填项和复核。
4. 已关闭投诉不可删除；重新开启需要记录原因，并保留全部版本。

## EPIC D：销售、发票、集成和治理

### US-D01 医院销量与发票资料（P0）

作为经销商操作员，我希望上报医院销量并上传发票/植入资料，以便销售、返利和合规数据完整。

验收标准：

1. 销售至医院时校验医院产品线关系、库存、批号/序列号和授权；植入场景校验必要的手术信息。
2. 支持扫码、单笔录入和 Excel 导入三种上报方式；导入前校验重复序列号、日期和必填字段。
3. 发票可批量导入并上传扫描件/PDF，可与一个或多个销售记录关联；强制产品线缺失发票或植入单时禁止提交。
4. 冲红或修正必须保留原单关联、原因、金额方向和后续处理记录。

### US-D02 ERP/MDM/EDI 生产接口（P0）

作为集成管理员，我希望监控并补偿生产接口，以便业务数据不会因外部失败丢失或重复。

验收标准：

1. 每个接口配置对象、方向、认证、幂等键、重试策略和告警负责人；密钥经加密保存并不在日志中泄露。
2. 订单、主数据、发货、库存等消息必须保存请求摘要、响应、状态、重试次数、关联单据和时间。
3. 短暂失败自动重试；超过阈值进入失败队列，管理员可在权限控制下查看、修正映射后重放。
4. 每日对账报告能列出双方数量、金额、状态差异及处理结果。

### US-D03 预警与系统使用报表（P2）

作为运营主管，我希望看到业务风险和系统使用情况，以便及时干预并提升采用率。

验收标准：

1. 可配置安全库存、临期、授权到期、返利不足、CAPA 超期、接口失败和盘点迟报阈值及接收角色。
2. 预警在工作台、站内消息和企微/飞书 Webhook 中展示；已读、忽略、处理和关闭均记录责任人与时间。
3. 系统使用报表按角色、组织、日期和功能统计登录数、活跃用户、操作次数、导入失败、待办时长和接口失败。
4. 所有报表支持筛选、导出、图表和下钻；导出按数据权限截断并写审计日志。

### US-D04 企业 UI 与移动作业体验（P1）

作为业务用户，我希望在 PC 和手机上获得一致、可理解的界面，以便快速完成高频工作而不误操作。

验收标准：

1. PC 列表使用统一标题、主操作、筛选、表格、分页结构；复杂编辑使用全屏 Drawer，关联字段显示编码和名称。
2. 表单有中文标签、必填提示、输入校验、保存草稿、离开未保存提醒和错误定位；危险操作均二次确认。
3. 状态使用“文字 + 颜色 + 图标/标签”呈现，满足足够对比度，不能只依赖颜色。
4. 移动端扫码、报台、订单追溯和工作台的触控目标足够大，处理相机拒绝、网络失败和重复提交。

## 全局完成定义（Definition of Done）

任一故事完成前，必须有字段字典、状态机、权限矩阵、接口契约、数据库迁移、页面实现、单元/接口/端到端测试、失败与回滚路径。测试报告需要同时覆盖正常、越权、重复提交、并发、超期、撤销、导入错误、接口重试和审计查询；仅演示正常页面流程不构成验收通过。
