# DMS 报表体系需求文档 v4.2

> 版本：v4.2（整合截至 2026-08-06 的全部报表反馈）
> 日期：2026-08-06
> 范围：PC（frontend-vue/）、移动端（frontend-vue/src/views/mobile/，同一构建产物）、后端（backend/）
> 测试环境：http://43.128.145.141
> 上游：v4.0 改造方案、v4.1 报表设计，以及本轮产品验收反馈（仪表盘、报表中心、经销商画像、测试数据、手机端）

---

## 0. 本轮核心结论

v4.1 已搭出报表骨架（报表中心门户 + 统一 ReportPage + 13 张报表 + 经销商画像 + 仪表盘可拖拽）。本轮验收聚焦在"能用、好看、数据真、可穿透、可导出"，明确以下原则，作为后续所有报表的验收基线：

1. 每张报表都要有查询条件和导出；库存类等少数报表可无时间范围。
2. 除库存类外，所有报表至少带一个时间范围，默认当前年（仪表盘默认本年）。
3. 报表要能穿透：产品 TOP 行穿透到该产品订单，经销商行穿透到该经销商订单/画像，订单行穿透到订单行与状态历史。
4. 展示就要展全：不追求报表数量多，但每张报表的列、KPI、图表必须信息完整、不空、不 undefined。
5. 测试数据必须真实、完整：合同要有合同主体、期限、金额、结算条款；返利/达成要有期间；库存要有产品名称；画像每个经销商都要有连续周期数据。
6. 仪表盘默认当年、带筛选、布局可自定义；首页至少嵌入一部分仪表盘。
7. PC 改动同步到手机端。

## 1. 全局交互规范（所有报表/仪表盘通用）

### 1.1 筛选区
- 每张报表顶部固定筛选条：时间范围（当日 / 近 7 天 / 近 30 天 / 近 90 天 / 本周 / 本月 / 本季 / 本年 / 不限 / 自定义）+ 业务筛选项 + 查询 / 重置 / 保存视图。
- 默认时间范围：经营类报表默认"本年"；库存类（库存周转、库存呆滞）默认"不限"；订单追溯默认"近 30 天"；应收/审批默认"近 90 天"。
- 筛选条件通过 from / to 透传给后端，穿透子表继承当前时间范围。
- 保存视图：把时间范围 + 筛选值写入 localStorage，下次进入自动恢复。

### 1.2 导出
- 每张报表提供"导出 xlsx"按钮，使用前端 xlsx 生成。
- 导出内容必须包含：报表名、生成时间、当前筛选条件、数据行数、KPI 摘要、明细数据。
- 明细按列定义的格式化后的值导出（金额带 ¥ 与千分位、数量千分位、百分比 x.x%、期间 YYYY-MM、日期 YYYY-MM-DD），不允许导出原始 undefined / 空键。
- 文件名：{报表名}_{YYYY-MM-DD}.xlsx。

### 1.3 穿透（Drill-down）
- 所有可穿透行鼠标悬停高亮、点击在行内展开子表（不跳页），子表标题注明"穿透数据"与条数，可收起。
- 穿透子表继承父表时间范围。
- 穿透层级：
  - 产品类 → 该产品销售明细（订单号、经销商、数量、单价、金额、日期）。
  - 经销商类 → 该经销商订单明细，或跳转经销商画像。
  - 订单类 → 订单行 + 状态历史（复合返回 lines + history，分区展示）。
  - 医院/终端 → 该医院手术报台明细（可继续进报台详情）。
- 无明细时显示"该维度下暂无明细"，不允许空白。

### 1.4 图表
- 报表页支持三种视图：表格 / 图表 / 图表+表格（默认图表+表格）。
- 图表类型由报表 metadata 声明：bar / line / pie / stackBar。
- 切到图表视图、从隐藏切回时必须正确 resize，禁止空白 canvas。
- 图表与表格共享同一份数据与筛选。

### 1.5 空态与错误
- 无数据显示空态，并提示"暂无数据，请调整筛选条件"。
- 接口失败要提示错误，表格清空但不白屏。
- 任何位置禁止出现 undefined / null / NaN。

## 2. 仪表盘

### 2.1 筛选（必须）
- 时间范围：当日 / 近 7 天 / 近 30 天 / 本月 / 本季 / 本年（默认）/ 自定义日期区间。
- 经销商：远程搜索下拉，可清空（全部）。
- 订单状态：草稿 / 已审核 / 出库中 / 已完成。
- 订单类型：常规 / 加急。
- 所有图表与 KPI 随筛选联动刷新。

### 2.2 自定义布局（必须）
- "编辑布局"模式下：
  - 图表卡片可拖拽排序（vuedraggable，手柄拖拽）。
  - 可隐藏单个图表区块，隐藏后在"已隐藏区块"一键恢复。
  - "重置布局"恢复默认顺序与显示。
- 布局（顺序 + 隐藏状态）按用户保存在 localStorage。

### 2.3 KPI 区（8 项）
总销售额、订单数、活跃经销商、产品数、合格库存、待检库存、不合格库存、报台数。

### 2.4 图表区（6 块，默认顺序）
1. 销售趋势（折线，月）
2. 库存三态（饼：合格 / 待检 / 不合格）
3. 销售 TOP 经销商（柱状）
4. 订单漏斗（草稿→审核→出库→完成）
5. 医院手术 TOP（柱状）
6. 近 7 日活跃

要求：6 个图表均必须有数据、正常渲染，不允许空图。

### 2.5 首页嵌入
- 工作台首页 /home 必须嵌入"仪表盘速览"：
  - 顶部时间范围切换（当日 / 本月 / 本季 / 本年默认）+ 刷新 + "查看完整仪表盘"入口。
  - KPI 行 + 销售趋势 + 订单漏斗 + 经销商 TOP5 + 本月速览。
- 首页与 /dashboard 不重复挂载同一组件实例。

### 3.1 待补强项
- 销售业绩排行不能太空：KPI 至少含总销售额、订单数、活跃经销商；表格列要全（排名、经销商、级别、区域、销售额、订单数、同比/环比、目标达成率）；图表 TOP20。
- 合同 / 授权 / 借货三张报表目前列偏少、无穿透，后续需补：
  - 合同台账：合同编号、名称、甲方、乙方、类型、期限(起–止)、天数、目标额、签约额、返利率、结算周期、状态、负责人。
  - 支持按状态 / 经销商 / 期限筛选，并从合同行穿透到该合同相关订单或经销商画像。
- 所有报表的 KPI 卡不允许为 0 且无说明；测试数据要让 KPI、图表、表格都有内容。

## 4. 经销商 360 画像（本轮重点重做）

路由：/dealers/profile（列表）→ /dealers/:id/profile（画像）。
左侧为经销商基本信息卡片（编码、名称、等级、法人、税号、GSP 状态/有效期、联系人/电话/邮箱）。左侧已展示基本信息，右侧不再重复文字说明，直接展示 KPI 与各业务页签。

### 4.1 KPI 概览页签
KPI 必须是"目标 vs 结果"的对比，而不是只给一个结果数字：

- 本月销售目标达成：实际额 / 目标额 / 差额 / 达成率进度条。
- 年累计目标达成：YTD 实际 / 年目标 / 剩余 / 达成率进度条。
- 环比上月：环比百分比 + 上月与本月金额。
- 小卡：本月订单数(YTD)、YTD 净返利、YTD 退货(退货率)、库存数量(金额)、库存 SKU(合格率)、有效合同(90 天到期数)。
- 月度目标达成趋势图：目标(虚线) / 实际(柱) / 达成率(右轴折线)。

图表要求：首次进入必须渲染；切到其他页签再切回必须重新 resize 渲染，禁止空白；横轴期间禁止出现 undefined。

### 4.2 月度达成页签
列：期间、目标额、实际额、达成率、差额、环比、档位、毛返利、净返利。
- 期间必须有值（YYYY-MM），禁止空期间。
- 每个经销商至少有连续 24 个月数据（2025-01 ~ 2026-12）。

### 4.3 返利明细页签
列：期间、销售目标、实际销售、达成率、档位、毛返利、扣减、净返利、结算状态。
- 期间、金额、状态都必须有值；扣减原因要真实（返利扣减 / 价保 / 窜货 / 促销补差 / 考核扣减）。

### 4.4 合同列表页签（合同必须专门做）
合同是正式业务单据，必须信息完整，列至少包含：
- 合同编号、合同名称、类型、甲方（厂商主体）、乙方（经销商主体）。
- 期限：起始日期 至 截止日期 + 天数。
- 目标额、签约额、返利率。
- 结算周期、付款条款、交货条款、业务范围。
- 状态（生效/到期/待签/终止）、负责人、电话。
- 测试数据要求：每个经销商至少 5 份合同，覆盖经销协议 / 授权 / 供货 / 推广 / 服务等类型，主体、期限、条款齐全且合理。

### 4.5 库存明细页签
列：产品编码、产品名称、规格、分类、仓库、批号、数量(单位)、单价、金额、库存状态、生产日期/效期。
- 产品名称禁止为空（INNER 产品维表或 COALESCE 兜底）。
- 每个经销商都要有库存数据，含合格 / 待检 / 不合格等状态批次。

## 5. 测试数据要求

1. 真实、不一眼假：金额、数量、价格符合医疗器械经销业务量级；名称用真实品类（支架、弹簧圈、导管、止血纱、透明质酸钠等），不要让"演示产品-xx"充斥主报表。
2. 完整性：每条合同有甲乙方 + 期限 + 金额 + 条款；每条返利/达成有期间；每条库存有产品名；每张订单至少有订单行 + 状态历史。
3. 覆盖度：
   - 全部经销商（51 家）都有 24 个月达成/返利数据。
   - 每家经销商至少 5 份合同、多批次库存。
   - 仪表盘 6 图、首页图表、报表 TOP 排行都有数据。
4. 通过迁移脚本维护（Flyway），幂等可重放：
   - V54：合同画像字段扩充。
   - V55：真实演示画像数据（合同主体/期限/条款、返利、库存、产品中文名）。
   - V57：补齐缺失周期与缺失库存。
   - V58：修复无订单行的订单。
5. 数据生成后必须自测：KPI、图表、表格、穿透逐项点开验证，不能等用户发现空数据。

## 6. 手机端同步

PC 端报表/仪表盘改动必须同步到手机端（同一 frontend-vue 构建，移动端路由 /mobile/*）：
- /mobile/home：首页仪表盘速览，无 undefined，图表正常。
- /mobile/dashboard：我的业绩（KPI + 趋势 + TOP 经销商/订单状态）。
- 手机端复用同一套后端 /api/dashboard/* 与报表接口。
- 手机端不要求完整 13 张报表，但首页与业绩页的数据正确性、空态、字段显示必须随 PC 一并验证。

## 7. 技术实现与文件清单

### 7.1 前端
- frontend-vue/src/views/Dashboard.vue：完整仪表盘（筛选 + 拖拽布局 + 6 图 8 KPI，默认本年）。
- frontend-vue/src/views/Home.vue：首页嵌入仪表盘速览。

- frontend-vue/src/views/DealerProfile.vue + DealerProfileList.vue：经销商 360 画像。
- frontend-vue/src/views/mobile/：MHome / MDashboard 等手机端页面。

### 7.2 后端
- BusinessReportController：/api/reports/*（sales-ranking、product-top10、inventory-turnover、surgery-stats、receivables、order-trace、inventory-aging、order-approval-stats、product-sales-detail、dealer-orders、hospital-surgery、order-detail-child）。
- DashboardController：/api/dashboard/*（kpi、sales-trend、inventory-pie、order-funnel、top-dealers、top-hospitals、activity-7d）。
- DealerProfileController + DealerProfileService：/api/dealer-profile/{id}/{tab}（basic/kpi/achievement/rebate/contracts/inventory）。
- ReportController + ReportService：/api/reports/{type}/query（sales/contract/authorization/loan/rebate 等通用聚合）。

### 7.3 部署
- 后端：Maven 打包 dms-backend.jar，上传至 dms-test-backend 容器并重启，Flyway 自动执行迁移。
- 前端：npm run build 后 dist.zip 上传至 dms-test-frontend 容器（nginx /usr/share/nginx/html），PC 与手机端同一次构建同步。
- 后端启动约 70 秒，需等待 Started DmsApplication 后再回归。

### A.4 v4.0 风险与对策（保留参考）

| 风险 | 影响 | 对策 |
