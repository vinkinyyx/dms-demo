# DMS v4.3.0 需求规格

> 版本：v4.3.0（MINOR）
> 日期：2026-08-27
> 基线：v4.2.9
> 设计：`docs/02_设计/v4.3.0/总体设计.md`、`docs/02_设计/v4.3.0/订单折扣与促销规则说明书.md`
> 范围：多出库单销退、客户多联系人/多地址、订单计价体系升级、促销扩展、客户代金券、产品/客户全局折扣、折扣加价方向、客户账号与自助注册、移动端客户自助下单。

---

## 1. 背景

v4.2.x 期间业务侧提出一批围绕「销售订单计价」与「客户自主经营」的需求：销退只能按单张出库单退货、客户主数据只有单一联系人/地址、折扣只能减不能加、没有代金券与全局折扣、客户无法自主下单。v4.3.0 将这些需求统一为正式版本特性，并沉淀唯一计价口径。

---

## 2. 需求清单

### R1. 一张销退单关联同一经销商多张销售出库单

- 销退订单可一次导入/关联同一经销商的多张销售出库单。
- 可退量按来源出库单行维度锁定（已退 + 在途 + 本次），跨出库单不可挪用。
- 出库单必须属于同一经销商，混选时拦截并说明原因。
- 审批通过后按来源行分别回写库存/可退量；退货价按 EA 快照计算。
- 销退单列表统一展示新 RMA 单与历史红字单（unified），详情可正确打开两类单据。

### R2. 客户主数据：多联系人、多收货地址

- 一个客户（经销商）维护多个联系人（dealer_contacts），支持默认联系人。
- 一个客户维护多个收货地址（地址名、收货人、电话、省市区、详细地址、默认标记）。
- 销售订单（PC + H5）下单时选择该客户下的不同送货地址，并写地址快照。
- 历史 dealers 单联系人字段保留兼容，回填一条默认联系人。

### R3. 整单一口价 / 整单 0 金额 / 行 0 金额

- 整单一口价：直接指定整单成交价，产品按基础原价，差额按折后行金额占比摊到各行与 EA。
- 整单 0 金额：所有行金额为 0。
- 行 0 金额：NORMAL 模式下将指定行金额设为 0；该行权重 0，低开/高开均不向其分摊。
- 一口价、整单 0、代金券三者互斥；任一折扣存在时三者均不可用。

### R4. 促销扩展：满 N 件打折 / 满 N 件减 / 满赠

- 新增促销模式：SKU 或品类满 N 件享折扣（百分比/固定单价）、满 N 件减固定金额；满赠保留。
- 同一 SKU 在同一有效时间段只能命中一种促销，配置冲突时拦截并列清单。
- 「满 N 件打折」仅作用于命中行，命中行不允许再用行手动折扣。
- 处于促销中的 SKU 不允许手动设为 0 金额。
- 同 SKU 拆多行提交时拦截，要求合并为一行。
- 订单上方用文本列举命中的促销条件；命中落库 order_promotion_hits。
- 退货跌破门槛：赠品可按 0 金额退回，已享优惠从退款相应扣减。
- 本期不做满额折、阶梯增量、套餐、秒杀、首单价等其他促销。

### R5. 客户级别代金券（含有效期）

- 厂家统一发放代金券，可按客户/范围批量生成，含面值、最低消费、适用范围（全部/指定 SKU/品类）、有效期。
- 销售或客户下单时可使用，一单限用一张。
- 代金券在整单层抵扣，绝不摊入任何行单价（防退货套现）。
- 面值大于商品原价合计时拦截；过期/停用/他人券不可用。
- 代金券与一口价、整单 0 两两互斥，且与所有折扣互斥；用券时产品按基础原价。
- 整单未出库作废返还券；部分退货/已出库不退券。

### R6. 产品全局折扣

- 可对产品设置全局折扣比例（只减），客户下单取客户价后直接乘以折扣。
- 提供独立 PC 维护页面，按时间段生效，历史留痕；同产品时间段不可重叠。
- 未生效/过期不应用。

### R7. 客户全局折扣

- 可对客户设置全局折扣比例（只减），下单时在最终价格上打折，每一行都需打折。
- 提供独立 PC 维护页面，按时间段生效，历史留痕；同客户时间段不可重叠。
- 按各行折后金额占比摊回每行；摊后任一行 < 0 拦截。

### R8. 折扣加价方向（高开）

- 行折扣与整单折扣均支持「向下减」与「向上加」，百分比与金额两种形式都要支持。
- 加价（高开）无上限，不需要记录原因。
- 自动折扣（产品/客户/促销）只减；加价仅用于手动行/整单折扣。
- 所有金额、折扣按含税处理。

### R9. 客户账号、自助注册与移动端自助下单

- 厂家端除销售人员下单外，为客户开通账号：客户只能为自己下单/查看自己的数据。
- 客户自助注册（PC + 独立 H5 注册页，未来作为小程序链接）：填写基本信息、上传附件，本质是创建客户主数据申请。
- 注册提交后进入待审核；厂家审核通过自动创建客户账号 + 客户主数据（dealer + 联系人 + 地址），登录名为手机号。
- 客户权限：申请/查看销售订单、查看合同、查看自己的报表、查看自己的授权、申请/查看自己的手术报台。
- 数据范围后端强制：客户只能访问自己 dealer_id 的数据，越权返回 403/空。
- H5 客户自助下单全流程：选地址、选品、自动折扣、行/整单折扣、一口价、代金券选择、促销文案、金额明细实时刷新。
- 主数据维护、促销/折扣配置等管理功能只放 PC 端。

## 3. 全局计价口径（所有销售订单一致）

- 全部为含税金额；数量为正整数（销售订单 qty、BOM 子件用量均改为整型且 > 0）。
- 单价/金额保留 2 位小数，中间过程高精度，尾差最后统一吸收到金额最大行。
- 行价格优先顺序：1) 基础客户价（合同价 > 客户价 > 全局价）→ 2) 产品全局折扣 → 3) 产品促销折扣 → 4) 行手动折扣，汇总出行总价。
- 整单折扣优先顺序：1) 客户全局折扣 → 2) 整单手动折扣。
- 大原则：先行后整单；整单增减按各行折后总价比例分摊到行，再平摊到每个 EA。
- 0 金额行/赠品行权重为 0：不被产品/促销/整单折扣影响；高开（ADD）也不向权重 0 行分摊。
- 任一行金额、整单金额均不得小于 0，违反即拦截。
- 提交时后端重算落库，不信任前端金额；任何校验拦截都必须给出具体原因（含行号/SKU/原因）。
- 外键字段展示业务名称，不暴露原始 id/枚举码。

详细规则与 A–L 折扣组合测试场景见《订单折扣与促销规则说明书.md》。

---

## 4. 不做什么

- 不做 R4 清单之外的促销玩法（满额折、阶梯、套餐、秒杀、首单价等）。
- 代金券不接真实支付、不找零。
- 采购、库存盘点等非销售模块数量精度不在本期。

---

## 5. 验收标准

- R1–R9 逐条功能可用，PC/Admin/H5 三端无白屏、无 Console 红错、无 5xx。
- 计价 A–L 场景集全部通过（前端真实点击 + 后端 API + DB 回读 + 业务规则 + 异常路径）。
- 全量冒烟（PC + Admin + Mobile）通过；F1–F5 核心流回归通过。
- 客户账号数据隔离验证通过（越权 403/空）。
- 版本号升至 4.3.0，CHANGELOG、设计文档、需求文档、测试报告齐全。
