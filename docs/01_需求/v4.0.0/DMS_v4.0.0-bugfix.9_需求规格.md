# DMS v4.0.0-bugfix.9 需求规格

**版本**: v4.0.0-bugfix.9
**日期**: 2026-08-21
**测试环境**: http://43.128.145.141

## 背景
bugfix.8 上线促销赠品后发现：在编辑页修改产品数量/折扣时，前端会反复触发促销试算，且上一轮赠品行未被识别，导致赠品被无限累加。同时折扣分摊采用“逐段在剩余可分摊余额上再分摊”的方式，与业务要求的“按各行标准金额占比一次性分摊总折扣”不一致。本次修正促销计算时机、幂等性与分摊算法。

## 1. 促销计算时机
1. 编辑页数量、产品、行折扣、整单折扣发生变化时，只实时刷新价格与折扣金额的“价格预览”，**不**生成赠品、不应用满减促销。
2. 订单明细卡片头部新增“刷新赠品及价格”按钮（刷新图标）。点击后按当前下单产品与数量重新计算赠品与满减。
3. 点击“保存草稿”或“提交”时，系统在提交前自动执行一次与按钮相同的刷新，再构建提交数据。
4. 重复点击刷新按钮必须幂等：同一数量下赠品行数与数量不发生累加。

## 2. 赠品行规则
1. 赠品直接显示在明细行内，产品与数量锁定，不可编辑、不可删除，单价/金额为 0。
2. 买赠阈值按整数倍向下取整：每满 N 送 M 时，赠品数量 = floor(命中数量 / N) × M；一次性买赠命中即送一份。
3. 赠品不参与任何金额分摊。

## 3. 折扣分摊算法（核心）
1. 仅对计费行分摊：非赠品、非 BOM 母件（普通行与 BOM 子件）。
2. 总折扣 = 各行行折扣之和 + 整单折扣 + 促销满减金额。
3. 每个计费行分摊额 = 总折扣 × (该行标准金额 / 所有计费行标准金额合计)。
4. 分摊额按 2 位小数四舍五入（HALF_UP），尾差调整到标准金额最大的行；分摊不得使行最终金额为负。
5. 行最终金额 = 标准金额 − 分摊额；出库单价 = 行最终金额 / 数量。
6. 示例：两行标准金额分别为 1000、500，总折扣 300，则第一行分摊 200、最终 800（出库 200/个），第二行分摊 100、最终 400（出库 50/个）。

## 4. 命中提示
1. 刷新赠品及价格后，在订单基本信息下方用提示条展示命中信息。
2. 买赠：本单因满足【规则名称】，赠送 产品编码 名称 ×数量。
3. 满减：本单因满足【规则名称】，整单减免 ¥金额。
4. 未命中任何促销时不展示提示条。

## 5. 范围与不做
1. 不改动账号、权限、审批流等配置数据。
2. 不改动促销规则的维护页面与数据结构。
3. 复用现有促销类型 GIFT / MOQ / FULL_REDUCTION。
