# DMS v4.1.0 需求规格

> 版本：v4.1.0
> 日期：2026-08-22
> 基线：v4.0.3
> 范围：BOM 价格双轨、行折扣优先级、促销计价口径统一、产品价格维护增强

---

## 1. 背景

v4.0.0 之后连续 10 个 bugfix 版本暴露了以下核心问题：

1. BOM 母件被当作实物参与出库与计价，子件价格与单品价格混用。
2. 同一 SKU 作为 BOM 子件和作为独立单品时价格无法分别维护。
3. 行折扣、整单折扣、促销满减的分摊顺序不符合财务口径。
4. 产品价格维护保存 BOM 母件价后，母件记录被子件记录覆盖。
5. 促销赠品在每次数量变动时无限累加。

v4.1.0 将以上 bugfix 期间的需求正式沉淀为版本特性。

---

## 2. 需求清单

### R1. BOM 母件零金额、不计总价、不参与折扣分摊

- BOM 母件行展示子件标准价汇总（只读），但母件自身单价、标准金额、最终金额均为 0。
- 母件不参与订单总价汇总，不参与整单折扣与促销满减分摊。
- 母件不能做行折扣。
- BOM 母件不参与销售出库（无实物），审批后可一键全部出库。

### R2. BOM 子件可单独行折扣，行折扣优先级最高

- BOM 子件行可独立设置行折扣（比例/金额）。
- 计价顺序：先算行折扣 → 得到「行后金额」→ 再按「行后金额占比」平摊整单折扣和促销满减。
- 最终出库单价 = 最终金额 / 下单数量。
- 示例：两行标准金额 1000/500，第一行 20% 行折扣（减 200），整单减 270；行后金额 800/500；按 800:500 分摊 → 第一行减 166.15 最终 633.85，第二行减 103.85 最终 396.15。

### R3. BOM 子件价与单品价双轨维护

- 产品价格新增「价格用途」：单品价（STANDALONE）、BOM 母件价（BOM_HEADER）、BOM 子件价（BOM_COMPONENT）。
- 维护 BOM 母件销售价时，录入每个子件在该经销商下的价格；系统保存 1 条 BOM_HEADER 0 元头记录 + N 条 BOM_COMPONENT 子件记录。
- 同一 SKU 可同时维护单品价和作为某 BOM 子件的价格，两套记录通过 price_context + bom_parent_product_id 隔离。
- 价格列表默认隐藏 BOM_COMPONENT 子件行（避免噪音），通过「价格用途」筛选和「查看 BOM 子件价」查看。
- BOM 母件价生效/失效时，级联生效/失效其下所有 BOM_COMPONENT 子件价。
- 列表新增「价格类型」「经销商」过滤条件；只读页显示 SKU 编码+名称和经销商名称，不显示裸 ID。

### R4. BOM 子件下单不回退单品价

- 销售订单选择 BOM 母件展开子件时，子件价格只取该经销商该 BOM 上下文的 BOM_COMPONENT 价。
- 如果该 BOM 在该经销商下没有维护子件价，子件价格为 0，不回退到单品价。
- 单品下单时取 STANDALONE 价（经销商专属 → GLOBAL(0) → GLOBAL(null)）。

### R5. 促销赠品手动刷新、幂等、锁定

- 赠品不在每次数量/产品变动时自动累加。
- 明细区新增「刷新赠品及价格」按钮，点击后统计当前下单产品及数量是否满足满赠/满减规则。
- 满足满赠则在明细内添加赠品行（价格 0，产品/数量不可编辑、不可删除）；满足满减则在总价中扣减。
- 保存草稿、提交前自动触发一次刷新，保证落库数据与页面一致。
- 刷新幂等：同一赠品 SKU 按规则聚合数量，重复点击不产生重复行。
- 页面顶部显示命中文案：「本单因满足【规则名】赠送 X 物料 N 个」或「整单减免 ¥X」。

### R6. 促销规则修复

- 满减（FULL_REDUCTION）选择产品后保存不再误报「请选择目标 SKU 或产品层次」。
- BigDecimal 金额字段不再被 instanceof Number 误判。
- targetType=LINE（产品层次）时不再强制要求选择 SKU。
- 列表页「启用/停用」按钮正常调用后端正接口并回读状态。
- 只读页明细中命中 SKU、赠品 SKU、赠送周期显示编码+名称/中文标签，不显示裸 ID。

### R7. 销售订单布局

- 新增/编辑页经销商字段加宽（md=16），订单类型和期望日期各 md=4，保持同一行。
- 缺价校验错误信息显示产品编码+名称，不显示 ID。

---

## 3. 不做什么

- 不做 BOM 母件价格的独立金额维护（母件金额始终为 0，仅展示子件汇总）。
- 不改变采购价的计价逻辑（采购价仍为单品维度）。
- 不调整审批流引擎本身。

---

## 4. 验收标准

1. BOM 母件订单提交后总价只含子件，审批后一键出库状态为「已完成」。
2. BOM 子件行折扣 + 整单折扣 + 促销满减按本文件 R2 顺序计算，误差不超过 0.01。
3. 同一 SKU 在同一经销商下能同时查到单品价和 BOM 子件价两条记录。
4. BOM 母件价失效后，其下子件价全部失效。
5. 满减规则选择产品后保存成功；满赠规则刷新后赠品正确出现在明细内。
6. 产品价格列表和只读页不出现裸 ID。
7. 销售订单经销商字段完整显示经销商名称不截断。

## v4.1.1 补充（2026-08-22）

- 销退只读页金额必须以持久化数据为准：明细行总价取 `order_lines.final_amount`，汇总恒等于表头 `orders.final_amount`；不允许用「当前剩余可退数」裁剪已审批保存的退货数量。
- 促销赠品（`is_gift=true`）与 BOM 母件（`line_level='PARENT'`）无实物、零金额，不得进入销售出库草稿，也不得作为销退可退明细。
- 销退明细需展示来源定位：出库子单行号（发货行）与销售订单行号（订单行），便于核对退货来源和原始出库价。

## 附录：v4.1.2 需求变更（2026-08-22）

1. **促销规则保存校验**：满A减钱（FULL_REDUCTION）只需维护命中对象与减免金额，不应再要求赠品SKU/赠品数量；满赠（GIFT）才校验赠品。命中对象统一为「选择SKU」或「选择产品层次」，二者必填其一。
2. **赠送周期**：仅满赠适用。`仅赠一次(ONCE)` 达到门槛A赠1份；`每满N循环(EVERY_N)` 达到门槛A赠1份，之后每再满N份加赠1份（`1+floor((hit-A)/everyN)`）。
3. **计价可用**：演示数据重置后下单/促销计价必须正常，不得因 price_scope 旧值（SALES vs SALE）报「未维护价格」。

---

## 附录：v4.1.3 补充需求（2026-08-22）

1. **出库单必须体现出库明细**：销售订单自动/模拟生成的销售出库单，详情页必须展示「发货子单」明细，包含行号、批号、序列号、出库单价；销退选择出库单时据此带出行号与原始出库价。
2. **BOM 母件与促销赠品不出库**：BOM 母件无实物、促销赠品 0 元，均不参与销售出库与销退可退明细。
3. **单据新建必须全新空白**：销退等单据在提交/查看后点「新建」，表单必须完全重置，不得残留上一单的经销商、原发货单、明细等。
4. **跨页不得残留异步请求**：离开单据编辑页后，不得继续请求旧单据数据，不得弹出与当前页无关的业务错误提示。
5. **满A减钱支持减免周期**：满减规则可选择「仅一次」或「每满N循环」。仅一次达门槛减一次；每满N循环在达门槛后每满 N 再减一次，循环减免封顶不超过命中行折后金额。
