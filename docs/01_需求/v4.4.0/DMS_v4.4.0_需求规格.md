# DMS v4.4.0 / v4.4.1 需求规格

> 版本：v4.4.1（PATCH，2026-08-28；v4.4.0 MINOR 同日交付）
> 日期：2026-08-28
> 基线：v4.3.2
> 设计：`docs/02_设计/v4.4.0/总体设计.md`
> 测试：`docs/04_测试/v4.4.0/测试报告_v4.4.0_20260828.md`
> 范围：寄售（代销）业务闭环、订单类型扩展（补货/开票/样品/定制）、经销商资信与账期、进销存租户开关精细化；v4.4.1 增补寄售补货红冲（R8）与开票拣选交互细化（R9），并修复联调 BUG-01~04。

---

## 1. 背景

业务侧从「先发货铺货、后按实际使用开票」的经销模式出发，提出寄售（代销）库存的管理诉求：厂家先以 0 金额向经销商补货，货到经销商处即构成「经销商寄售库存」；经销商实际消耗后再开具开票订单结算。与此同时，需要样品、定制等更多订单类型，以及对经销商信用额度、账期、寄售额度的统一管控。v4.3.x 反馈的进销存开关也需要细化为「仅约束厂家用户、不影响经销商自助库存查看」。

---

## 2. 需求清单

### R1. 订单类型扩展

销售订单在原「销售订单/补货订单」基础上扩展为：

| 类型 | 编码 | 说明 |
|------|------|------|
| 销售订单 | SALES | 需求与逻辑不变（默认）。 |
| 补货订单 | REPLENISHMENT | 经销商先向厂家进货（寄售铺货）。所有产品为 **0 金额**；不可用任何折扣、代金券、一口价；不参与满减/满赠等促销。发货后厂家库存扣减（沿用销售出库），同时计入该经销商寄售库存。 |
| 开票订单 | INVOICE | 针对经销商**已有寄售库存**开票。按合同价/客户价/全局折扣重新计价；可使用产品促销价、经销商折扣、整单/行折扣等**部分金额类**折扣；**不可用代金券、一口价、0 金额**；**不参与满减/满赠**。可选择结算终端（终端医院）。 |
| 样品订单 | SAMPLE | 只能下 **一个单品**；0 金额；不可用折扣/促销；**必填申请样品原因**。 |
| 定制订单 | CUSTOM | 保留选项，暂按普通订单逻辑，后续细化。 |

### R2. 经销商寄售库存开关与额度

- 经销商主数据维护「是否开启寄售库存」开关（`consignment_enabled`）。
- 仅当开关开启时，该经销商才能下「补货订单」与「开票订单」；未开启时下单被拦截并提示先在经销商主数据中开启。
- 经销商主数据增加：寄售额度（`consignment_limit`）、信用额度（`credit_limit`）、账期（`payment_days`）、结算方式、信用等级。

### R3. 寄售库存台账与流水

- 补货订单**发货后**：厂家库存扣减（与销售出库一致），同时将该批货计入经销商寄售台账。
- 台账维度：**经销商 + 产品 SKU + 批号 + 序列号**，含在库量、锁定量、标准单价。
- 流水（consignment_stock_movements）记录：补货入库（REPLENISH_IN）、开票预占（INVOICE_LOCK）、开票实扣（INVOICE_DEDUCT）、开票释放（INVOICE_RELEASE）。
- 寄售金额统一按**产品标准价**汇总，得到每个经销商的当前寄售金额（`consignment_used`）。

### R4. 开票订单库存选择与生命周期

- 开票订单**必须**从该经销商自己的寄售库存中选择产品；选择器按 产品+批号+序列号 维度展示可用量（在库-已锁定）、标准单价、仓库等，支持关键字检索、勾选、填写本次开票数量，加入明细后整单替换。
- 开票数量不得超过该维度可用量；不在该经销商寄售库存中的产品（或批号/序列号不匹配）被拒绝，错误信息带产品编码+名称。
- 生命周期：
  - **提交**：预占寄售库存（locked+）。若有审批流，进入审批中。
  - **审批通过**：正式扣减寄售库存（on_hand-，locked-）。
  - **审批拒绝 / 退回 / 撤回**：释放预占（locked-，on_hand 不变）。
- 开票订单明细携带批号/序列号落库（order_lines.batch_no/serial_no），保证与台账维度一致。

### R5. 经销商资信与账期

- 新增「经销商资信与账期」模块与页面，展示每个经销商的信用额度、信用占用、账期、结算方式、信用等级、寄售额度、寄售占用。
- 超额 / 超账期时**触发审批**（不硬拦截），由审批流决定放行。
- 信用额度为独立维护字段；寄售额度仅对开启寄售的经销商维护；寄售金额按产品标准价汇总。

### R6. 进销存租户开关精细化

- 平台后台可对一个租户开启/关闭「进销存管理」功能（tenants.modules_enabled.inventoryEnabled）。
- 关闭后：
  - **厂家用户**：采购订单、采退订单、收货入库、库存管理、库存调整、库存移动、盘点、效期、序列号追溯等菜单与对应接口**不可用**（菜单隐藏、接口拒绝并提示未启用）。
  - **销售订单、销退订单、销售出库、寄售库存**对厂家用户**始终保留**。
  - **经销商用户**（绑定 dealer_id 的客户账号）：库存相关菜单与接口**仍可使用**，不受该开关影响。

### R7. v4.3.x 反馈问题修复（随版本交付）

- R7-1 销退订单（RMA）提交后正确进入审批流（待审批/审批中状态一致，审批中心可见待办；驳回/退回/撤回释放可退量锁定）。
- R7-2 销退新建页新增「退货类型」筛选（有价产品退货 / 0 金额产品退货）联动：0 金额退货时退货原因不可选「常规退货」，选出库单仅带出对应金额类型产品；默认有价产品退货。
- R7-3 销售订单新建/只读页布局：第一行「经销商 + 订单类型」，第二行「送货地址 + 期望日期」；送货地址必填；下单日期默认当天。
- R7-4 销退单选择出库单支持点击整行选中；销退审批页展示主要退货信息（退什么货、原因、数量金额、关联出库单）。
- R7-5 layer1 历史遗留 `????` 乱码段落重写为中文。

### R8. 寄售补货红冲（红字补货订单，v4.4.1 新增）

- 补货铺货后如发生撤回/错补，需要对补货订单做**红冲**：支持创建红字补货订单（orderType=REPLENISHMENT + isRed=true，单号前缀 SOR），全行为 0 金额，规则同补货单。
- 红字补货单经提交、审批、ERP 红字出库回调后，生成红字销售出库（sales_outs / sales_out_lines 带红冲标记）。
- 红冲生效后**扣减该经销商寄售台账**对应维度的在库量（on_hand-），并写补货红冲流水（REPLENISH_OUT / SALES_OUT）；在库不足时拒绝红冲。
- 红字出库明细与原蓝字出库明细允许使用**相同序列号**：序列号唯一约束仅约束蓝字出库行（防重复发货），红冲行豁免。
- 红字订单当前**仅开放补货类型**；销售/开票等类型的红字红冲沿用既有销退流程，不在本需求范围。

### R9. 开票拣选寄售库存交互要求（v4.4.1 细化，方案 A）

- 开票订单不允许手工录入产品/批号/序列号，必须通过「选择寄售库存」弹窗从该经销商可用台账中**整行勾选**。
- 弹窗展示：经销商（只读）、仓库筛选、产品编码/名称/规格/批号/序列号/在库/锁定/可用/标准单价；支持关键字检索；序列号商品本次开票数量限 1。
- 弹窗底部实时汇总已选行数、合计开票数量、合计开票金额；确认后整单替换开票明细，行内以标签展示批号/序列号并自动计价。
- 门禁：未选经销商时拣选按钮禁用并提示「请先选择经销商后再拣选寄售库存」；经销商未开启寄售时，补货/开票订单类型不可选；切换经销商需清空已拣明细。

## 3. 验收标准

1. 未开启寄售的经销商下补货/开票订单被拦截；开启后可下。
2. 补货订单全行为 0 金额，任何折扣/促销/代金券/一口价均不生效。
3. 补货发货后，寄售台账按 经销商+SKU+批号+序列号 增加在库，流水为 REPLENISH_IN。
4. 开票订单只能从该经销商寄售库存选择；选择器仅显示可用量>0 的库存；超量/错批号被拒并提示编码+名称。
5. 开票提交即预占（可用量下降）；审批通过实扣；拒绝/退回/撤回释放，可用量恢复。
6. 寄售金额 = 在库量 × 产品标准价 汇总，随台账变动实时更新。
7. 样品订单：多于一个单品或未填原因被拒；合法时 0 金额。
8. 租户关闭进销存后，厂家用户库存/采购菜单与接口不可用、销售/销退/出库/寄售可用；经销商用户库存菜单仍可用。
9. 三端（PC 业务前台、平台后台、移动 H5）入口页面可打开、无白屏、Console 无红色错误、网络无 5xx。
10. 红字补货单可创建（SOR 前缀，0 金额），提交/审批/ERP 红字回调后寄售台账对应维度 on_hand 扣减、产生 REPLENISH_OUT 流水；红字出库行与原行同序列号不报错；非补货类型不允许红字。
11. 开票订单只能通过「选择寄售库存」弹窗整行勾选加入明细，批号/序列号标签展示、自动计价；未选经销商时拣选按钮禁用并有提示。
12. 进销存关闭时厂家视角供应商菜单隐藏、开启后可见；各 CRUD 页操作无未捕获 Promise 异常；官网产品手册页图片无 404。

---

## 4. 关键假设

- 补货发货沿用现有「销售出库」流程，通过源订单类型识别补货并回写寄售台账。
- 开票订单的批号/序列号来自寄售库存选择器；普通销售订单不强制批号/序列号。
- 信用占用（credit_used）当前为占位（应收账未集成），寄售占用（consignment_used）已按标准价实时计算。
- 定制订单（CUSTOM）本期仅保留选项，按普通订单计价，不做额外业务规则。
