## 1. 系统概述

DMS (Distributor Management System) 经销商管理平台，面向医疗器械行业提供产品/经销商/医院/仓库/订单/库存/合同/促销/手术报备/审批流/报表的全流程数字化管理。

**技术栈**: Spring Boot 3 + JPA (Native Query) · Vue 3 + Element Plus · PostgreSQL 14 · Docker + Nginx · Flyway 数据库迁移

**多租户**: 单数据库, `tenant_id` 隔离; 测试租户 `default` (admin/Sh123456)

### 3.2 状态机

#### 采购订单 (PO)
```
DRAFT → SUBMITTED → APPROVED → RECEIVING → COMPLETED
                ↘ REJECTED / CANCELLED
```
- **DRAFT**: 可编辑/取消/删除 (模块配置 editableWhen=['DRAFT'])
- **SUBMITTED**: 仅可 审批通过/驳回; **不能编辑/取消/删除** (v3.7.5)
- **APPROVED**: 不可删除; 可取消 (前提: 关联收货单均 DRAFT 且累计已收=0)
- **RECEIVING**: 累计已收 > 0 但未达 PO 数量
- **COMPLETED**: 全部收完，或源 PO 关联收货单均终结 (COMPLETED/CANCELLED)
- **CANCELLED**: 用户手动取消, 级联关闭 DRAFT/RECEIVING 收货单 + DRAFT 子单

#### 收货入库 (receipt)
```
DRAFT → APPROVED (自动) → PARTIAL_RECEIVED → COMPLETED
                      ↘ CANCELLED (取消剩余 且无 CONFIRMED 子单)
```
- **自动生成**: PO APPROVED 时 `AutoDocGenerator.createReceiptForPurchaseOrder()` 创建 DRAFT 收货单 + 复制 lines
- **取消剩余**: 终结父单; 有 CONFIRMED 子单 → COMPLETED, 否则 → CANCELLED
- **取消剩余后 PO 同步 COMPLETED** (v3.7.6)

#### 收货子单 (receipt_batch)
```
DRAFT → CONFIRMED
      ↘ CANCELLED
```
- 一次 PO 可多次收货, 每次对应一个子单
- 子单可无限创建直到父单取消剩余
- 确认收货后写 `confirmed_at` 作入库时间

### 3.3 库存状态字典 (stock_status)

| code | 含义 | label |
|------|------|-------|
| U | 合格 | `U 合格` |
| Q | 待检 | `Q 待检` |
| B | 不合格 | `B 不合格` |

**内部值** (库存表 stock_status 字段): QUALIFIED / PENDING / DEFECTIVE

**显示规则**: 前端 CrudView `dictLabel(col, v)` 自动翻译带 `filter.options` 的列 (v3.7.5).

### 3.4 操作日志 (v3.7.5+)

- 通用 `@OperationLog` 注解 + `OperationLogAspect` AOP 拦截
- 业务类型: `purchaseOrder` / `receipt` / `order` / `product` / `dealer` 等
- 关键动作: CREATE / UPDATE / DELETE / APPROVE / REJECT
- **收货子单**业务日志 businessId 统一为 `receiptId` (aspect 优先取 result.receiptId)
- **PO 操作**: create/submit/approve/reject/cancel 全部入日志, remark 中文
- 存储: `operation_log` 表
- 查询: `GET /api/operation-log/list/{businessType}/{businessId}`

### 3.5 序列号管理
- 产品 `is_serial_managed=true` 时收货强制填序列号 (多行文本, 一行一个)
- 确认收货时 serial 数量必须等于 qty
- 库存表 `serial_no` 字段唯一约束 (产品 + 序列号 + 仓库)

### 3.6 批次管理
- 所有库存明细必带 `batch_no`
- 同产品同仓库同批次同状态库存可合并
- 序列号管理产品库存**不可合并** (每个序列号一行)

## 4. 关键业务流程

### 4.1 采购订单全流程
```
1. 用户新建 PO (必填: 类型/供应商/仓库/明细产品+数量)
2. PO.status = DRAFT, 可编辑
3. 提交审批 (submit) → SUBMITTED, 仅可审批/驳回
4. 审批通过 (approve) → APPROVED + 自动生成收货单 (AutoDocGenerator)
5. 用户进入收货单 (GR-*), 创建子单 GR-*-1
6. 子单加明细 (从 PO lines 选产品, 填批次/序列号/数量)
7. 确认收货 (confirm) → 子单 CONFIRMED, confirmed_at=now()
   - 库存表更新 (stock_status=PENDING 待检)
   - receipt_lines.received_qty 累加
   - receipt.status 更新 (PARTIAL_RECEIVED / COMPLETED)
   - PO.status 同步 (RECEIVING / COMPLETED)
8. 可继续创建 GR-*-2, ... 直到全部收完
9. 取消剩余 (cancel-remaining) → 父单 + PO 同步 COMPLETED/CANCELLED
```

### 4.2 取消约束 (v3.7.5/v3.7.6)
- **PO cancel**: 仅 DRAFT / APPROVED 可取消; APPROVED 状态下需 关联收货单全 DRAFT 且 累计已收 = 0
- **SUBMITTED 不可取消** (v3.7.5 起)
- **PO cancel 级联**: 关联收货单 (DRAFT/RECEIVING/PARTIAL_RECEIVED/APPROVED) → CANCELLED; DRAFT 子单也 CANCELLED
- **收货单 cancelRemaining**: 取消所有 DRAFT 子单, 未收 receipt_lines 转 cancelled_qty; 若有 CONFIRMED 子单 → COMPLETED, 否则 → CANCELLED; 级联 PO → COMPLETED

### 4.3 异常提示 (v3.7.5)
所有收货类异常已统一为 `BusinessException(ErrorCode.BUSINESS_RULE_VIOLATION, 中文文案)`:
- 本次收货数量超过采购订单数量 (含产品名/累计/本次/采购数量)
- 批次号不能为空
- 数量必须大于 0
- 序列号管理产品请填写序列号
- 序列号个数与本次收货数量不一致
- 收货子单还没有明细
- 仅 DRAFT 子单可编辑 / 可取消

### 4.4 审批历史
- `approval_tasks` + `approval_history` 表记录
- PO `approved_by` + `approved_at` 字段写入, 前端列表 JOIN users 显示 `auditUserName / auditAt`
