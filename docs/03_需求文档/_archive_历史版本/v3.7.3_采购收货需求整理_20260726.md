# v3.7.3 采购订单 + 收货入库 需求整理与差距分析

- 版本：v3.7.3（草案）
- 提出时间：2026-07-26
- 来源：用户在 v3.7.2 供应商修复上线后，进行下单+收货全链路测试时提出的 9 项问题
- 状态：**待用户确认（尚未开工代码）**

## 1. 用户原文诉求（9 项，编号 R1-R9）

**采购订单侧**
- R1: 采购订单创建完成后依然是草稿状态，无法审核（应能提交并审核）
- R2: 采购订单审核通过后，应自动创建对应的收货入库单
- R3: 采购订单中"物料明细"区域不够大气，要与整个页面宽度匹配
- R4: 采购订单必输项（物料、数量等）需要在字段前打星号，提交时进行前端校验

**收货入库侧**
- R5: 收货入库不应有"新增"按钮，所有收货入库都必须从采购订单来
- R6: 收货入库编辑页/详情页应带出关联采购订单的基本信息
- R7: 收货入库编辑页中，目前无法对每一行物料进行本次收货操作
- R8: 收货入库不能有"删除"按钮，只能"取消收货"或"完成收货"
- R9: 清理之前无用的收货入库测试数据，重造 4 种状态的测试数据（已完成/未完成/部分收货/取消收货），全部与真实采购订单关联

## 2. 代码摸底与差距分析

### 2.1 采购订单

| 项 | 现状 | 差距 |
|---|---|---|
| 状态机 | Controller 注释写 `DRAFT -> SUBMITTED -> APPROVED -> RECEIVING -> COMPLETED`；`create()` 落 DRAFT；`submit()` DRAFT->SUBMITTED；`approve()` SUBMITTED->APPROVED 且已闭环 `AutoDocGenerator.createReceiptForPurchaseOrder(poId)` | 后端已就绪 |
| 前端 statusActions | `modules.js:400` 中 `when: ['PENDING_APPROVAL']` — 与后端实际状态 `SUBMITTED` 不匹配，且 **完全没有"提交审批"按钮** | **R1 根因**：DRAFT 状态下前端未渲染任何 action，用户看不到入口；`when` 值全部要改成 `SUBMITTED` |
| 自动建收货入库 | `AutoDocGenerator` 已实现 INSERT INTO receipts + receipt_lines，状态 DRAFT，`auto_created=true`，`source_po_id=poId` | 后端 R2 已完成；**需在验证阶段确认闭环** |
| 明细区域宽度 | 采购订单表单使用通用 `CrudView.vue` 的 dialog + `type:'lines'` 渲染，dialog 默认 60% 宽 | **R3 差距**：明细行 4 列（产品/数量/单价/税率）+ 操作，dialog 需要拓宽到 90% 或改为"全屏抽屉" |
| 必输星号+校验 | `CrudView.vue:95` 已有 `:required="f.required"` 渲染 label 前的 `*`；但明细行 (`type:'lines'`) 走独立表格，无 required 校验 | **R4 差距**：明细行内 `productId`、`qty` 无红星、无提交前校验；`unitPrice/taxRate` 可选（非必输） |

### 2.2 收货入库

| 项 | 现状 | 差距 |
|---|---|---|
| 新建入口 | `modules.js:514` `receipts` 未设置 `noCreate: true`；CrudView 顶部有"新建"按钮 | **R5 差距**：需加 `noCreate: true` |
| 关联 PO 信息 | `ReceiptEdit.vue` 已显示 `sourcePoCode / refDocType / warehouseName`，但**未显示**采购单类型/供应商/下单日期/总金额/期望到货日期 | **R6 差距**：需扩展 `GET /api/receipts/{id}` 返回 PO 关键字段（supplierName、expectedDate、totalAmount、orderCreatedAt），并在编辑页展示 |
| 按行收货操作 | `ReceiptEdit.vue` 已有"应收/已收/本次/待收/序列号/批量录入"列，`handleSubmit` 应走 `/api/receipts/{id}/confirm` | **R7 差距（需核实）**：需要在测试中确认"本次收货"能否提交成功；如后端 confirm 缺行级参数则需要补 |
| 删除按钮 | CrudView 表格行有默认"删除"按钮（`canDelete = !readonly && !noDelete`） | **R8 差距**：`modules.js` 中 `receipts` 需加 `noDelete: true`；后端 `DELETE /api/receipts/{id}` 可保留但不给 UI 入口 |
| 测试数据 | 之前散落 seed，未与真实 PO 关联，无 4 种状态覆盖 | **R9 差距**：新增 V34 迁移，先清理再造数据 |
