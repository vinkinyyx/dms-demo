# v3.7.7 销售订单/销售出库对齐采购订单/收货入库

> 状态：已完成
> 日期：2026-07-31
> 范围：PC 端（`frontend-vue/`），**不动移动端**（`mobile/`）

## 一、背景

v3.7.3–v3.7.6 已对采购订单/收货入库完成了三轮重构，形成了成熟模式：
- 原生 SQL 分页列表 + 详情 + 完整状态机按钮
- 单据列表 join 仓库/来源单/审核人返回友好名称
- 详情页区分「应发行（expected_qty）」「已执行行（shipped/received）」
- 审批通过自动生成下游单据草稿
- 编辑页布局：单据头信息 / 关联来源单据 / 产品明细 / 编辑区 / 汇总 / 已执行记录 / 操作记录

销售订单与销售出库仍是旧版 JPA + CrudView 逻辑，存在：
1. 销售订单端点 `/api/orders` 同时处理销退红字，路由混乱
2. 缺少 `warehouseId`（发货仓库）、税额、审批时间字段
3. 状态用 SHIPPED，语义不清，无法区分"部分发货"与"全部完成"
4. 销售出库 partialShip 按 productId 聚合，同产品多行时累计校验 bug
5. 出库详情页布局简陋，没有关联销售订单/订单产品明细/操作记录卡片

## 一点五、最终验收补充（2026-08-01）
- 销售出库采用与收货入库一致的父子单模型：每次发货生成一张 DRAFT 子单，可保存明细、确认发货、取消本次；父单按已发/已取消汇总状态。
- 状态统一使用 `PARTIAL_SHIPPED`，不再使用 `PARTIAL_CANCELLED`。部分发货后取消剩余，会把未发数量写入 `cancelled_qty`，父单和源销售订单均转为 `COMPLETED`。
- 销售订单审批通过后自动生成销售出库单；只要存在已确认发货记录，销售订单不可取消、不可修改。完全未发货的 APPROVED 订单允许取消，并级联取消出库单及 DRAFT 发货子单。
- PC 销售出库列表只保留“打开/查看”，所有执行操作收敛到销售出库编辑页；审批/驳回等动作执行后统一刷新列表，修复审批通过按钮未消失问题。
- 销售出库与收货入库的关键差异：出库批次号/序列号只能选择，不能手填；可选范围限定为当前仓库、当前物料、`QUALIFIED` 在库库存，序列号还必须未发货。
## 二、改造内容

### 2.1 销售订单（orders）

**新端点**：`/api/sales-orders`（SalesOrderController，原生 SQL，镜像 PurchaseOrderController）
- 列表 join dealers/warehouses/users，返回 `warehouseName/dealerName/auditUserName/approvedByName`
- 详情返回 lines + allowedActions
- create 必填 dealerId + warehouseId；put 仅 DRAFT
- 状态机：`DRAFT → SUBMITTED → APPROVED → SHIPPING → COMPLETED`，支持 REJECTED / CANCELLED
- approve 调 `AutoDocGenerator.createSalesOutForOrder(id)` 自动建销售出库草稿
- cancel 校验关联 sales_outs 均为 DRAFT/CANCELLED 且无发货，并级联取消
- 单号前缀 `SO-*`，导出/批量导入对齐采购

**Flyway V36 新字段**：`warehouse_id, tax_amount, approved_by, completed_at, cancelled_at, extra`

**前端 modules.js**：
- `api`：`/api/orders` → `/api/sales-orders`
- 列：去 `dealerId` 原数，加 `warehouseName（发货仓库）`、`amountInclTax（含税金额）`
- 状态选项：去 `SHIPPED`，加 `SHIPPING（发货中）`
- 订单类型：简化为 `NORMAL（常规销售）/ URGENT（紧急销售）`
- form 新增 `warehouseId（发货仓库，必填，picker: warehouses）`
- `editableWhen: ['DRAFT'], noDelete: true`
- statusActions 采用数组式，对齐采购

### 2.2 销售出库（sales_outs）

**表结构对齐 receipts**（V36 迁移）：
- 主表加：`warehouse_id, remark, approved_at, approved_by, shipped_at, completed_at, cancelled_at, extra`
- 明细加：`expected_qty（应发）, shipped_qty（累计已发）, unit_price, tax_rate, subtotal, seq`
- 历史数据回填 `expected_qty = qty, shipped_qty = qty`；`status=NULL/SUBMITTED → DRAFT`

**AutoDocGenerator.createSalesOutForOrder 重写**：
- 单号前缀 `XS-*`（红字 `GIR-*`）
- 从 orders 表读 warehouse_id，不再兜底
- 插入 sales_out_lines 时 `expected_qty = 订单行qty, shipped_qty=0, qty=0`，带 seq/unit_price/tax_rate/subtotal

**SalesOutService.partialShip 重构**：
- DTO `ShipLineRequest` 加 `expectedLineId`，按应发行 ID 定位（修复同产品多行 bug）
- 每行校验累计 shipped_qty + 本次 ≤ expected_qty
- 执行行（expected_qty=0）记录本次发货，回写应发行 shipped_qty
- 全部发完 status=COMPLETED + shipped_at/completed_at，否则 PARTIAL_SHIPPED
- 回写源 orders：APPROVED → SHIPPING（部分）或 COMPLETED（全部）

**前端 SalesOutEdit.vue 完全重写**（对齐 ReceiptEdit.vue 布局）：
1. 顶部工具栏：返回 / 部分取消 / 部分发货 / 确认发货 / 整单取消
2. **出库单信息**：单号/经销商/发货仓库/来源订单/状态/日期/备注
3. **关联销售订单**（v-if sourceOrder）：单号/类型/状态/经销商/仓库/金额/下单人/审批人/备注
4. **销售订单产品明细**（soLines）：只读，展示订单原始数量/单价/小计
5. **发货明细**（核心编辑区）：产品+应发已发剩余/在库批次选择/本次发货数量/批次/序列号/删除
6. **发货汇总**：累计应发/已发/待发/已取消/本次发货/本次金额
7. **已发货记录**（shippedLines）：执行行只读表
8. **操作记录**：`/api/operation-log/list/salesOut/{id}`
