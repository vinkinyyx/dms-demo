## 1. 产品定位

DMS（Dealer Management System，经销商管理系统）是面向医疗器械/耗材分销场景的多租户 SaaS，覆盖：

- 经销商/医院/区域/供应商/仓库/产品线等主数据；
- 产品、批次、序列号、UDI、保质期、包装层级等追溯主数据；
- 销售订单、采购订单、收货入库、销售出库、库存调整/移动/盘点、借货、退换货等进销存闭环；
- 合同、授权、促销、价格/折扣/返利等商务政策；
- 手术登记/报台、RMA、分销、质量投诉/CAPA、发票等行业业务；
- 报表、仪表盘、审计日志、RBAC、工作流、字典、通知、接口集成等平台能力；
- PC 后台与 H5 移动端（扫码收货、移动下单、订单跟踪、消息、报表）。

技术栈：Vue 3 + Element Plus + Vite、Spring Boot 3 + JPA + Native SQL + AOP、PostgreSQL 14、Redis、MinIO、Docker/Docker Compose。

## 5. 销售订单模块（v3.7.7 最新）[已上线]

### 5.1 数据模型
- 表 orders + order_lines；销退复用 orders 并置 is_red=true。
- 关键字段：code(SO-*)、order_type(NORMAL/URGENT)、dealer_id、warehouse_id(发货仓必填)、amount_incl_tax、discount_amount、final_amount、tax_amount、expected_date、status、approved_by/approved_at、completed_at/cancelled_at、ship_snapshot、extra。
- 明细字段：product_id、qty、unit_price、tax_rate、sub_total、is_gift。

### 5.2 状态机
DRAFT → SUBMITTED → APPROVED → SHIPPING → COMPLETED；SUBMITTED 可 REJECTED；DRAFT 与未发货 APPROVED 可 CANCELLED。

- DRAFT：可编辑、提交审批、取消、删除。
- SUBMITTED：只能审批通过或驳回，不可编辑/取消/删除。
- APPROVED：自动生成销售出库单；仅完全未发货可取消；不可删除。
- SHIPPING：存在部分发货，订单不可修改/取消。
- COMPLETED：全部发货，或部分发货后取消剩余。
- CANCELLED：草稿取消或审批后未发货取消；级联取消出库单与草稿子单。

### 5.3 接口与前端
- POST /api/sales-orders 必须填 dealerId + warehouseId + lines；PUT 仅 DRAFT 可改。
- POST /api/sales-orders/{id}/submit|approve|reject|cancel。
- GET /api/sales-orders 分页，join 经销商/仓库/审核人；详情返回 lines 与 allowedActions。
- 审批通过调用 AutoDocGenerator.createSalesOutForOrder 自动生成 GI-* 销售出库草稿。
- PC 列表显示发货仓库、审核人、含税金额；状态筛选含 SHIPPING，不含 SHIPPED。
- 动作：DRAFT 提交/取消；SUBMITTED 审批/驳回；DRAFT/APPROVED 取消；动作后统一刷新列表，修复审批按钮不消失。
- 销退订单仍走 /api/orders?isRed=true，不在本次改造范围。

## 6. 销售出库模块（v3.7.7 最新）[已上线]

### 6.1 数据模型
- 父单 sales_outs：code(GI-*)、source_order_id、dealer_id、warehouse_id、status、shipped_at/completed_at/cancelled_at、remark。
- 应发行 sales_out_lines：expected_qty、shipped_qty、cancelled_qty、unit_price/tax_rate/subtotal、seq。
- 执行行：同表 expected_qty=0, shipped_qty>0 表示实际发货记录。
- 子单 sales_out_batches + 子单行 sales_out_batch_lines（V39）：seq、status、confirmed_by/at、cancelled_by/at/reason；行含 expected_line_id、ship_line_no、product_id、warehouse_id、qty、stock_batch_id、batch_no、serial_no、unit_price。

### 6.2 状态机
- 父单：DRAFT/APPROVED → PARTIAL_SHIPPED → COMPLETED；部分发货后取消剩余 → COMPLETED；未发货可 CANCELLED。
- 子单：DRAFT → CONFIRMED；DRAFT 可 CANCELLED。CONFIRMED 不可撤销。
- recalc 规则：sum(shipped+cancelled) >= sum(expected) 则 COMPLETED；shipped>0 则 PARTIAL_SHIPPED；否则 DRAFT。
- 源销售订单状态镜像：出库 PARTIAL_SHIPPED → 订单 SHIPPING；出库 COMPLETED → 订单 COMPLETED；未发货取消 → 订单 CANCELLED。

### 6.3 业务规则
- 审批通过自动创建销售出库父单，应发行来自订单行 expected_qty=订单数量，shipped_qty=0。
- 每次发货创建一张 DRAFT 子单，可保存明细、确认发货、取消本次；支持多次部分发货。
- 确认发货扣减 QUALIFIED 库存；序列号逐件扣减并写 stock_serials.shipped_at；写 inventory_transactions、插执行行、累加应发行 shipped_qty、回写父单和源订单状态。
- 校验：批次号必须来自该仓该物料 QUALIFIED 在库批次；序列号产品每行 qty=1，序列号必须从未发货 QUALIFIED 库存选择；累计发货不超过剩余数量（超额返回 40006 中文提示）。
- 取消本次：仅 DRAFT 子单可取消，不影响库存。
- 取消剩余：取消所有 DRAFT 子单，将未发数量写入 cancelled_qty；若存在已确认子单则父单与源订单 COMPLETED，否则 CANCELLED。
- 销售订单取消：仅无发货记录且出库为 DRAFT/CANCELLED 时允许，并级联取消出库单与 DRAFT 子单。

### 6.4 接口
- POST /api/sales-outs/{id}/batches 创建发货子单。
- PUT /api/sales-out-batches/{bid} 保存子单明细。
- POST /api/sales-out-batches/{bid}/confirm 确认发货。
- POST /api/sales-out-batches/{bid}/cancel 取消本次。
- POST /api/sales-outs/{id}/cancel-remaining 取消剩余。
- GET /api/inventory/available-batches?productId&warehouseId 返回 QUALIFIED 在库批次。
- GET /api/inventory/available-serials?productId&batchNo&warehouseId 返回未发货且 QUALIFIED 序列号。

### 6.5 PC 前端
- 销售出库列表仅保留“打开/查看”，不显示整单取消/审批等行内动作；所有执行操作进入编辑页。
- 编辑页布局对齐 ReceiptEdit：单据头、关联销售订单、销售订单产品明细、发货子单列表、发货汇总、已发货记录、操作日志。
- 子单卡片：DRAFT 可编辑，显示“新增行/保存明细/确认发货/取消本次”；CONFIRMED/CANCELLED 只读。
- 批次号用 el-select 选择合格在库批次；序列号用单选弹窗选择，不能手填。
- 顶部“创建发货单”“取消剩余发货”仅在 DRAFT/APPROVED/PARTIAL_SHIPPED 时显示。

## 7. 采购订单与收货入库（v3.7.6 最新）[已上线]

### 7.1 采购订单
- 表 purchase_orders + purchase_order_lines；采退复用并置 is_red=true。
- 状态机：DRAFT → SUBMITTED → APPROVED → RECEIVING → COMPLETED；SUBMITTED 可 REJECTED；DRAFT/未收货 APPROVED 可 CANCELLED。
- 规则：
  - DRAFT 可编辑/提交/取消/删除；SUBMITTED 仅审批/驳回，不可编辑/取消/删除。
  - APPROVED 可取消（仅未收货），可生成/打开收货单；不可删除。
  - 取消时级联关闭关联收货单与子单。
  - 列表去总金额，显示审核人（来自 users.name）与审核时间。
  - 供应商/仓库显示名称，不显示裸 ID。
  - 提交/审批写中文操作日志。

### 7.2 收货入库
- 父单 receipts：code=GR-YYYYMMDD-N，关联 source_po_id。
- 子单 receipt_batches：code=GR-*-N（收货子单），状态 DRAFT/CONFIRMED/CANCELLED。
- 子单行 receipt_batch_lines：po_line_id、po_line_seq、receipt_line_no、qty、batch_no、serial_nos。
- 流程：
  1. PO APPROVED 自动创建父单 DRAFT。
  2. 打开父单创建 DRAFT 子单。
  3. 子单选 PO 行，填写本次数量、批次号、序列号（可手填/批量录入）。
  4. 确认收货写库存 PENDING，累加 PO 行 received_qty，子单 CONFIRMED 并写 confirmed_at 作为入库时间。
  5. 取消本次仅取消 DRAFT 子单；取消剩余将未收数量写 cancelled_qty。
  6. 父单 COMPLETED/CANCELLED 时同步 PO 为 COMPLETED（非 RECEIVING）。
- 校验：累计收货不超过采购数量，超额返回中文友好错误；序列号产品序列号个数必须等于数量且必填。
- 列表只保留“打开/查看”，详情页/编辑页使用同一路由，底部展示操作日志。

## 8. 库存模块

### 8.1 库存与事务 [已上线]
- inventory 维度：tenant、product、warehouse、batch_no、serial_no、stock_status、qty、exp_date、prod_date。
- inventory_transactions 记录每次收发货/调整/移动，字段含批次、序列号、数量、事务类型、来源单据、操作人、时间。
- 收货增加 PENDING 库存（待检），销售出库扣减 QUALIFIED 库存。
- 库存状态变更（放行/隔离/报废）通过库存调整或质量流程记录。

### 8.2 调整、移动、盘点 [已上线/部分]
- inventory_adjustments：盘点、报损、数据修正、其他；影响库存并记流水（本次不动）。
- stock_moves（v3.7.8 改造）：库存移动支持两种模式，单据保存即生效（COMPLETED，无草稿/审批）。
  - **STATUS_ADJUST 仓内状态调整**：在同一仓库内，把一批库存的库存状态从 A 调整为 B（合格/不合格/隔离/待检）；目标仓库=源仓库。
  - **WAREHOUSE_TRANSFER 跨仓移动**：从源仓库批量移动到目标仓库，并可同时调整库存状态；源仓库与目标仓库不能相同。
  - 单号前缀 `MV-YYYYMMDD-NNNNN`（如 MV-20260801-00001），基于 doc_no_sequences 原子自增。
  - **库存必须从库存中选择，不可手填**：物料、批次号、序列号全部从所选源仓库+物料下 qty>0 的库存记录中带出，并自动带出当前 stock_status 作为“当前状态”。
  - 同一张单允许一次选择多个批次/多行；每行可独立设置目标状态。
  - 跨仓移动时，目标状态默认带出源库存状态，允许修改；仓内状态调整时目标状态默认隔离，源状态与目标状态相同且同仓时拒绝（无需调整）。
  - **数量校验**：本次数量必须 > 0 且 ≤ 该库存行当前在库数（UPDATE ... WHERE qty >= ? 原子扣减）；超额拒绝并友好提示。
  - **序列号产品**：序列号库存每行 qty 固定为 1，序列号必须从该仓该批次在库序列号中勾选，不可手填；数量=勾选件数。
  - 库存状态字典：QUALIFIED(合格)/DEFECTIVE(不合格)/QUARANTINED(隔离)/PENDING(待检)，本次新增 QUARANTINED。
  - 落库：按 srcInventoryId 原子扣减源库存，按 (product+warehouse+batch+serial+toStatus) upsert 增加目标库存；写 stock_move_lines（含 src_inventory_id/from/to_stock_status）和 inventory_transactions（STATUS_ADJUST_OUT/IN、MOVE_OUT/IN，含操作人）；写操作日志。
  - 列表页只保留必要列（移动类型/源仓/目标仓/源状态/目标状态/状态/时间），新增/查看通过专用编辑页完成；PC only，移动端本次不改。
- stocktakes + stocktake_lines 盘点功能，支持盘盈盘亏生成调整。

## 14. 非功能要求
- 多租户隔离，所有查询必须带 tenant_id。
- 所有金额使用 numeric，禁止浮点误差；时间统一 Asia/Shanghai。
- 库存扣减需并发安全（UPDATE ... WHERE qty >= ?），失败给出友好提示。
- 所有审批/状态变更/创建/修改/删除/导入导出纳入操作日志。
- API 统一返回 {code,message,data}，code=0 成功；业务异常使用 BusinessException 与错误码。
- 列表默认分页，支持后端筛选/排序；导入导出 Excel。
- 审计日志不可篡改；库存流水不可修改。
