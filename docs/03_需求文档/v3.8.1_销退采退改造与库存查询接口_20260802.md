> 冲突处理：本文相对 `需求总览.md` 中关于销退/采退触发方向、单号前缀的旧描述，以本文为准。

## 1. 改造目标

参考并对齐四个成熟模块的全部细节：
- 采购订单（`/api/purchase-orders`）
- 销售订单（`/api/sales-orders`）
- 收货入库（`/api/receipts`，含子单/多次收货/部分收货/剩余取消）
- 销售出库（`/api/sales-outs`，含子单/多次发货/部分发货/剩余取消）

对两个红字订单模块做方向纠正与功能补齐：
- **销退订单**：客户把货退回我方，审批后触发 **收货入库**（货物入我方仓库，库存增加，入“待检 PENDING”）。
- **采退订单**：我方把货退给供应商，审批后触发 **销售出库**（货物出我方仓库，库存减少，不限制库存状态）。

> 现状问题（需修复）：
> 1. 销退审批后错误地生成了“销售出库单 GIR”，方向反了；且 `/api/orders` 列表未按 `is_red` 过滤，销退与销售订单混显。
> 2. 采退审批后生成的是“收货入库单 GRR”（按退货给供应商扣减库存的旧逻辑），现需统一改为触发标准销售出库单。

## 3. 销退订单（Sales Return）

### 3.1 数据模型
- 复用表 `orders` + `order_lines`，置 `is_red=true`，`code` 前缀 RS。
- 字段：
  - `ref_order_id`：原销售订单（必填）。
  - `ref_sales_out_id`：原发货单（销售出库单，必填）——销退必须关联“已发货”的发货单。
  - `return_reason`：退货原因（必填，单据头）。
- 建单时从所选原发货单（sales_out_lines 已确认发货数量）带出明细与“可退数量”：
  - 每行带出 product_id、批次/序列号（若原发货有记录）、原发货数量作为可退上限。
  - 退货数量默认等于可退上限，**只能改小，不能改大**。
  - 行可以删除（表示该行不退）。
  - 校验：退货数量 ≤ 该产品/批次/序列号的累计可退数量；不可为负。

### 3.2 状态机（对齐销售/采购订单）
```
DRAFT -> SUBMITTED -> APPROVED -> RECEIVING -> COMPLETED
                 \-> REJECTED
DRAFT/APPROVED(未收货) -> CANCELLED
```
- DRAFT：可编辑、删除、提交审批、取消。
- SUBMITTED：可审批通过、驳回。
- APPROVED：自动生成 RGR 收货入库草稿单；未产生收货时可取消（联动取消下游入库单）。
- RECEIVING：下游入库单已部分收货；不可取消。
- COMPLETED：下游入库单全部收货完成（按入库单状态回写）。
- CANCELLED / REJECTED：终态。

### 3.3 审批联动
- 审批通过：状态置 APPROVED，写 approved_at/approved_by；自动生成 RGR 入库草稿（明细 expected_qty=退货数量）；幂等不重复创建。
- 取消（APPROVED 且未收货）：校验关联 RGR 单 received_qty 累计=0 且无非草稿子单，否则拒绝；联动取消 RGR 及 DRAFT 收货子单。
- 订单状态随下游入库单进度回写（部分入库→RECEIVING，全部→COMPLETED）。

### 3.4 库存方向
- 销退入库在“收货确认”时增加库存，库存状态为 **PENDING（待检）**。
- 序列号商品：收货时序列号必填，支持“批量粘贴一串序列号”（换行/逗号/空格分隔，自动去重）；写入 receipt_lines 与 inventory.serial_no，qty=1/个。
- 批次商品：录入批次号、生产日期/有效期（可选，按产品配置）。
- 库存事务类型 `RECEIPT`（正向 +库存），ref_doc_type='sales_return'。

### 3.5 PC 前端
- 列表：`sales-returns` 走专用接口，按 is_red=true 过滤；列：销退单号、原销售单、原发货单、经销商、仓库、金额、状态、创建时间、审核人。
- 列表按钮精简（对齐销售订单）：仅在该状态显示该显示的按钮，maxActions=2，其余操作进编辑页。
- 新建/编辑页：选择原销售单 → 选择该单下“已发货”的发货单 → 自动带出明细与可退数量；退货原因必填；明细数量只能改小、行可删除。
- 编辑页底部汇总：累计应退/已退/取消/剩余。
- 本期不动移动端。

## 4. 采退订单（Purchase Return）

### 4.1 数据模型
- 复用表 `purchase_orders` + `purchase_order_lines`，置 `is_red=true`，`code` 前缀 RP。
- `ref_po_id`：原采购单（可选记录，不做数量强校验）。
- 出库仓库必填（货物从我方哪个仓库退给供应商）。
- 不限制原单、不限制可退数量（按需求“采退不限制”）。

### 4.2 状态机（对齐采购订单，但进行中为 SHIPPING）
```
DRAFT -> SUBMITTED -> APPROVED -> SHIPPING -> COMPLETED
                 \-> REJECTED
DRAFT/APPROVED(未发货) -> CANCELLED
```
- 采退是“出库”，下游为销售出库单，因此进行中状态为 SHIPPING（而非 RECEIVING）。

### 4.3 审批联动
- 审批通过：状态置 APPROVED；自动生成 RGI 销售出库草稿（明细 expected_qty=退货数量）；幂等不重复创建。
- 取消（APPROVED 且未发货）：校验关联 RGI 单 shipped_qty 累计=0 且无非草稿发货子单，否则拒绝；联动取消 RGI 及 DRAFT 发货子单。
- 订单状态随下游出库单进度回写（部分发货→SHIPPING，全部→COMPLETED）。

### 4.4 库存方向
- 采退出库在“发货确认”时扣减库存，**不限制库存状态**（QUALIFIED/DEFECTIVE/QUARANTINED/PENDING 都可出）。
- 序列号/批次：从库存中选择该仓库+物料下真实存在的库存（带出当前库存状态），不可手填；序列号商品 qty=1。
- 库存事务类型 `SHIPMENT`（负向 -库存），ref_doc_type='purchase_return'。

### 4.5 PC 前端
- 列表：`purchase-returns` 走专用接口，按 is_red=true 过滤；列：采退单号、供应商、出库仓库、金额、状态、创建时间、审核人。
- 按钮精简、对齐采购订单。
- 新建/编辑页：供应商、出库仓库、期望日期、明细（物料选择器支持分页 50 与规格搜索）。
- 编辑页底部汇总：累计应发/已发/取消/剩余。
- 本期不动移动端。

## 6. 库存查询 JSON 接口（新增）

面向外部系统的轻量库存汇总查询：仅按物料编码 + 仓库查询，直接返回可用库存总数，不展开批次/序列号/库存状态。

### 6.1 接口定义
- `POST /api/inventory/query`
- Content-Type: application/json
- 鉴权：与现有接口一致（Bearer Token，租户隔离）。
- 只读，不产生任何库存变动。

### 6.2 请求体
```json
{
  "productCodes": ["XYZZ", "PROD-002"],
  "warehouseId": 10
}
```
字段说明：
- `productCodes`：物料编码数组，**必填**且至少 1 个，支持一次查询多个物料（对应 products.code）。
- `warehouseId`：仓库 ID，**选填**；不传则汇总该租户下所有仓库。

### 6.3 响应体
按物料汇总库存数量（SUM(inventory.qty)，按 product_id 聚合，不区分批次/序列号/库存状态）：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "warehouseId": 10,
    "items": [
      {
        "productCode": "XYZZ",
        "productName": "腔镜吻合器",
        "productSpec": "EGIA60AMT",
        "unit": "把",
        "totalQty": 128
      },
      {
        "productCode": "PROD-002",
        "productName": "超声刀头",
        "productSpec": "HARH36",
        "unit": "把",
        "totalQty": 0
      }
    ],
    "totalCount": 2
  }
}
```
说明：
- `totalQty` 为该物料在所查仓库范围内的库存总数（汇总所有批次/序列号/库存状态）。
- 请求中存在但无库存的物料同样返回，`totalQty=0`。
- 错误统一 `{code, message}`；未登录/过期返回 401/40101；`productCodes` 为空返回参数错误。
