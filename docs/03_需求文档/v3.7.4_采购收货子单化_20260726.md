## 一、用户需求（已拍板）

| 编号 | 需求 | 决策 |
|------|------|------|
| R1 | PO 明细必填校验 + 产品切换时清空该行 qty/unitPrice + 默认行号 seq | 全部实现 |
| R2 | PO 审批后按钮控制: APPROVED 后隐藏审批通过/驳回/编辑/删除, 仅当关联收货单全 DRAFT 且累计已收=0 时允许取消 | D1+D2 前后端双拦截 |
| R3-R6 | 收货入库子单化: 父单 + 多张子单 (DRAFT/CONFIRMED/CANCELLED), 每个子单独立选料/校验/入库 | D3-D4 新表 |
| R7 | stock_status 字典补 U 合格 / Q 待检 / B 不合格 | D5 label 加前缀 U/Q/B, 内部 code 保留 |

## 二、决策清单

- D1: PO 取消条件 = 所有关联 receipts 状态 = DRAFT 且 SUM(received_qty) = 0
- D2: 前后端双拦截, 前端按钮按状态显示, 后端 API 强校验
- D3: 新表 eceipt_batches (子单头) + eceipt_batch_lines (子单明细)
- D4: 子单号 = {父code}-{seq} (seq 从 1 起)
- D5: dict_items label = "U 合格" / "Q 待检" / "B 不合格", code 仍是 QUALIFIED/PENDING/DEFECTIVE
- D6: V35 迁移里直接清理 default 租户旧 receipts/inventory/stock_serials/inventory_transactions

## 六、历史 lessons 追加

- L32: BOM 陷阱 - Windows PowerShell Out-File 或 Set-Content -Encoding UTF8 会写入 BOM, 而 mvn 编译器不接受 java 源码里的 BOM。使用 Python 或 System.Text.UTF8Encoding($false) 或 [System.IO.File]::WriteAllText 显式禁 BOM
- L33: EntityManager native query 里 Tuple.get(...) 返回 Object, 需 null 判断; 时间戳映射用 DateFmt.fmt
