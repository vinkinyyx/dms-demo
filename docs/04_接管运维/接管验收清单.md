# 接管验收清单

## 使用方式

接管开发完成七天计划后，由团队负责人或原熟悉系统的人逐项验收。每项都必须有实际产出或现场演示，不能只口头回答。

## 1. 环境和代码

- [ ] 能独立拉取代码并说明三个主目录用途：`backend/`、`frontend-vue/`、`admin-vue/`。
- [ ] 能本地启动后端。
- [ ] 能本地启动业务前端。
- [ ] 能本地启动平台后台。
- [ ] 能访问 Swagger 和健康检查。
- [ ] 能使用测试账号登录业务端和后台。

## 2. 架构理解

- [ ] 能画出系统总体架构图。
- [ ] 能说明业务前端和平台后台的区别。
- [ ] 能说明 PostgreSQL、Redis、MinIO 各自用途。
- [ ] 能指出认证、授权、租户、日志相关代码位置。
- [ ] 能说明 Flyway 迁移目录和版本规则。
- [ ] 能找到至少三个核心业务模块的 Controller、Service、Repository。

## 3. 部署运维

- [ ] 能说明测试环境服务运行方式、端口和目录。
- [ ] 能找到并查看后端日志。
- [ ] 能找到并查看 Nginx access/error 日志。
- [ ] 能执行服务重启。
- [ ] 能执行数据库备份。
- [ ] 能说明生产必须覆盖哪些环境变量。
- [ ] 能说明发布后如何做健康检查和冒烟测试。
- [ ] 能说明前端、后端、数据库分别如何回滚。

## 4. 故障排查

- [ ] 能根据浏览器 Network 信息定位接口问题。
- [ ] 能根据后端异常栈定位代码或配置问题。
- [ ] 能排查登录失败。
- [ ] 能排查 401 和 403。
- [ ] 能排查页面空白或静态资源 404。
- [ ] 能排查数据库连接失败。
- [ ] 能排查 Flyway 迁移失败。
- [ ] 能排查文件上传下载失败。
- [ ] 能说明发现租户数据串用时的止血步骤。

## 5. 需求变更

- [ ] 能独立完成一个字段新增。
- [ ] 能独立完成一个页面或菜单入口新增。
- [ ] 能独立新增或修改一个接口。
- [ ] 能说明权限和数据范围需要改哪里。
- [ ] 能说明报表口径变更的风险。
- [ ] 能按规范新增 Flyway 脚本。
- [ ] 能列出变更测试点。
- [ ] 能列出变更回滚点。

## 6. 安全和规范

- [ ] 知道生产密码、Token、密钥不能写入仓库。
- [ ] 知道不能修改已发布的 Flyway 脚本。
- [ ] 知道不能绕过租户过滤和权限校验。
- [ ] 知道后端权限校验不能只依赖前端按钮隐藏。
- [ ] 知道直接改生产数据前必须备份和评估。

## 7. AI 辅助开发

- [ ] 能给 AI 明确指定阅读范围和修改范围。
- [ ] 能要求 AI 输出影响面、测试点和回滚点。
- [ ] 能识别 AI 生成代码中的越权、硬编码、跨层逻辑问题。
- [ ] 能在 AI 修改后做代码审查和本地验证。

## 8. 最终实战验收

在答疑人只观察不操作的情况下，独立完成以下任务：

- [ ] 本地启动三个端并登录。
- [ ] 在测试环境查看日志并定位一个模拟 500 错误。
- [ ] 执行一次数据库备份。
- [ ] 执行一次服务重启和健康检查。
- [ ] 完成一个小需求并说明影响面。
- [ ] 执行一次构建。
- [ ] 说明一次完整发布和回滚流程。

## 9. 接管结论

全部关键项通过后，可以认为开发人员具备基础接管能力。建议按以下等级记录：

- 已通过：可独立处理日常运维和常规需求。
- 有条件通过：可处理常规任务，但复杂状态流、性能优化、生产事故需双人复核。
- 未通过：继续补齐对应训练项，暂不单独负责生产变更。

## 10. 接管后必须继续补齐的事项

当前已知建议补齐：

- [ ] 从服务器或历史备份中找回真实 `docker-compose.yml` 或等价编排文件。
- [ ] 修正 `backend/README.md` 中文编码问题。
- [ ] 明确生产环境变量清单和负责人。
- [ ] 建立发布记录模板。
- [ ] 建立故障复盘记录位置。
- [ ] 将备份恢复演练纳入固定计划。
