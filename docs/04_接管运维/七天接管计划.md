# 七天接管计划

## 使用方式

本计划面向已经具备 Java/Vue/数据库基础，但不熟悉 DMS 的开发人员。每天都必须有可验证产出，不能只阅读文档。

建议安排：

- 一名熟悉系统的人作为答疑人。
- 一名接管开发作为主负责人。
- 测试环境可随时重启、备份和回滚。
- 每天结束进行 15 分钟复盘。

## 第 1 天：跑通系统

目标：本地启动所有核心组件并能登录三个入口。

任务：

- 阅读 `docs/文档索引.md` 和本目录 `系统全景图.md`。
- 准备 JDK 17、Node.js、PostgreSQL、Redis、MinIO。
- 使用 `local` profile 启动后端。
- 启动 `frontend-vue`。
- 启动 `admin-vue`。
- 访问 Swagger 和 Actuator。
- 登录业务前端和平台后台。

产出：

- 本地启动截图或访问记录。
- 一张自己整理的启动依赖表。
- 记录至少 3 个启动过程中遇到的问题和解决方法。

验收标准：

- 后端 `/actuator/health` 返回 UP。
- 业务前端可登录并打开一个列表页。
- 平台后台可登录。
- Swagger 可访问。

## 第 2 天：理解架构和业务边界

目标：说清系统由哪些模块组成，核心业务对象是什么。

任务：

- 阅读后端 `com.dms` 下各业务包。
- 阅读 `docs/05_数据库设计/数据库设计.md`。
- 阅读 `docs/06_API设计/API接口清单.md`。
- 梳理登录、租户、权限、订单、合同、库存、报表相关模块。
- 画出一张业务模块关系图。

产出：

- 模块清单。
- 核心业务对象关系说明。
- 不理解或发现不一致的问题列表。

验收标准：

- 能说清两个前端的区别。
- 能说清后端主要包职责。
- 能指出认证、租户、权限相关代码位置。

## 第 3 天：掌握核心链路

目标：理解一个请求从前端到数据库的完整路径。

任务：

- 选一个典型列表查询，从前端 API 追到后端 Controller、Service、Repository、数据库表。
- 选一个典型保存操作，追踪参数校验、权限、事务、租户和日志。
- 查看 Flyway 中菜单、权限、字典相关脚本。
- 用两个不同角色账号验证菜单和按钮差异。

产出：

- 一条查询链路说明。
- 一条写入链路说明。
- 权限和租户控制点清单。

验收标准：

- 能独立定位某个页面对应的前后端代码。
- 能解释接口为什么返回 403。
- 能解释新增字段可能影响哪些层。

## 第 4 天：掌握部署和运维

目标：能在测试环境查看状态、日志、备份和重启服务。

任务：

- 收集测试环境部署资产：容器/Jar、Nginx、环境变量、日志目录、数据库、Redis、MinIO。
- 查看 Nginx 配置。
- 查看后端日志和容器日志。
- 执行一次数据库备份。
- 执行一次服务重启。
- 模拟一个接口错误并从日志定位。

产出：

- 测试环境部署拓扑。
- 日志和配置路径表。
- 一次备份记录。
- 一次重启和健康检查记录。

验收标准：

- 能说清测试环境每个服务运行在哪里。
- 能独立找到后端错误日志。
- 能独立完成备份和重启。

## 第 5 天：完成一个小需求

目标：走通完整需求变更流程。

建议任务：

- 给某业务对象新增一个展示字段。
- 或给某列表增加一个筛选项。
- 或给某详情页增加一个只读字段。

任务要求：

- 新增 Flyway 脚本。
- 修改 Entity、DTO、Service 和接口。
- 修改前端页面。
- 验证权限和租户过滤。
- 写出测试点和回滚点。

产出：

- 可运行的代码变更。
- 数据库迁移脚本。
- 测试记录。

验收标准：

- 功能在本地可用。
- 不破坏现有列表和详情。
- 能说明如何回滚。

## 第 6 天：完成一次中等变更或排障演练

目标：处理跨模块影响，不只会改单表单页。

建议任务二选一：

- 新增一种业务状态，并让列表、详情、筛选、操作按钮、权限、日志同步支持。
- 由答疑人制造一个测试环境问题，接管开发独立定位并修复。

任务要求：

- 先输出影响面分析。
- 再实施代码或配置修复。
- 补充测试用例或测试清单。
- 更新相关文档。

产出：

- 影响面分析。
- 修复或变更代码。
- 测试和回滚记录。

验收标准：

- 能识别跨模块影响。
- 能独立定位问题根因。
- 不只修表面现象。

## 第 7 天：接管验收

目标：在答疑人只观察不操作的情况下独立完成接管任务。

任务：

- 完成 `接管验收清单.md` 中的所有项目。
- 演示一次发布和一次回滚预案。
- 演示一次故障定位。
- 演示一次需求变更。
- 回答团队关于架构、权限、租户、数据库、部署的问题。

产出：

- 已勾选的验收清单。
- 遗留风险清单。
- 后续文档补齐计划。

验收标准：

- 不依赖原 AI 开发过程的口头知识。
- 能独立运维测试环境。
- 能独立处理常规需求。
- 知道什么时候应该升级风险，而不是直接改生产数据。

## 接管后的持续动作

- 每周补充一次排障 FAQ。
- 每次发布更新发布记录。
- 每月做一次备份恢复演练。
- 对高频需求沉淀标准改法。
- 持续修正文档中的过时内容。
