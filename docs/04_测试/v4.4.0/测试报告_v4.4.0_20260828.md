## 11. 发现的问题清单（本次不修复）

### BUG-01【严重 / P0】补货订单发货后寄售入库链路全路径断裂（R1/R3 主链路阻断）

- **复现步骤**：创建 REPLENISHMENT（补货订单，0 金额）→ 提交审批 → 审批通过 → 执行模拟发货。
- **预期**：发货后自动生成 `consignment_movements` 的 REPLENISH_IN 入库流水，并写入 `consignment_stock` 寄售台账；随后开票订单可在「选择寄售库存」弹窗选到该批库存。
- **实际**：销售出库单生成成功（sales_out id=112），但 REPLENISH_IN 流水 **0 条**、寄售台账 **0 行**；`/api/consignment/available` 永远返回空；寄售库存台账页永远"暂无数据"。
- **根因取证**：
  1. `backend/.../erp/v4/V4ErpService.java` 的 `receiveOutbound` 硬编码 `business_type='ERP'`，全流程不调用 `ConsignmentService`（补货发货钩子缺失）；
  2. `backend/.../sales/service/SalesOutService.java` 第 418 行判断写成 `"REPLENISH".equals(orderType)`，而订单类型枚举实际值为 `REPLENISHMENT`，条件永不成立。
- **影响面**：补货→寄售入库→开票扣减的 v4.4.0 核心闭环无法走通；开票订单无寄售库存可选；寄售台账/寄售占用数据无来源（资信页寄售占用列恒为 0）。
- **证据**：`results-v440/api-results-T4400828102333.json` → E5 `{replenishInCount:0, stockRows:0, out:[112,"ERP","REPLENISHMENT"]}`（API 42 项中唯一 FAIL）；`deep-results.json` D5 寄售台账页 rows=0。

### BUG-02【中 / P1】进销存关闭时"供应商"菜单仍显示，点击进入为死页面（菜单与模块开关不一致）

- **复现步骤**：inventoryEnabled=false 下，厂家 admin 登录 → 侧边栏"基础数据"组 → 点击"供应商"。
