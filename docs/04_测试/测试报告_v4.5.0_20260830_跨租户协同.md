## 2. 场景1（路径A）：经销商采购 → 厂家销售草稿 → 厂家出库 → 经销商收货

### 2.1 界面操作步骤（可复现）
1. **经销商下单**：`dealer_a1_admin`（DEALER_A1）登录 → 订单业务 → **采购订单** → 新增：供应商选 **平台厂家（系统供应商）**，入库仓库选本租户仓库，明细选 `COLLAB-DEA-001`、数量 10，保存 → 点 **提交审批**。
2. 系统在**厂家租户**自动生成一张草稿销售订单（客户＝该经销商）。
3. **厂家补价并提交**：`mfr_a_admin`（MFR_A）登录 → 销售订单，找到由采购转入的草稿（备注含"经销商采购单 … 自动转入"，字段"客户采购单号"带经销商采购单号）→ 打开补价格/折扣 → **提交**（测试库该审批流为自动通过）。
4. **厂家出库**：销售出库中找到该订单的出库草稿 → 执行发货（选库存批次、填本次发货数量，支持部分出库）。
5. **经销商收货**：`dealer_a1_admin` → 库存业务 → **收货入库**，出现一张**待收货**单（备注含厂家出库号/销售单号）→ 打开 → **收货确认**（整单确认或逐行填批次/数量）。

## 3. 场景2（路径B）：厂家直接开单出库 → 自动补建经销商采购 + 待收货

### 3.1 界面操作步骤（可复现）
1. **厂家直接开销售单**：`mfr_a_admin`（MFR_A）→ 销售订单 → 新增，客户选该经销商（dealer），产品 `COLLAB-MFR-002`、数量 8，补价后提交/审批。
2. **厂家出库**：对该销售单执行发货出库（选批次 BATCH-B-9，数量 8）。
3. 因为经销商侧**没有对应的采购单**，系统在经销商租户**先自动生成一张"已审批"采购订单**，再生成待收货入库单。
4. **经销商收货**：`dealer_a1_admin` → 收货入库，找到待收货单 → 收货确认。

## 8. 自动化回归（v4.5.1 补齐，2026-08-31）

v4.5.0 首版仅手工测试，自动化覆盖为零。2026-08-31 补齐双层自动化回归，并在编写过程中发现/修复 4 个后端缺陷。

### 8.1 端到端自动化脚本（接口+DB 回读，测试环境）

- 脚本：`automation_test/v450_collab.py`（PowerShell + Python 3.13 运行，TAG=`T4500831130355`，全部种子数据带 TAG 并在 C9 步自清理）。
- 结果：**56/56 全部通过**，覆盖原手工报告的 10 个缺口：

| 缺口 | 场景 | 自动化断言 |
|------|------|-----------|
| G1 | 路径A 转单 | 厂家 DRAFT 销售单存在、customer_po_code 回写、vendor_order_code 回写、台账 PO_TO_SALES_ORDER 1 行 |
| G2 | 路径A 重复提交幂等 | 两次提交返回同号、厂家订单仅 1、台账仅 1 |
| G3 | 路径A 未对码阻断 | 返回 40006 含"对码"、无订单无台账 |
| G4 | 路径A 未绑定阻断 | 返回业务错误含"尚未绑定厂家客户主数据" |
| G5 | 路径B 首次发货 | 自动补 APPROVED PO + PENDING 收货单（dealer_id/warehouse_id 非空）+ DEALER-SELF 主体 + COLLAB-DEFAULT-WH 默认仓 |
| G6 | 路径B 分批发货 | 第二批复用同一张自动 PO，行数量累计 5+3=8，收货单 2 张 |
| G7 | 路径B 同批重发幂等 | outLineId 粒度去重，收货单/台账不重复 |
| G8 | 路径A 台账存在时路径B | 出库回传复用正式 PO，数量保持 10 不被累加 |
| G9 | 未绑定经销商出库 | 静默跳过，无任何单据 |
| G10 | 对码缺失出库回传 | 抛错且整笔回滚，无 PO/收货单/台账 |

### 8.3 编写测试过程中发现并修复的后端/测试基建缺陷

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| B1 | 第二次部分发货整笔跳过 | 路径B 只按 sales_out_id 查台账，首批发货已写台账后，第二张出库单的行被误判为"全部回传过" | 幂等判断细化到 outLineId 粒度（line_refs 内收集 doneOutLineIds 过滤 pending 行） |
| B2 | 路径B 分批发货重复补 PO | linkRowBySalesOut 未命中历史自动 PO 时每次都新建 PO | 补建/复用逻辑统一：先按 salesOrder 链路、再按历史出库台账找自动 PO，命中则 upsertPoLineQty 累加 |
