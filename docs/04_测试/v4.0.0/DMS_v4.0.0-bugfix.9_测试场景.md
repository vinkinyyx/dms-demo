## 1. 促销计算时机
1. 新建销售订单，选择经销商与产品 PRD-J002，数量改为 6：页面只刷新价格，明细中**不出现**赠品。
2. 连续多次修改数量（2→4→6→6）：明细行数不增加，不出现重复赠品。
3. 点击“刷新赠品及价格”：出现赠品 PRD-J003 ×15（每满2送5，floor(6/2)=3）。
4. 再次点击“刷新赠品及价格”：赠品仍为 15 个，不累加。
5. 数量改为 1 后点刷新：赠品行消失（未达阈值）。

## 2. 赠品锁定
1. 赠品行产品选择器不渲染。
2. 赠品行数量输入框禁用。
3. 赠品行无删除按钮。
4. 赠品标准价、最终金额均为 0。

## 3. 折扣分摊
1. 两行标准金额 1000 与 500，总折扣 300（行折扣+整单折扣+满减合计）：第一行最终 800、第二行最终 400（允许 1 分尾差，由最大行吸收）。
2. 出库单价 = 最终金额 / 数量：第一行 4 个 → 200/个；第二行 8 个 → 50/个。
3. 赠品不参与分摊且金额为 0。
4. BOM 母件金额为 0，不参与分摊；BOM 子件按标准金额参与分摊。
5. 整单折扣、行折扣、满减同时存在时，订单总价 = 各行最终金额之和（含赠品 0）。

## 4. 满减
1. 满足满减规则时总价扣减对应金额。
2. 命中提示展示“整单减免 ¥金额”。
3. 未达阈值时不扣减、不提示。

## 5. 命中提示
1. 命中买赠显示“本单因满足【规则名称】，赠送 编码 名称 ×数量”。
2. 多条规则命中时提示条逐行列出。
3. 未命中时不显示提示条。

## 6. 保存与提交
1. 保存草稿前自动刷新：回读订单，赠品与最终金额正确持久化。
2. 提交前自动刷新并进入审批流，状态变为待审批/自动审批。
3. 编辑已有草稿并修改数量后保存，赠品按新数量刷新且无重复。

## 7. 回归
1. 普通单品（无促销、无折扣）订单金额正确。
2. BOM 订单展开、出库只含子件、订单一次完成。
3. Console 无红色错误，网络无 500/非预期 4xx。
4. `node tools/smoke-test.cjs` 通过。
