# DMS v4.0.0-bugfix.8 测试场景

## 1. 促销赠品
1. 新建销售订单，选择经销商和 PRD-J002。
2. 数量录入 2，确认明细出现 PRD-J003 赠品 5 个，赠品数量/折扣/删除不可编辑，行最终金额为 0。
3. 数量改为 6，确认赠品数量自动变为 15，订单总价不含赠品金额。
4. 保存草稿后重新进入编辑页，确认赠品行仍存在且锁定。
5. 提交订单并审批，审批后生成出库，确认赠品作为实物出库。

## 2. 满减分摊
1. 对命中的满减规则录入目标产品。
2. 保存并查看订单明细，确认促销折扣列按计费行分摊。
3. 订单最终金额、税额和各明细行金额一致，赠品和 BOM 母件不作为分摊基数。

## 3. BOM 出库
1. 新建销售订单选择 BOM PRD-J001，数量 1。
2. 确认页面展示母件和子件，母件金额为 0，子件金额合计为订单金额。
3. 提交并审批后点击“生成销售出库”。
4. 确认出库单不包含 PRD-J001 母件，只包含子件/赠品，订单状态为 COMPLETED。

## 4. 销退金额
1. 从已完成出库单创建销退单。
2. 确认明细显示平摊单价、本次退货行总价和汇总退货金额。
3. 修改本次退货数量，确认行总价和汇总金额同步变化。
4. 暂存后刷新进入只读页，确认单价、行总价、汇总金额一致。
5. 提交审批，确认后端金额不随前端篡改变化。

## 5. UI 与回归
1. 销售订单新增/编辑页经销商字段宽度足够，长名称可见且布局整齐。
2. 销退原发货单区域在编辑和只读页均紧凑显示。
3. 浏览器 Console 无红色错误，网络无 500。
4. 运行 `npm run test:all -- --module=orders`、`node tools/smoke-test.cjs`。
5. 定向深度脚本 `node automation_test/e2e/specs/12-orders-promo-bom-return.spec.js` 必须通过，并验证订单详情真实路由 `/orders/:id` 显示赠品标签。
6. 深度 E2E 结束后必须自动清理本次创建的订单、销退、出库和审批记录；回读最新列表确认无新增临时单号。
