## 一、项目概述

### 1.1 系统定位
DMS（Dealer Management System）通用经销商管理系统，面向**医疗器械 / 快消 / 零售**行业厂商+经销商两级用户，覆盖从**合同授权→订单→审批→库存→手术报台→返利→报表**的全生命周期管理，支持多租户 SaaS 模式。

### 1.2 核心用户（租户类型）
| 租户类型 | 典型用户 | 关注功能 |
|---------|---------|---------|
| 厂家(MFR) | 厂商管理员/销售/财务/仓库 | 产品主数据、经销商授权、全链路订单审批、全租户报表、手术报台、审批流配置 |
| 经销商(DEALER) | 经销商老板/销售/仓库 | 自己的库存、销售下单、采购单、退货、报台、业绩报表 |
| 平台后台 | 平台运营/审计/超级管理员 | 开通租户、全局字典、菜单配置、跨租户日志审计、产品对码 |

### 1.3 登录信息（测试环境）
详见 `DMS登录信息手册.md`。测试环境域名 `dms-dev.mysolmed.com`（→ 43.128.145.141，2026-08-28 启用；裸域名访问自动 302 到 `/dms/`）：
- **业务前台PC**: `http://dms-dev.mysolmed.com/dms/` → `admin / Sh123456`（租户default，厂商超级管理员；也可用 sys_admin / Dms@123456）
- **移动端H5**: `http://dms-dev.mysolmed.com/dms/mobile/login` → 同上
- **平台后台**: `http://dms-dev.mysolmed.com/dms/admin/` → `admin / Sh123456`（平台超级管理员，token与业务前台隔离）
- IP 直连 `http://43.128.145.141/...` 行为与域名一致；SSH/运维仍使用 IP。

### 2.1 多租户隔离策略
- **数据层**：所有业务表带 `tenant_code` 字段，JPA/Hibernate 与 MyBatis-Plus 查询统一注入租户条件（TenantContext + MVC `TenantInterceptor` 设置租户上下文）
- **应用层**：登录成功后 `tenant_code` 写入JWT claims，后端拦截器解析放入ThreadLocal
- **安全层**：AOP切面校验当前用户是否有权访问目标租户资源（403拦截）
- **平台后台**：`@AdminTenantIsolation` 注解可豁免，允许超级管理员跨租户查询审计日志

## 三、功能模块架构（与测试场景14章对应）

### 3.1 十大业务模块 + 3大支撑模块

| 模块 | 核心表（简） | 核心业务流 |
|------|-------------|-----------|

| 5.库存业务 | stock, goods_issue, goods_receipt, stock_move, stock_adjust | QUALIFIED/PENDING/DEFECTIVE 三态；批次+序列号+UDI；临期预警；库存调整需审批 |
| 6.手术与营销 | surgery_report, surgery_report_item, promotion, promotion_rule | 经销商→医院→医生→患者→植入产品明细+附件；促销引擎（满减/买赠/折扣） |

## 四、核心数据库表（关键字段）

### 4.1 全局基础表
| 表名 | 关键字段 | 状态枚举 |
|------|---------|---------|
| `tenant` | tenant_code(唯一), name, type(MFR/DEALER), domain, logo, status, storage_used | ACTIVE/FROZEN/CREATING |
| `user_account` | account, password_hash, name, tenant_code, role_id, type, email, phone, status, fail_count, lock_until | ACTIVE/LOCKED/DISABLED |
| `role` | code, name, tenant_code, description, status, permission_codes(JSON) | ACTIVE/DISABLED |

### 4.2 产品体系
| 表名 | 关键业务字段 |
|------|-------------|
| `product` | product_code(唯一+租户内唯一), name_cn, **name_en**, product_type(耗材/设备/试剂), category_id(关联产品分类树), spec, unit, ref_price, tax_rate(default 0.13), **udi_trace(BOOL是否UDI追溯)**, **serial_no_mgmt(BOOL是否序列号管理)**, **expire_warn_months(default 3临期预警月数)**, **safety_stock(default 10安全库存)**, **min_order_qty(default 1最小订购量)**, status(ACTIVE启用/INACTIVE停用) |
| `product_category` | 自关联parent_id形成树，支持多级分类 |
| `product_price` | product_id, dealer_id(可NULL=全局价), valid_from, valid_to, price, type(PURCHASE采购价/AGREEMENT协议价/PROMOTION促销价) |
| `product_line` | 产品线：code, name, manager_id, status |
| `package_level` | 包装层级：product_id + level(1=最小单位/2=中盒/3=箱) + qty_per + barcode(UDI条码) |
| `product_combo` | 产品组合：combo_id + component_product_id + qty + is_main(主次件标记) |

### 4.3 订单&库存
- **sales_order**: so_no(自动生成,规则=SO+yyyyMMdd+4位流水), type, dealer_id, warehouse_id, tax_amt, actual_amt, **promotion_id(命中的促销规则,可NULL)**, **price_adjustment(促销减免金额)**, status(DRAFT→PENDING→APPROVED→SHIPPING→COMPLETED→CANCELLED/REJECTED), approved_by, approve_at
- **order_item**: order_id, product_id, qty, unit_price, subtotal, **batch_no**, **serial_no**, **expire_date**, **stock_status(QUALIFIED/PENDING)**
- **stock**: warehouse_id, product_id, batch_no, serial_no, stock_status(QUALIFIED合格/PENDING待检/DEFECTIVE不合格), qty, expire_date, source_type, tenant_code(多租户)
- **goods_issue**: gi_no, ref_order_id, ref_order_type(SALES_ORDER/TRANSFER), warehouse_id, status(DRAFT→PENDING→SHIPPED→COMPLETED), actual_ship_at, **pick_list_json(拣货明细按批次序列号)**
- **goods_receipt**: gr_no, ref_order_id, ref_order_type(PURCHASE_ORDER/SALES_RETURN), warehouse_id, **inspection_required(BOOL是否待检)**, status(DRAFT→INSPECTING→QUALIFIED/DEFECTIVE→COMPLETED)
- **stock_move**: sm_no, from_warehouse_id, to_warehouse_id, **from_status, to_status(支持跨状态移动)**, status
- **stock_adjust**: sa_no, warehouse_id, reason(盘点差异/报损/报溢/其他), **before_qty, after_qty, delta_qty**, approval_status(PENDING→APPROVED→REJECTED)

### 4.4 审批流（扩展4子模块）
- `approval_flow_def`: 名称, 业务类型(sales_order/contract/surgery/purchase_order/stock_adjust...), 版本, 优先级, 驳回策略(REJECT_TO_START/BACK_TO_PREV)
- `approval_instance`: 关联业务单据id+type, 当前节点code, status, submitter
- `approval_node_instance`: 节点code, 审批人, status(PENDING/APPROVED/REJECTED/SKIPPED), 审批意见, 代理人(如有), arrived_at, handled_at(用于超时计算)
- **approval_delegate**(新增补充): delegator_id, agent_id, biz_types(JSON数组范围), valid_from, valid_to, status(ACTIVE/EXPIRED/REVOKED)
- **approval_monitor**(新增补充): 关联instance_id, timeout_threshold_h, warning_sent_count, last_warning_at, force_skip_by(平台超级管理员可强制跳过)

### 4.5 促销引擎
- `promotion`: name, type(FULL_REDUCTION满减/BUY_GIFT买赠/DISCOUNT折扣), priority, valid_from, valid_to, status, min_order_amt(适用门槛)
- `promotion_rule`: promotion_id + rule_json(满减={"threshold":10000,"reduce":500}; 买赠={"buy_qty":10,"gift_product_id":X,"gift_qty":1}; 折扣={"rate":0.9})
- 命中优先级：DISCOUNT折扣 > BUY_GIFT买赠 > FULL_REDUCTION满减（同一SO只命中最高优先级一条）

### 4.6 手术报台（移动端重点模块）
- `surgery_report`: report_no, dealer_id, hospital_id, department, surgeon_name, patient_name(脱敏存储), surgery_date, status, attachments(JSON图片数组)
- `surgery_report_item`: report_id, product_id, qty, **serial_no(扫码输入)**, **batch_no**, used_position(植入部位备注)

## 五、核心业务流程（最易出Bug的链路，详见测试文档INT-001~020）

**基础链路10条（v3.11.0原版）**：
1. **完整销售闭环**: 授权生效→SO建单→经理审批→财务审批→出库草稿→发货→库存扣→报台→报表（INT-001）
2. **完整采购闭环**: PO建单→审批→收货入库→QUALIFIED增加→可销售（INT-002）
3. **合同→授权→订单**: 合同审批ACTIVE→自动生成授权→下单前置校验命中（INT-008）
4. **审批委托链路**: 原审批人设委托→代理人看到待办→审批显示代理人名（INT-005）
5. **库存并发保护**: 出库串行化，绝不允许超卖后负数库存（INT-007）
6. **销退闭环**: SO完成→销退申请→审批→收货入库（原批次序列号退回原状态）→应收冲减
7. **采退闭环**: PO收货→采退申请→审批→出库→应付冲减
8. **手术报台→库存扣减**: 报台提交→关联发货单/或直接扣减→序列号使用状态=已植入
9. **安全库存预警→采购建议**: 库存查询触发预警→工作台推送→一键生成采购草稿
10. **产品对码→订单传输**: 厂家编码→平台标准码→经销商编码→三方对码成功后订单通过API自动传输

**新增集成链路10条（v3.11.1附录D补充）**：
11. **促销引擎→SO→返利闭环**: 促销规则配置→SO建单命中自动减免→报表actual_amt扣减→返利按actual_amt×比例（INT-011）
12. **UDI追溯+序列号→出库扫码强制**: 产品开启序列号+UDI→销售出库必须逐个扫码→漏扫无法保存→报表可按序列号追溯全链路（INT-012）
13. **临期预警月→库存查询红黄提示**: expire_warn_months=3→stock.expire_date距今日≤3月=黄色；≤1月=红色；过期=灰色禁用出库（INT-013）
14. **产品停用→全链路阻断**: product.status=INACTIVE→SO/PO新建无法选择；未完成单据拦截继续操作；现有库存保留但无法新出库（INT-014）
15. **库存调整审批→审计留痕**: stock_adjust提交→审批流→通过后变动库存+写入adjust_log（调整前后数量+原因+审批人），禁止无审批改库存（INT-015）
16. **审批超时→监控中心自动催办**: 节点配置24h超时→approval_monitor检查→邮件+站内信催办→催办3次自动升级上级→可强制跳过（INT-016）
17. **销售岗位→数据行级隔离**: sales_position绑定region/dealer_list→列表页只可见自己负责经销商的单据/报表；越权访问返回空列表非403（防泄露存在性）（INT-017）
18. **角色权限→按钮级三层控制**: ①菜单显隐（路由级）②顶部按钮显隐（新建/导入/导出/删除）③行操作按钮显隐（编辑/删除/查看）+ 后端API权限码二次校验（INT-018）
19. **账龄+信用额度→SO下单拦截/特批**: 应收>授信→拦截；>90天逾期→二次拦截；财务临时提额7天→有效期后自动失效；回款先冲抵最长账龄（INT-019）
20. **合同到期→授权自动过期→订单前置拦截**: 每日03:00定时任务检查→合同到期→授权status=EXPIRED→下单红色拦截；续签合同审批通过→授权重新激活（INT-020）

## 六、非功能设计

| 维度 | 指标 |
|------|------|
| 性能 | 列表1000条≤1s；1年报表≤3s；登录≤2s |
| 并发 | 100并发登录无5xx；50并发建单不超卖不重复 |
| 兼容性 | Chrome/Edge/Firefox/Safari；分辨率1920-1366；移动端iPhone12/Samsung S20/iPad |
| 安全 | 密码Bcrypt加盐+9次锁定；JWT过期2h+刷新7d；SQL注入/XSS拦截器；敏感操作全量审计 |
| 多租户 | 每操作SQL必带tenant_code；越权API返回403；平台后台token不互通 |
| 可观测 | 操作日志+API调用日志+邮件日志+登录审计+错误堆栈聚合 |
