## 四、PC 端 UI 测试结果

### 4.1 页面可访问性测试（通过 browser-use）

所有菜单页面通过 `/m/{key}` 路由均可正常访问，未出现 404。但 **所有 PC 端列表页均显示"暂无数据"**，尽管后端 API 确认有数据。移动端则能正常显示数据。

**根因分析**: PC 端 ModuleView/CrudView 组件在请求列表数据时可能触发了 403 权限拦截（browser-use 测试中观察到"没有权限访问该资源"提示），或前端请求参数与后端不匹配。移动端使用独立的 API 调用逻辑，不受此问题影响。

## 七、发现的 Bug 清单

### Bug-001: PC端所有列表页显示"暂无数据"

- **严重程度**: P0（阻断）
- **描述**: 通过 browser-use 访问 PC 端所有业务模块（/m/*），列表均显示"暂无数据"，但后端 API 确认有数据（如产品200条、订单701条）
- **可能原因**: 
  1. 前端请求列表时触发 403 权限拦截（browser-use 观察到"没有权限访问该资源"提示）
  2. 前端 ModuleView/CrudView 组件请求参数与后端不匹配
  3. 可能是 browser-use 浏览器的 cookie/token 与正常浏览器不同
- **影响范围**: 所有 PC 端业务模块
- **备注**: 移动端能正常显示数据，说明后端 API 正常

### Bug-002: 移动端仪表盘报"系统内部错误"

- **严重程度**: P1
- **描述**: 访问 /mobile/dashboard 时显示"系统内部错误"，图表未渲染
- **可能原因**: 后端 /api/dashboard/overview 返回的数据格式与移动端期望的不一致

### Bug-003: 合同申请API返回500

- **严重程度**: P1
- **描述**: GET /api/contract-apps 返回 HTTP 500
- **影响**: 合同申请模块无法正常使用

### Bug-004: 订单追溯报表API返回500

- **严重程度**: P1
- **描述**: GET /api/reports/order-trace 返回 HTTP 500
- **影响**: 订单追溯报表无法正常使用

### Bug-005: 后台菜单配置API返回500

- **严重程度**: P1
- **描述**: GET /api/admin/menus 返回 HTTP 500
- **影响**: 后台菜单管理无法正常使用

### Bug-006: 未实现API返回500而非404

- **严重程度**: P2
- **描述**: 14个未实现的API端点均返回 HTTP 500 而非 404
- **影响**: 前端无法区分"接口未实现"和"服务端错误"
- **说明**: v3.6.x 曾修复 NoResourceFoundException→404，但测试环境可能未部署最新代码
