# DMS 服务器迁移/复刻清单

## 1. 新服务器准备

- 准备 Linux 服务器，建议 Ubuntu 22.04+，磁盘不少于 40 GB，内存不少于 2 GB。
- 安装 Docker 和 Docker Compose 插件，启动 Docker 并设置开机自启：
  - `systemctl enable --now docker`
- 开放端口：
  - 生产前端：`8081`
  - 生产后端：`8080`
  - 测试前端：`8083`
  - 测试后端：`8082`
  - PostgreSQL：`5432`、`5433`
  - Redis：`6379`、`6380`
  - MinIO：`9000`、`9001`、`9002`、`9003`
  - Mock：`9090`
  - 宣传页：`8084`
  - 如经 Nginx 统一入口访问，再开放 `80`。
- 创建部署目录：`/opt/dms`。

## 2. 迁移代码和静态文件

- 复制以下目录到新服务器：
  - `/opt/dms/frontend-vue`
  - `/opt/dms/dms-test/frontend-dist`
  - `/opt/dms/dms-test/admin-dist`
  - `/opt/dms/brochure`
  - `/opt/dms/mocks`
  - `/opt/dms/scripts`
  - `/opt/dms/docker-compose.yml`
  - `/opt/dms/docker-compose.test.yml`
- 检查前端、Nginx、后端配置中的 IP、域名、端口、API 地址，替换为新服务器地址。
- 确认生产前端容器使用的是当前 `dist` 内容，测试前端容器使用的是当前 `frontend-dist/dist` 和 `admin-dist` 内容。

## 3. 迁移数据库和对象存储

- 迁移生产 PostgreSQL：
  - 源容器：`dms-postgres`
  - 数据库：`dms`
  - 用户：`dms`
  - 数据卷：当前生产库挂载的 Docker volume
- 迁移测试 PostgreSQL：
  - 源容器：`dms-test-postgres`
  - 数据库：`dms_test`
  - 用户：`dms`
  - 端口：`5433`
- 迁移 Redis：
  - 生产容器：`dms-redis`
  - 测试容器：`dms-test-redis`
- 迁移 MinIO：
  - 生产容器：`dms-minio`
  - 测试容器：`dms-test-minio`
  - 同步 bucket、access key、secret key 和持久化卷数据。
- 迁移方式二选一：
  - 冷迁移：停源库后用 `pg_dump`/`pg_restore` 导出导入，并复制 Redis/MinIO volume。
  - 卷迁移：停止新旧容器后直接复制 Docker volume 数据目录。
- 迁移后校验：表数量、租户、用户、基础数据、附件文件、业务数据条数。

## 4. 迁移或重建镜像

- 可直接导出导入现有镜像：
  - `dms-backend:latest`
  - `dms-backend-test:latest`
  - `dms-frontend-vue:latest`
  - `dms-frontend-test:latest`
- 也可从源码重建：
  - 后端：使用 `backend/Dockerfile.aliyun` 或服务器实际 Dockerfile 构建。
  - 生产前端：在 `/opt/dms/frontend-vue` 基于 `Dockerfile.dist` 构建。
  - 测试前端：使用 `dms-frontend-test:latest` 或重建后通过 `docker cp` 更新静态文件。
- 基础镜像需要可用：
  - `postgres:14-alpine`
  - `postgres:14`
  - `redis:7-alpine`
  - `nginx:1.25-alpine`
  - `minio/minio:latest`
  - `wiremock/wiremock:3.3.1`

## 5. 启动容器

- 创建 Docker 网络：`dms-net`。
- 按依赖顺序启动：
  - PostgreSQL、Redis、MinIO
  - 后端
  - 前端/Nginx
  - Mock、宣传页等辅助服务
- 所有 DMS 容器设置：
  - `--restart unless-stopped`
- Docker 服务设置开机自启：
  - `systemctl enable docker`

## 6. 必改配置

- 数据库连接地址、端口、库名、账号、密码。
- Redis 地址、端口、密码。
- MinIO endpoint、access key、secret key、bucket。
- 后端 `SPRING_PROFILES_ACTIVE`、跨域、JWT、文件访问地址。
- 前端 API base URL、移动端地址、静态资源地址。
- Nginx 反向代理目标和端口。
- 如有短信、邮件、企业微信、飞书、ERP/WMS/CA 等外部集成，同步替换回调地址和密钥。

## 7. 验收检查

- 容器全部运行：`docker ps`。
- 健康检查通过：
  - 生产前端：`http://新服务器IP:8081/`
  - 测试前端：`http://新服务器IP:8083/`
  - 生产后端：`http://新服务器IP:8080/actuator/health`
  - 测试后端：`http://新服务器IP:8082/actuator/health`
  - 宣传页：`http://新服务器IP:8084/`
- 使用 `default / admin / Sh123456` 登录生产和测试环境。
- 验证菜单、订单、库存、报表、附件上传下载、移动端页面。
- 验证 Flyway 已执行到最新版本，后端启动日志无数据库错误。
- 重启服务器后确认所有 DMS 容器自动恢复。

## 8. 切换和回退

- DNS/安全组/负载均衡切换到新服务器前，先完成数据最终同步。
- 切换前停止旧环境写入，避免迁移后产生增量数据丢失。
- 保留旧服务器和旧镜像，至少保留一个回滚窗口。
- 回退方式：将流量切回旧服务器，并恢复迁移期间新增数据。

## 附录 A：历史部署要点归档

> 说明：本附录合并自旧版 Vue 前端部署指南、Docker Compose/Seed 部署方案和移动端 v3.9.0 部署记录；若与正文冲突，以正文最新迁移清单为准。

### A.1 端口和目录历史基线

- 生产前端容器：`dms-frontend-vue`，端口 `8081`，Nginx 代理后端 `dms-backend:8080`。
- 测试前端容器：`dms-test-frontend`，端口 `8083`，Nginx 代理后端 `172.17.0.1:8082`。
- 测试后端容器：`dms-test-backend`，端口 `8082`。
- 生产后端容器：`dms-backend`，端口 `8080`。
- 常见挂载目录：`/opt/dms/frontend-vue`、`/opt/dms/dms-test/frontend-dist`、`/opt/dms/dms-test/admin-dist`、`/opt/dms/brochure`、`/opt/dms/mocks`、`/opt/dms/scripts`。

### A.2 前端产物替换流程

1. 本地在 `frontend-vue/` 执行 `npm run build`，确认 `dist/` 包含最新 PC 与移动端资源。
2. 打包 `dist/` 为 zip，上传到服务器临时目录。
3. 替换前先备份旧产物，例如：`cp -a dist dist.bak.$(date +%Y%m%d-%H%M%S)`。
4. 使用清空目录后解压的方式替换，避免旧 hash chunk 残留。
5. `docker restart dms-test-frontend` 或 `docker restart dms-frontend-vue`。
6. 验证：首页、登录、关键 API、移动端路由（如 `/mobile/home`、`/mobile/dashboard`）、`/assets/*.js` chunk 均返回 200。

### A.3 回滚要点

- 测试前端：从 `dist.bak.<timestamp>` 恢复后重启 `dms-test-frontend`。
- 生产前端：保留上一版本镜像 tag，例如 `dms-frontend-vue:backup-<timestamp>`，回滚时停止当前容器并用旧镜像重新启动。
- 后端：至少保留上一版本可运行 jar 或镜像；回滚后检查 Flyway 版本、健康检查和核心接口。

### A.4 Docker Compose / Seed 历史说明

- 基础服务包括 PostgreSQL、Redis、MinIO、Nginx、后端、前端、Mock 服务。
- 首次启动通过 Flyway 自动迁移，Seed 数据用于演示和测试。
- 演示账号以最新 `docs/DMS登录信息手册.md` 为准，历史文档中出现的 `admin / Sh123456`、`D00001_01 / Sh123456` 可能因首次登录强制改密或租户隔离而变化。
- 阿里云演示环境建议服务器至少 Ubuntu 22.04+、40 GB 磁盘、2 GB 内存；磁盘不足时优先清理 Docker 构建缓存、旧镜像和无用 volume。

### A.6 常见故障快速处理

- 端口冲突：更换宿主机映射端口或停止占用进程。
- 镜像构建失败：先执行 `df -h /` 检查磁盘，再执行 `docker system prune -af` 清理缓存。
- 页面无法访问：检查容器状态、防火墙/安全组、Nginx 代理目标和后端健康检查。
- API 401/403：确认登录环境、租户类型、token 和 Nginx 是否放行对应 `/api/` 路径。
