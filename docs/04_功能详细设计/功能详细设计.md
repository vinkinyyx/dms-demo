**当前版本**: v3.8.2

## 变更日志

### v3.8.2 (2026-08-02) — 接口调用日志模块（入站+出站）

#### 一、目标
- 记录所有「外部系统调用 DMS」的入站请求，以及「DMS 调用外部系统」的出站请求，统一落库、可查询、可扩展（未来对接系统会增多）。
- 与既有业务操作日志 `op_log` 解耦：`op_log` 偏业务审计与 HTTP 跟踪，`api_call_log` 专注接口契约层面的调用记录（请求/响应体、状态码、耗时、对端系统）。

#### 二、表结构（Flyway V45 `api_call_log`）
- 关键字段：`direction`(IN/OUT)、`system`(ERP/WMS/HR/UDI/CA/第三方)、`endpoint`(业务端点编码)、`http_method`、`url`、`path`、`status_code`、`biz_code`、`success`、`client_ip`、`user_id/username`、`app_key`、`request_headers/request_body/response_body`、`error_msg`、`spent_ms`、`started_at/finished_at`、`request_id/trace_id`。
- 索引：started_at、direction+started_at、system+started_at、tenant_id+started_at、request_id。

#### 三、入站记录
- `ApiCallLogFilter`（Spring `OncePerRequestFilter`，@Order(60)，在 JwtFilter 之后）拦截所有 `/api/**`。
- 用 `CachedBodyHttpServletResponse` 包装响应以捕获响应体，链结束后把缓冲内容回写真实响应，再异步写库；请求体复用既有 `ContentCachingFilter` 的缓存。
- 解析 JSON 响应中的 `code` 作为 biz_code；success = HTTP 2xx 且 (biz_code 为空或 0)。
- 排除 actuator/swagger/api-docs 以及日志查询自身路径，避免噪音；请求/响应体截断 32KB。

#### 四、出站记录（可扩展组件）
- `ApiCallLogService.callExternal(ExternalCall)` 基于 JDK `HttpClient` 发起外呼，自动记录 OUT 日志：成功记状态码与响应体，异常记 error_msg。
- 字段 system/endpoint/url/method/headers/body/appKey 由业务侧传入；自动带入当前租户/用户/requestId。
- 未来新增对接系统只需复用该方法，不重复实现日志逻辑；也可单独调用 `recordOutbound(entry)` 记录已有 HTTP 客户端的调用。

#### 五、查询接口与权限
- `GET /api/admin/api-call-logs`：分页 + direction/system/method/statusCode/keyword/startTime/endTime 过滤，size 上限 200。
- `GET /api/admin/api-call-logs/{id}`：详情（请求头、请求体、响应体、错误）。
- 仅 admin 可访问（沿用 `OpLogAdminController` 的 admin 判定）。

#### 六、前端
- 新增 `ApiCallLog.vue`，路由 `/api-call-logs`，菜单位于「用户与权限」组；支持筛选、成功/失败标签、耗时展示、详情抽屉。
- 仅 PC 端，移动端不动。

### v3.8.1 (2026-08-02) — 销退/采退改造 + 库存查询接口

#### 一、业务方向（关键决策）
- **销退订单 RS**：客户退货给我方。审批通过后自动生成 **RGR 销退入库单**（库存 +），入库库存状态为 **PENDING 待检**。状态机 DRAFT→SUBMITTED→APPROVED→RECEIVING→COMPLETED（→REJECTED/CANCELLED）。
- **采退订单 RP**：我方退货给供应商。审批通过后自动生成 **RGI 采退出库单**（库存 −），出库**不限库存状态**（合格/不合格/隔离均可出）。状态机 DRAFT→SUBMITTED→APPROVED→SHIPPING→COMPLETED（→REJECTED/CANCELLED）。
- 这是对旧逻辑方向的反转（旧版销退减库存、采退加库存均已纠正）。
- 仅改 PC 端，移动端不动。

#### 二、销退订单（Sales Return）
- 领域：`com.dms.order.controller.SalesReturnController`，基路径 `/api/sales-returns`，操作 `orders` 表 `is_red=true` 的红字销售单。
- 单据号前缀 `RS`；入库单 `RGR`。
- **强约束**：必须关联已发货发货单（`ref_sales_out_id`，状态 PARTIAL_SHIPPED/COMPLETED）；通过 `/api/sales-returns/shipped-outs` 与 `/shipped-outs/{id}/lines` 带出可退明细及 `returnableQty=已发-已退`；数量只能改小、行可删除；`returnReason` 退货原因必填；序列号支持批量粘贴。
- 审批通过：`AutoDocGenerator.createReceiptForSalesReturn` 生成 RGR 草稿（`ref_doc_type='sales_return'`，`is_red=true`），明细拷贝自销退单行（`order_lines`，列名 `sub_total`）。
- 入库进度回写：`ReceiptBatchService` 在确认收货/取消剩余时，若 `ref_doc_type='sales_return'` 调用 `syncSalesReturnStatus`，按 RGR 明细整体进度把销退单置为 RECEIVING/COMPLETED。
- 入库库存状态固定写 `PENDING`（待检）。

#### 三、采退订单（Purchase Return）
- 领域：`com.dms.order.controller.PurchaseReturnController`，基路径 `/api/purchase-returns`，操作 `purchase_orders` 表 `is_red=true` 的红字采购单。
- 单据号前缀 `RP`；出库单 `RGI`。
- **不限制原单与数量**，出库仓库必填，批次/序列号从库存选择。
- 审批通过：`AutoDocGenerator.createSalesOutForPurchaseReturn` 生成 RGI 草稿（`source_po_id=采退单id`，`is_red=true`），明细拷贝自采退单行（`purchase_order_lines`，列名 `subtotal`）。
- 出库进度回写：`SalesOutBatchService` 透传 `isRed`，确认发货时调用 `syncPurchaseReturnStatus`，按 RGI 进度把采退单置为 SHIPPING/COMPLETED。
- **库存状态不限**：`deductBatch`/`deductSerial` 在 `isRed=true` 时条件为 `qty >= ?`（不附加 `stock_status='QUALIFIED'`）；校验 `validateLoadedLines` 对红字单跳过合格库存限定，仅校验在库数量足够。

#### 四、状态机与取消联动
- 销退：DRAFT 可编辑/删除/提交/驳回；APPROVED 可取消（级联取消未执行的 RGR DRAFT/APPROVED/PARTIAL_RECEIVED 及其 DRAFT 子单）；已有收货记录不允许取消。
- 采退：DRAFT 可编辑/删除/提交/驳回；APPROVED 可取消（级联取消未执行的 RGI DRAFT/APPROVED/PARTIAL_SHIPPED 及其 DRAFT 子单）；已有发货记录不允许取消。
- 完整对齐采购订单/销售订单/收货入库/销售出库四模块的子单、部分收发、剩余取消能力。

#### 五、库存查询接口
- `POST /api/inventory/query`（`InventoryController`）。
- 入参：`productCodes`（必填，物料编码数组，支持多物料）、`warehouseId`（选填）。
- 返回：按物料汇总 `totalQty`，**不展开**批次/序列号/库存状态；`items` 内含 productCode、productName、totalQty，外加 `totalCount`。

#### 六、数据库变更（Flyway V44）
- `orders`：新增 `ref_sales_out_id`、`return_reason`。
- `order_lines`：新增 `batch_no`、`serial_no`。
- `purchase_orders`：新增 `return_reason`。
- `sales_outs`：新增 `source_po_id`。
- 所有新列向后兼容，存量数据不受影响。

#### 七、列名事实（避免重复踩坑）
- `order_lines` 用 `sub_total`，含 `batch_no/serial_no/created_at/updated_at`。
- `purchase_order_lines` 用 `subtotal`（无下划线），含 `created_at` 但**无 `updated_at`**。
- `receipt_lines` 无 `seq` 列；`receipts` 含 `source_po_id/ref_doc_type/ref_doc_id/is_red/auto_created`，无 `source_order_id`。
- `sales_out_lines` 用 `subtotal`；`sales_outs` 含 `source_order_id/source_po_id/is_red/auto_created/warehouse_id`。

#### 八、前端
- 新增 `SalesReturnEdit.vue`、`PurchaseReturnEdit.vue`，路由 `sales-return-edit/:id`、`purchase-return-edit/:id`。
- `modules.js` 注册 sales-returns/purchase-returns 模块及 `createPath/detailPath`，列表按钮收敛（maxActions=2，其余进编辑页）。
- `CrudView.vue` 支持 `detailPath`，点击单号跳专用编辑页。

### v3.7.0 (2026-07-25) — 主数据补齐（W1-W2）

#### 一、产品线 / 包装层级 / 组套主数据

#### 1.1 模块划分
- **领域归属**：`com.dms.masterdata`（主数据领域）
- **新增 Service**：`ProductLineService`、`ProductPackageLevelService`、`ProductBundleService`
- **新增 Controller**：`ProductLineController`、`ProductPackageLevelController`、`ProductBundleController`
- **审计集成**：所有写操作通过 `@OperationLog` 注解自动落 `op_log` 表

#### 1.2 关键数据流

**产品线创建流程**：
1. 用户 POST `/api/product-lines` → JWT 拦截器提取 tenantId
2. Controller 注入 `ProductLine` entity → 调用 Service
3. Service 校验：编码唯一性 (40901) + 层级范围 1-3 (40001)
4. 自动补充：tenantId、status=active、sortOrder=0、updatedAt
5. 保存 → 自动标记 audit log

**组套创建流程**：
1. 用户 POST `/api/product-bundles` → 携带 parentProductId
2. Service 校验父产品存在 (40401) + 编码唯一性 (40901) + 定价方式合法性 (40001)
3. OVERRIDE 模式强制要求 bundlePrice (40001)
4. 保存主表 → 自动标记产品 `is_bundle=true` + `bundle_id=新ID`
5. 子表添加：`addLine()` 校验子产品存在 + 不可包含自身 (40001) + 子件类型 (40001)
6. 最后一固定件不可删除 (40001)

#### 1.3 模块依赖关系
```
ProductLineController → ProductLineService → ProductLineRepository
ProductPackageLevelController → ProductPackageLevelService → ProductPackageLevelRepository → ProductRepository (cross-domain)
ProductBundleController → ProductBundleService → ProductBundleRepository + ProductBundleLineRepository → ProductRepository
```

### v3.6.2 (2026-07-24) — 全链路操作日志采集 + bugfix-2026-07-24 集成

#### 一、全链路操作日志采集（v3.6.2 R1-R7）
**需求背景**：用户要求记录所有操作日志、调用日志到日志文件，支持服务器存储和本地下载

**后端代码变更**：
1. **数据库表设计**：新增 `op_log` 表（Flyway V27），字段包括 `request_id`、`layer`（HTTP-IN/HTTP-OUT/BUSINESS/EXCEPTION）、`http_method`、`path`、`status`、`spent_ms`、`user_id`、`username`、`tenant_id`、`ip`、`method`、`biz_type`、`biz_id`、`action`、`remark`、`request_body`（脱敏）、`response`、`stack`、`created_at`

10. **业务层操作日志集成**：修改 `OperationLogAspect.java`，新增 `@Autowired OperationLogRecordService`，在记录原有 operation_log 同时，也写入 op_log 表的 BUSINESS 层

## 关键数据流

### 销售订单业务闭环 (v3.4+)

```
[销售] 创建订单(status=DRAFT, code=SO-xxx)
   │ 前端：选完经销商后，产品选择器只显示授权分类内的产品
   ↓
[销售] submit(status=SUBMITTED)
   ↓
[经理] approve(status=APPROVED, approved_at=now)
   │
   │ 触发 AutoDocGenerator.createSalesOutForOrder()
   ↓
[系统] 自动创建 sales_outs(code=CK-xxx, status=DRAFT, auto_created=true, source_order_id)
   │ 拷贝订单明细到 sales_out_lines
   ↓
[仓管] 进入销售出库页 → 看到 DRAFT 单
   │
   ├── execute → 弹窗填批次/序列号 → 校验库存 QUALIFIED → 扣减 → status=COMPLETED
   └── cancel-draft → status=CANCELLED（不动库存）
```

### 采购订单业务闭环

```
[采购] 创建采购订单(code=PO-xxx)
   ↓ approve → 自动创建 receipts(code=RK-xxx, DRAFT)
   ↓
[仓管] 进入收货入库页 → DRAFT 单
   ├── execute → **手工录入**批次/序列号（唯一手填场景）→ 增 PENDING → COMPLETED
   └── cancel-draft
```

### 分次收发货 + 执行明细留痕流程 (v3.4.10 → v3.4.12)

```
[仓管] 打开 RK/CK 草稿 → 收/发货录入子页
   │ 明细行显示：应收/发量 · 已收/发量 · 待处理量(=应收/发−已收/发) · 本次量
   │ 序列号产品 → 拆多行逐件录入(收货手输 / 出库从合格库存多选)，每序列号 qty=1
   ↓
[仓管] 提交本次 execute
   ↓
[后端] OrderApprovalExecutionController.executeReceipt / executeSalesOut
   │ 1) seqBase = SELECT COALESCE(MAX(seq_no),0) FROM *_execution_lines WHERE doc_id=?
   │ 2) 遍历每行的多条子录入(Map<lineId, List<sub>>)
   │    - inventoryOps.change 变更库存(收货增 PENDING / 出库扣 QUALIFIED)
   │    - INSERT *_execution_lines(seq_no=++seqBase, batch_no/serial_no, qty, operator_id, created_at)
   │ 3) received_qty / shipped_qty 累计
   │ 4) 全部收/发完 → COMPLETED；否则 → PARTIAL_RECEIVED / PARTIAL_SHIPPED
   ↓
[详情页] BizDocDetailController 返回 executionLines (join products + users)
   │ 渲染"🔖 收/发货执行记录"：第N次 · 批次 · 序列号 · 数量 · 操作人 · 时间
   └── 第一次收 ABC×5、第二次收 DEF×5 各留一条，不再互相覆盖
```

**设计取舍**：`receipt_lines` 仅保留一行汇总（received_qty 累计），若把多次多批次都塞进这一行，`batch_no` 只能存最后一次的值。因此把"每一笔"下沉到独立的执行明细表，是解决"分次收货详情看不到"的根因方案。

### 单据号生成流程 (v3.4.12)

```
[任意建单] DocNoGenerator.next("PO")
   ↓ @Transactional(REQUIRES_NEW)
[后端] INSERT INTO doc_no_sequences(tenant_id, prefix, date_key, last_seq)
       VALUES(:tid, 'PO', '20260719', 1)
       ON CONFLICT (tenant_id, prefix, date_key)
       DO UPDATE SET last_seq = doc_no_sequences.last_seq + 1
       RETURNING last_seq
   ↓
   String.format("%s-%s-%05d", prefix, date_key, seq)  →  PO-20260719-00001
```

- 原子 UPSERT + 独立事务保证并发下同租户同日单号连续、不撞号
- 前缀体系：PO / RPO / RK / RRK / CK / RCK / SO / RSO（R 前缀为红字单）


### 授权前置过滤流程

```
[前端] 销售订单表单 → dealerId 选择器绑定
              ↓
   产品明细行 → 点击"选择产品"
              ↓
   openPicker('products', callback, { dealerId: 3 })
              ↓
   GET /api/lookups/products?dealerId=3
              ↓
[后端] SELECT DISTINCT p.* FROM products p
       JOIN authorizations a ON a.dealer_id = 3
         AND a.status = 'active'
         AND CURRENT_DATE BETWEEN a.valid_from AND a.valid_to
         AND (a.category_ids = '' OR p.category_id IN split(a.category_ids))
              ↓
   只返回该经销商授权分类下的可下单产品
```

## 关键技术决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 前端 CSS 变量令牌 | 便于 M3 主题一键切换 |
| 2 | 用 native SQL 而非 JPA Sort | 修复 updatedAt 属性映射 500 |
| 3 | 用 CAST() 替代 ::text | Hibernate 会把 :xxx 当参数占位符 |
| 4 | 岗位与账号 UNIQUE 绑定 | 数据权限单一入口 |
| 5 | Auto 建单用 Native SQL | 避免 JPA 级联依赖 Entity 结构 |
| 6 | 单号前缀迁移 UPDATE 而非重建 | 保留 700 测试数据 |
| 7 | 授权过滤下沉到 Lookup | 前端组件单一，无需业务耦合 |
| 8 | 收发货执行明细独立成表 | 一行汇总放不下"多次多批次"，batch_no 会被覆盖；下沉留痕是根因解 |
| 9 | 单据号用 DB 序列表原子自增 | 取代时间戳尾数，保证 PREFIX-YYYYMMDD-连续号且并发不撞号 |
| 10 | 主数据 update 全字段 COALESCE | 部分字段未传时不误清空历史值 |
| 11 | 操作日志复用 audit_logs 表 | 不新增表，通过 resourceType/resourceId 统一时间轴查询 |

## v3.7.6 变更 (2026-07-26)
- **单号规则**:
  - 收货入库: `GR-YYYYMMDD-流水号`, 子单 `GR-YYYYMMDD-流水号-子流水号`
  - 销售出库: `GI-YYYYMMDD-流水号`
  - 采购单 `PO-*`, 销退 `RPO-*` 保持不变
- **状态级联**:
  - 收货子单确认收货完毕/取消剩余 → 收货单 + PO 状态自动 COMPLETED
  - 采购订单 cancel → 关联 DRAFT/APPROVED/RECEIVING/PARTIAL_RECEIVED 收货单一并 CANCELLED
- **审计字段**:
  - PO list 加返回 `auditUserName / auditAt` (users JOIN po.approved_by)
  - 收货子单 `confirmed_at` = 确认收货时刻, 前端卡片展示
- **操作记录**:
  - 所有 5 个 ReceiptBatchController 端点 @OperationLog 记录 businessType=receipt / businessId=receiptId
  - ReceiptEdit.vue 底部展示操作记录表
