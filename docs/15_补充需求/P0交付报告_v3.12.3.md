判断为远程 sshd/后端服务或服务器资源异常，不是本地代码构建问题。需要先恢复服务器 SSH/服务响应后才能部署。

## 五、恢复后部署步骤

### 1. 后端
上传：
- `release-p0/dms-backend-p0.jar`

远程执行：
```bash
docker cp /opt/dms/dms-test/app.jar.new dms-test-backend:/app/app.jar
docker restart dms-test-backend
curl -f http://localhost:8082/actuator/health
```
同时确认容器存在环境变量：
```bash
MAIL_PASSWORD=新的163授权码
```

### 2. 前端
上传并解压：
- `release-p0/frontend-dist-p0.tar.gz` -> `/opt/dms/dms-test/frontend-dist`
- `release-p0/admin-dist-p0.tar.gz` -> `/opt/dms/dms-test/admin-dist`

重建/重启静态容器：
```bash
cd /opt/dms/dms-test
docker build -f Dockerfile.frontend-static -t dms-frontend-test:latest .
docker rm -f dms-test-frontend
docker run -d --name dms-test-frontend --network dms-test_dms-net -p 8083:80 --restart unless-stopped dms-frontend-test:latest
```

### 3. 回归
```bash
python tools/p0-regression/regression_api.py
```
