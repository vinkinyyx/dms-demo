## 一、本次工作概述

本次围绕"全量问题排查 → 修复 → 部署测试环境 → 真实浏览器验证"展开，主要修复：

1. **后端 500 错误修复**
   - 销售订单列表按经销商关键字搜索 500（`SalesOrderService` COUNT 查询缺少 JOIN dealers）
   - 合同列表 500（PostgreSQL TIMESTAMPTZ 列经 Hibernate 返回 `Instant`，不能强转 `OffsetDateTime`，改用统一 `DateFmt.fmt()`）
   - 经销商画像、授权、采购/销退、岗位、促销、跟台报告、用户等列表/详情的查询与字段映射修复
2. **PC 端与移动端统一**
   - 移动端销售订单去除对授权的依赖、补齐订单类型/BOM 结构/折扣填写
   - 移动端审批报错修复
   - `MOrderCreate` / `MOrderDetail` 等大规模重构（计价、BOM、促销、可退量）
3. **查询项生效**：PC 各列表搜索条件全部接入后端查询（经销商、产品、状态、日期等）
4. **前端基础设施**：`CrudView` 通用列表组件、`dict.js` 字典、`reports.js` 报表配置、`order.js` API 等调整
5. **数据库迁移**：新增 `V120__fix_v83_resource_api_paths.sql`，修正资源/API 路径
6. **部署修复**：测试环境 Nginx 容器缺失前端 bind mount 导致三端无法访问，重建容器修复
7. **营销页图片不显示**：`/opt/dms/test/frontend/assets/` 缺少 PNG，从 `brochure-test/assets/` 复制 41 张图片修复
8. **清理**：本地临时脚本 + 测试服务器临时文件/旧容器/旧镜像清理

## 三、服务器端基础设施变更（非代码仓库文件）

以下变更发生在测试服务器 `43.128.145.141`，不属于 git 仓库文件，单独记录：

### 3.1 Nginx 容器重建（修复三端无法访问）
- 问题：`dms-test-nginx` 容器只挂载了 `nginx.conf`，未挂载 `frontend` 静态目录，导致 `/`、`/dms/`、`/dms/admin/` 全部打不开
- 操作：
  ```bash
  docker rm -f dms-test-nginx
  cd /opt/dms/test && docker compose up -d --no-deps nginx-test
  ```
- 验证：真实浏览器确认营销页、移动 H5、平台后台均可打开并登录

### 3.2 营销页图片补全（修复 34 张图全部 404）
- 问题：`/opt/dms/test/frontend/assets/` 中只有 Vue 构建的 JS/CSS，0 个 PNG；`index.html` 引用的 `../assets/XX-xxx-new.png` 全部 404
- 操作：
  ```bash
  sudo cp -n /opt/dms/brochure-test/assets/*.png /opt/dms/test/frontend/assets/
  ```
- 结果：复制 41 个 PNG；浏览器验证 34 个 `<img>` 全部 `complete=true`、`naturalWidth=2880`、无 broken
- 注意：该批图片源自本地 `DMS产品宣传手册/assets/`（41 个 PNG），后续若重建前端镜像需确保这些图片被打入或挂载
