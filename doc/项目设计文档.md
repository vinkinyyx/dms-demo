## 今日设计要点（2026-09-02）

### v4.6.1（PATCH，定时邮件发送运行时开关，Flyway V146；开发期曾标号 v4.5.7）

- **需求**：系统每天定时自动向邮箱发邮件（报表订阅、审批超时提醒），数量过多；需要运行时可切换、无需重启、后台可视化操作的开关，控制定时邮件是否发送。
- **控制范围**：仅拦截"定时自动发邮件"——①`ReportSubscriptionService` cron 每日 08:00 报表订阅 CSV 邮件；②`ApprovalTimeoutReminderTask` cron 每日 09:00 审批超时提醒邮件。业务操作触发的即时邮件（审批流转通知等）不在控制范围。
- **配置模型**：复用既有 `system_settings` 表（scope/tenant_id/key/value_json JSONB，唯一约束 `UNIQUE(scope,tenant_id,key)`），scope='global'、tenant_id=NULL（与 V6 种子同命名空间；IntegrationController 的 scope='system' 为另一命名空间，互不影响）。3 个 key：`mail.schedule.enabled`（总开关）、`mail.schedule.report.enabled`（报表子开关）、`mail.schedule.approval.enabled`（审批子开关）。
- **优先级与默认值**：DB 值 > yml `dms.mail.enabled`（默认 true）。总开关 DB 未配置时回退 yml；子开关未配置默认 true。生效逻辑：报表 = 总开关 && 报表子开关；审批 = 总开关 && 审批子开关。
- **读写链路**：`SystemSettingService`（com.dms.system.service）EntityManager 原生 SQL；写 = UPDATE affected-rows==0 再 INSERT（规避 `ON CONFLICT (scope,key)` 与三列唯一约束 + NULL tenant_id 不匹配的坑）；读 = Redisson RBucket 缓存 `dms:cfg:setting:<key>` TTL 30 分钟，写后 evict；缓存/DB 异常均静默降级（不阻断业务）。
- **数据迁移（V146）**：`INSERT ... SELECT FROM (VALUES ...) WHERE NOT EXISTS` 幂等种子 3 行，value_json 为 jsonb 布尔 true，无表结构变更。
- **后台接口**：`AdminMailConfigController` `/api/admin/mail-config/switches`——GET 返回开关视图列表（key/label/description/enabled 生效值/value 存储值/configured/defaultValue）；POST `{key,enabled}` 更新（key 白名单校验，非法 40001）。走 `/api/admin/**` 平台后台鉴权（SecurityConfig authenticated + AdminJwtFilter），仅平台管理员。
- **管理界面**：admin-vue「平台配置 → 通知设置」页（/notify-settings，NotifySettings.vue）：总开关高亮 + 红色 tag，关闭总开关二次确认；总开关关时子开关置灰；每项显示生效状态（发送/已停止）与说明；切换即时生效（写 DB + evict 缓存，最长 30min 缓存也被主动失效）。
- **行为细节**：关闭报表开关时报表仍按时生成、last_run_at/last_status 正常更新，仅跳过 SMTP 发信；审批提醒任务保留原 yml `dms.approval.reminder.enabled` 硬开关作为最外层熔断，DB 开关在其后判断。

## 2026-09-01 设计要点

### v4.5.6（PATCH，经销商 button 权限补全 + 协同收货单号修复，Flyway V145）

- **RBAC 权限模型**：权限链 users → user_roles → roles → role_strategies → strategies → strategy_resources → resources（resources.type = menu/button/api，code 命名：menu 为连字符 `:menu` 后缀、button 为下划线 `module:action`）；前端 PC 菜单显隐 menuVisible() 与路由守卫检查 button 码（如 purchase_order:view、receipt:view、sales_order:view），GET /api/me/permissions 返回当前用户全部权限码（data 直接为字符串数组）。
- **缺陷根因**：开户预置器 TenantRoleProvisioner 为新租户只创建 type='menu' 资源，不创建 type='button' 资源；V61 的 button 补种仅覆盖当时已存在租户，之后新开户经销商（DEALER_D1、DEALER_D2 等）缺 215 个 button 资源 → 登录后无业务菜单、业务页 403。
- **修复方案（V145，数据补丁）**：以模板经销商 DEALER_A1（22222222-0000-0000-0000-000000000001）的 215 个 button 资源为基准，DO $$ 块遍历所有 tenant_type='DEALER' 且无 button 资源的租户：①幂等复制 resources（按 tenant_id+code NOT EXISTS，parent_id 置 NULL、status active）；②查该租户 DEALER_ADMIN 角色关联的管理员策略，幂等插入 strategy_resources（operations={view}，按 strategy_id+resource_id NOT EXISTS）。无表结构变更，可重复执行。中期根治：TenantRoleProvisioner 开户时直接预置 button（未做）。
- **协同收货单号修复**：路径B（onSalesOutShipped，厂家发货→经销商 PENDING 收货单）取号 `docNoGenerator.next("RK")` 与经销商收货单 GR 序列撞段，改为 next("GR")；红字路径D（onRedSalesOutShipped）取 next("RGR")。
- **联调测试数据**：D1=DEALER_D1（默认厂家经销商，dealer_d1_admin/Sh123456，dealerId 19，收货仓「D1协同收货仓」29）、D2=DEALER_D2 苏州康宁（dealer_d2_admin，dealerId 2，收货仓 28）；链路数据：D1 PO-20260901-00001 → 厂家 SO-20260901-00004 → 收货单 RK-20260901-00001（修复前残留前缀）；D2 PO-20260901-00002 → SO-20260901-00005 → GR-20260901-00003。
- **验证**：flyway 145 success；D1/D2 各 215 button+21 menu、权限码 243 含 7 个关键菜单码；真实浏览器两租户菜单全可见、收货/采购页面正常、厂家销售单号回写正确。

### v4.5.5（MINOR，平台外经销商报文式开放接口，Flyway V143–V144）

- **定位**：DMS 厂家租户 ↔ **平台外下游经销商自有系统/ERP** 的单据报文协同（经销商不在 DMS 平台内）。与"同 SaaS 内跨租户协同"（com.dms.collab，JWT 业务接口触发、TenantContext 切租户直写对方表）是两套独立能力；与厂家 ERP 对接（/open/api/erp，ErpOutboundOpenService）亦无关。
- **4 个接口**：①入站 `POST /open/api/collab/purchase-orders/submit`（经销商采购订单 → DMS DRAFT 销售订单）；②出站 SHIP_NOTICE webhook（厂家发货 → 回传出库/收货信息到经销商 webhook_url）；③入站 `POST /open/api/collab/purchase-returns/submit`（经销商采购退货单 → DMS DRAFT 红字销退单）；④出站 RED_SHIP_NOTICE webhook（红字出库 → 回传红字出库信息）。报文为 header+lines 结构，单据号（poNo/returnNo/出库单号）在报文 header，URL 不含单据 id，日期仅 yyyy-MM-dd。
- **鉴权**：HMAC-SHA256 机器凭证（AppKey+AppSecret，open_app 表），四头 X-App-Key/X-Timestamp/X-Nonce/X-Signature；signString = `METHOD\nREQUEST_URI\ntimestamp\nnonce\nsha256Hex(body)`；±5 分钟时钟窗；出站推送用 webhook_secret（空则回退 app_secret）。
- **入站设计**：OpenApiAuthFilter 过滤链 → OpenCollabController → ExternalCollabOpenService；物料对码 open_partner_materials（外部编码→产品）；dealerCode 与 open_app 绑定校验；建单 DRAFT、税率 0.13、单价缺省 0；幂等唯一索引 ux_ocm_in_idem (app_id,msg_type,partner_doc_no) WHERE direction='IN'，重复报文返回首次结果（IDEMPOTENT）。
- **出站设计**：发货事务内登记 open_collab_messages(OUT,PENDING)，事务 afterCommit 异步推送——**推送成败绝不阻断发货主流程**；定时任务扫描 PENDING/到期重试；退避序列 5/15/30/60/120/360/720/1440 分钟，MAX_RETRY=8 后停止；对端成功判定宽松（HTTP 2xx 且 body 空/无 code/code=0）；物料映射缺失等可恢复错误固定 30 分钟重试不计数。
- **数据模型（V143/V144）**：open_app 扩 5 列（partner_type/dealer_code/dealer_id/webhook_url/webhook_secret）；open_partner_materials 对码表；open_collab_messages 报文台账（direction/msg_type/status/retry_count/next_retry_at/line_refs JSONB，入站幂等索引 + 出站重试索引）；sales_outs 加 logistics_company/tracking_no。
- **联调种子**：dealer EXT-D1；AppKey `dms-ext-dealer-d1`；webhook 占位 http://127.0.0.1:9999/webhook/collab；物料 EXT-MAT-001→PRD-J001、EXT-MAT-002→PRD-J002、EXT-MAT-003→PRD-M001。
- **验证**：入站 E2E 20/20、出站 E2E 13/13、铁律9 浏览器终验全过；接口规范 `docs/03_接口文档/跨租户订单协同接口文档_v4.5.5.docx`。
